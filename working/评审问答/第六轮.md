## 需要作者确认

1. **R-21 ～ R-33**（SPEC-0001 第 6.3 条）。
2. **P-05、P-06、P-07 的起草稿**：SPEC-0105 的全部方法表（方法的取舍、索引顺序、成本）；`MO_TIME`、`MO_RE`、`MO_BINT` 的索引 0 未分配；SPEC-0103 第 6 条的类型标识表（单一类型取其值指令的码值，组合类型 `Number`、`Intes`、`Char` 从 64 开始）。
3. **与构想层字面不同的几处取舍**：
   - MODEL 中 `!Type` 不匹配、`?{}` 局部匹配，构想层分别写「结束 Model 块」「整个 MODEL 不匹配」。本稿统一为「当前路径失败」，外层有 `...` 时可以回溯（R-28）。否则 `... !Int ...` 在 `...` 第一次尝试的位置不是整数时就会直接失败，`...` 的非贪婪语义不完整。
   - RE 单元没有找到匹配时，本稿判该单元不匹配（R-28）；构想层写「目标没有匹配取值为 nil」。需要「有就取、没有也行」时用 `?{RE…}`。目标指令没有数据时，构想层写「执行错误，MODEL 失败」，本稿同样按不匹配处理，以便回溯。
   - `^[0x80] CODE{…}` 在字节码中必须同时置 0x01（掩码 0x81）：长度附参被省略，解码器需要从掩码得知这一点。构想层写作 0x80。文本写法与掩码的对应由 SPEC-0201 规定。
   - `SOURCE` 只排除作为起点的那条 `SYS_NULL`，区间中间的 `SYS_NULL` 照常包含（R-30）。依据是构想层示例：`SOURCE[0x80]` 为「DATA ~ END」、`SOURCE[1]` 为「SIGNED ~ <Source.1>」，都包含区间内的 `SYS_NULL`。如果「任何情况下，取码时 NULL 点都不会被包含」是指区间内的全部 NULL 都要剔除，请指出。
   - `MO_TIME` 的 `UTC`、`InOffset`、`AddMilli`、`AddDate`、`Sub` 列为公共方法（R-33），超出了 DEC-0001 第 3 条「公共域只开放数值读取」的列举。理由是它们只做整数运算，不依赖格式化与时区数据库，结果确定。如需严格按该条，把这 5 个方法改为私有即可。
   - `MO_TIME` 的 `Format`、`Local`、`In` 定为私有方法。`Format` 的布局语法是 Go 专有的，要在共识中使用就必须完整规定它；构想层 `CALL` 示例中的 `"Format" "15_04_05"` 因此只在私有执行中成立。如果希望公共可用，可以另定一个受限的布局语法。
   - `CMPFLO` 的三个实参都必须是 Float（R-31），因此它在公共执行中总是失败。
4. **P-04（预发布）留给 SPEC-0901 的问题**：
   - 预发布期间统计的「新版交易」指什么。没有升级的节点会拒绝新版交易，而创建时的共识检查也会拒绝使用尚未生效版本的输出。统计的对象可能是交易头的版本标记（交易仍按旧规则验证），需要明确。
   - 统计窗口（多少个区块）与阈值的分母。
   - 到达生效高度而阈值未达时，是继续等待，还是本次升级作废。
   - 创建时检查的成本计入交易成本，是否同时受 `MaxTxScriptCost` 约束。

> **作者回答：**
> R-24: STRING(Byte) 改为按 ASCII 解码，控制字符和 0x80 及以上用16进制（\xhh）表示。
> R-26: 本来是想 Script 先转换为 Bytes。但如果直接接收 Script 不复杂，可以友好支持（免去 Bytes 转换的成本）。
> R-31: MATCH 没有匹配时返回 nil 或 ""，已在构想文档中的返回值中添加。
> R-32: Base58 同意对编解码长度做限制，编码时限制实参，解码时限制结果。统一为256字节。
> 其它的全部同意（含 2、3），构想层已相应修订。
> 第 4 点已在 `Design.md#附：版本关系` 中补充明确。新版本检查和统计成本极低，可忽略。分母为区块交易总数。

## 影响与提醒

- 集合成员数上限 1024 会直接影响：`RUNES`（超过 1024 个字符的 String 不能整体转为 `[]Rune`）；`MATCH` 的 `g` / `G` 与 `MO_RE` 的 `FindAll*`（超过 1024 个匹配即失败）。
- `BYTES(Script)` 按源码类（16KB）检查，否则 8KB 以上的 Script 无法转为 Bytes。
- `MO_BINT` 的 `ModPow` 等成本公式只是校准起点（P-02）。模块方法的成本以 `K` 为基数，因此同一运算经运算指令与经模块方法的成本可以不同（SPEC-0006 第 3 条）。
- 编写完成后做了一次独立的一致性核查，据此修正：`PACK` 接受 Bytes 成员；「新数据字节」的两种定义统一为 `D`；`RANDOM` 的上界改回构想层的 Int | Float，结果与上界同类型；几处 DEC 条号；SPEC-0103 加载期补充规则的〔R〕标注（并入 R-28、R-29）。
