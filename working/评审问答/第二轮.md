## 需要作者确认的问题

每条都附了建议答案。同意写「同意」即可，否则写下自己的规则。

- **Q1**（P0-8）：解锁段与锁定段只共享数据栈。解锁段结束时实参区必须为空，否则失败；锁定脚本从新的局部域开始。
- **Q2**（P1-3）：GOTO 目标脚本中的 `PASS(false)` 让整个验证立即失败（否决）；`CHECK(false)` 才是调用者可以覆盖的结论。
- **Q3**（P1-3）：EVAL 的代码执行到 `END` / `INPUT` 时视为 EVAL 失败，不再向外传递「结束」。
- **Q4**（P1-3）：`EXIT` 在 EMBED 代码和 MAP / FILTER 体内，都结束整个当前脚本。
- **Q5**（P1-3、P2-5）：字典两条规则。`EACH` 按进入时的键快照迭代；字典的值（递归地）不能包含字典。
- **Q6**（P1-7）：脚本版本号放在宿主的输出结构里（Evidcoin 建议用配置字节高 4 位或独立字段）；OP_SUCCESS 只对锁定方的脚本生效。
- **Q7**（P0-6）：建议 Evidcoin 的 TxID 不包含整个解锁数据（见证信息和解锁脚本）。请说明现状，以及签名消息覆盖哪些内容。
- **Q8**（P0-7）：单项 4KB 上限按实际签名算法调整，Script 类和源码类取值单独设上限 16KB；限额与成本的初始数值作为校准起点。
- **Q9**（P0-4、P1-1）：公共域禁止的是 Float 类型（任何指令产生 Float 值即失败），不只是浮点字面量；整数溢出一律失败。
- **Q10**（P0-5）：规格权威按三类处理；`MO_FMT` 以及 Time 的格式化、时区方法改为私有域专属；正则固定 Unicode 版本。
- **Q11**（P0-5）：`RANDOM` / `SLRAND` 改用基于 BLAKE3 XOF 的算法。
- **Q12**（P1-8）：结构类规则在加载期判定。不会执行到的分支里有结构错误，脚本同样无效。

## 正文勘误（本轮新发现）

1. GOTO / EMBED / SCRIPT 的附参 1 前后不一：`0.基本约束.md` 的 GOTO 写「区块高度」，例子却是「2026 年度」；`6.结果指令.md` 写「年度（按交易时间戳计算）」；`1.值指令.md` 的 SCRIPT 写「年度」，例子却说「87661 号区块」。
2. `14.工具指令.md` SLRAND 示例：PEEK 的位置是附参，`{-2} PEEK` 实际是先压入 -2，再引用栈底。-2 会留在栈里，被后面的 `@POPS[2]` 导出。应为 `PEEK[-2]`（或 `PEEK`，此时栈底正是种子）。
3. `14.工具指令.md` CALL 第二例：MO_MATH 已支持 Int，`Abs(-10)`、`Pow(2, 8)` 的结果是 `10`、`256`，注释里的 `10.0`、`256.0` 需要改。
4. OutKind 取值不一致：`13.环境指令.md` 的 ENV 写「1-币金 | 2-凭信」，`1.值指令.md` 的 GVAL 写「币金|凭信|存证：1|2|3」。
5. `9.运算指令.md` 开头「命名指令用于表达式外，不可混用」与 P1-4 的回答冲突，见 P1-4 回复。
6. `14.工具指令.md` MAP「内部语句块视为一个独立的脚本域」与 P1-3 的回答「在当前脚本域执行」措辞冲突，见 P1-3 回复。
7. `5.交互指令.md` INPUT 仍写「（阻塞）」，实际语义是无数据即中断。
8. `1.值指令.md` BigInt「即 2^1016 位的范围」应为「1016 位」。
9. `1.值指令.md` DICT 示例用了浮点数 `{1.0}`，在公共域会失败，建议换成整数。
10. `Design.md` 安全性一节的「组队校验冻结机制」仍未定义，见 P0-7 回复。
11. `12.模式指令.md` 的 `^'A'?`「兼容两个指令（opcode:3|4）」需要一条匹配规则，见 P2-4 回复。
