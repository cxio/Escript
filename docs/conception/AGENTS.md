## 构建指引

如果需要理解脚本的工作和设计原理，可参考 `Design.md` 文档。


### 实现参考

需要引用历史交易的指令有 `SCRIPT`、`GOTO`、`EMBED`、`INOUT`，如果用实时查询公共服务的方式，可能会因为网络问题而极大影响性能。

所以设计允许用户广播交易数据时，额外携带脚本验证相关的信息（输出项的默克尔验证路径；且输出项的内容有摘要优化）。这样验证节点就可以省去网络查询的负担，提升效率。同时，因为效率提升，该交易也更容易正常地被收录（这是对用户的利益驱动）。

对于公共常用的外部引用，如 `GOTO` 跳转的通用介管脚本，验证节点通常会缓存它，从而省去实时查询的负载。此时用户就可以省去必要的验证上下文，只需要广播交易数据本身。
