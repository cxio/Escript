# 结果指令

本类指令会产生决定性的结果，比如*通关*检查、逻辑*跳转*、函数*返回*或脚本结束等。

> **设计：**
> 初始通关状态为「未决」，但若脚本执行完毕依然为未决，则默认通过。
> 即通关逻辑为宽松，默认可自由通行：只有设置检查，才需要阻止（契合社会伦理）。
>
> 另外，这一逻辑也隐含「如果用户无意中构建了无通关指令的脚本」：
> - 默认不通过：会造成 UTXO/UTCO 永久积压。
> - 默认通过：正常花费，系统不应当承担用户失误。
>
> 但有一个前提：锁定脚本必须已经开始执行。用户构建解锁段的错误无法获得通过。


## 定义

指令码区间：`[51-57]`，7个。

```go
码值    指令字      说明
----------------------------------------------------------
51      PASS        通关（安检）
        // 实参为 true 时通过，设置通关状态，继续。
        // 通关 true 状态仅写入当前脚本域。
        // 实参为 false 时通关失败，结束脚本执行。
        // 如果是子脚本中的通关状态为 false，通关失败会即时透传到顶层。
        // 注意：「未决」通关状态不为失败，默认通过。
        // 实参：布尔值。
        // 返回值：无。
        // 提示：
        // 多个 PASS 类似于“And" 的逻辑，每一个都必须成功。
        // 不过此时需要注意 CHECK 的影响。
        //
        // 实现：
        // 通关失败可能触发某种通知机制，以便外部了解情况。

52      CHECK       检查（安检）
        // 实参为 true 时通过，为 false 时标记失败。
        // 与 PASS 相同的通关检查，但失败不会退出。
        // 与 PASS 同样逻辑，通关状态仅属于当前脚本域。
        // 注意：
        // 与 PASS(false) 的即时透传不同，子脚本执行完后，CHECK(false) 并不会向上透传。
        // CHECK(false) 依然只属于当前脚本的局域状态。
        // 也即，如果子脚本需要明确地向上传递通关逻辑，应当使用 PASS。
        // 实参：布尔值。
        // 返回值：无。
        // 注意：
        // 通关状态会被后续的 CHECK 覆盖，因此实际上取决于最后一个 CHECK。
        // 这有点类似于“Or”的逻辑（但不同）。
        //
        // 设计：
        // 如果验证没有因 PASS(false) 或 SYS_CHKPASS 失败而提前结束，
        // 顶层脚本正常结束后，系统会检查通关状态来判定是否通过。

53      GOTO(~,48,~)    跳转（独立）
        // 跳转到某个交易的输出脚本。
        // - 实参区数据传递到新脚本作为其数据栈初始内容。
        // - 新脚本延续当前的校验，但有其自身的环境（数据栈、实参区、全局变量区）。
        // - 新脚本中的通关状态（PASS/CHECK）属于新脚本自身，不反馈到调用者。
        //   但通关失败（PASS(false)、SYS_CHKPASS 失败）和运行错误会即时透传，整个验证不通过。
        //   注：跳转到的目标脚本中也可以包含 GOTO，但会有层级限制（安全性要求）。
        // - 私有环境的残留信息在脚本退出后会全部被丢弃。
        // 附参1：年度（按交易时间戳计算）。
        // 附参2：交易ID。
        // 附参3：输出项序位（从0开始）。
        // 实参：不定数量。
        // 返回值：无。
        // 例：
        //      @POPS[5] GOTO[2026, 0xab93cf..., 1]
        // 提取栈顶5项数据，
        // 跳转到2026年的 0xab93cf...交易的第2项输出项的脚本，
        // 传递实参为其数据栈初始内容。
        //
        // 设计：
        // 外部脚本对调用者的回馈仅限于通关失败（否决），不能替调用者放行。
        // 目标脚本中的 EXIT 和 END/INPUT（公共节点）只结束目标脚本本身，回到调用者继续。
        // 不支持数据栈残留项返回到调用者，这容易带来安全问题（不可控的数据注入）。
        //
        // 实现：
        // 本指令需要验证节点实时查询网络以载入目标脚本，
        // 因此考虑效率，支持用户自己提供目标脚本的验证上下文。

54      EMBED(~,48,~)   嵌入（合并）
        // 嵌入某个交易的输出脚本。
        // 目标脚本为合并逻辑，共享当前的脚本域（数据栈、实参区、全局变量区）。
        // 注意目标脚本直接执行，会向当前数据栈中添加内容。
        // PASS/CHECK 的影响也作用于当前脚本，没有额外的区隔。
        // 附参1：年度（按交易时间戳计算）。
        // 附参2：交易ID。
        // 附参3：输出项序位（从0开始）。
        // 实参：无。
        // 返回值：无。
        // 例：
        //      EMBED[2026, 0xab93cf..., 0] FN_HASH256 DATA{...} ...
        // 提取2026年某交易的首个输出项脚本，嵌入并执行，
        // 之后取栈顶值计算哈希摘要（FN_HASH256）……
        //
        // 实现：
        // 与 GOTO/SCRIPT 类似，支持用户提供目标脚本的验证上下文以提升效率。

55      EXIT        结束脚本
        // 脚本至此被终止执行并退出。
        // 退出前，系统会检查通关状态以判断验证是否通过。
        // 实参：任意单值，可选。
        // 返回值：即实参值。
        // 如果实参区有值，返回该值到系统（可能会被处理）。
        // 如果实参区无值，则仅简单结束。
        // 注：
        // 本指令通常出现在IF语句块内，但在顶层也可使用。
        // MAP/FILTER 私有块域不是独立脚本，其中的 EXIT 会结束上层脚本本身。

56      RETURN      迭代返回
        // 从 MAP/FILTER 子块迭代中退出，并返回一个值。
        // 注意仅是退出当前迭代——然后进入次一次迭代。
        // 实参：任意单值，可选。
        // 返回值：即实参值，无实参时返回nil。
        //
        // 约束：
        // 该指令只能位于 MAP/FILTER 之内。

57      END         公共验证结束
        // 公共验证逻辑结束，脚本退出。
        // 仅限于公共验证节点，其它私有用途的节点会忽略它。
        // 注：
        // 对公共验证节点来说，该指令类似于 EXIT。
        // 在 GOTO 目标脚本和 EVAL 执行的代码中，只结束该脚本本身，回到调用者继续。
        //
        // 例：定向加密：
        // - 交易者A先发布自己的公钥到链上。
        // - 交易者B用A的公钥创建共享密钥，加密数据后连同自己的公钥一并发布。
        // - 交易者A用B的公钥重构共享密钥，解密数据。
        // 解释：
        // 这种数据仅对交易者A有意义，因此需提前结束公共验证。
        //
        // 设计：
        // 私有监听需要借助于开放式的公共发布触达私有监听节点。
        // 私有处理通常需要包含公共验证的逻辑（部分）。
```
