# 系统指令

少量执行系统级功能的指令。至此，指令名已有前缀开头，此为 `SYS_`。


## 定义

指令码区间：`[164-169]`，6个。

```go
码值    指令字          说明
-----------------------------------------------------------
164     SYS_TIME(1){}   全局时间取值
        // 全局时间对象是客户端真实的当前时间。
        // 附参：条目标识。
        // 实参：无。
        // 返回值：目标条目的值。
        // 条目：
        // - 默认           当前时间（Time）
        // - Stamp          时间戳（Unix 毫秒数）
        // - Year           年次（4位）
        // - Month          月次/年（1-12）
        // - YearDay        日次/年（1-365|366）
        // - Day            日次/月（1-31）
        // - WeekDay        日次/周（0-6）
        // - Hour           时数/日（0-23）
        // - Minute         分钟数/时（0-59）
        // - Second         秒数/分钟（0-59）
        // - Millisecond    毫秒数/秒（0-999）
        // - Microsecond    微秒数/秒（0-999999）
        // 注：
        // 返回的数值统一为Int类型。
        // 例：
        // SYS_TIME{Stamp}  获取系统当前的时间戳。
        // SYS_TIME[0]      获取当前时间对象（Time）。
        // SYS_TIME         同上
        //
        // 设计：
        // 私有域指令。因为节点本地时间是一个非共识的值。
        // 这与值指令中的 Float 一样，主要是为私有域应用提供便利。

165     SYS_AWARD(1,4)  兑奖验算
        // 检查兑奖槽情况，按规则计算兑奖比例（0|50|100）。
        // 然后核算兑奖者支出（转移）的金额是否合法。
        // 兑奖比例为零时，任何支出都无效，即不能作为转移交易的输入项
        // 附参1：脚本所在输出序位
        // 附参2：区块高度。
        // 此两个附参主要是为了向指令内部传递正确参数。
        // 实参：无。
        // 返回值：布尔值（是否成功）。
        // 注意：
        // 仅可使用在 Coinbase 交易的输出脚本中，否则脚本会失败。
        // 规则：
        // - 附参1：脚本所在输出序位必须匹配真实位置。
        // - 附参2：区块高度为当前 Coinbase 交易所在区块高度。
        // 此规则在 Coinbase 交易合法性检查时核实。
        //
        // 设计：
        // 该指令会检查附参2（区块高度）之后的链段，包括高度和兑奖槽状况。
        // 该指令在兑奖时验算：
        // - 传参输出序位：检索接收者币金数量。
        // - 传参区块高度：按当前高度计算真实可用金额，向下取整。
        // 该指令也在兑奖标记期结束后验算：
        // - 根据同样规则计算不能被兑奖的部分金额。
        // - 该金额奖励给标记期结束后的首个区块的铸造者（即兑奖截留）。
        // 实现：
        // 从附参2可以快速推断后续链段是否满足兑奖规则（+31 ~ 48）。
        // 如果兑奖比例为零，返回 false。其作为花费输入项不能通过。
        //
        // 用户：
        // 花费前应当先自行检查可兑换金额，以及区块高度是否合法。

166     SYS_CHKPASS     系统验证
        // 即内置的地址核实&签名验证，签名包含单签和多签。
        // 本指令也是通关指令（如PASS），验证失败会退出。
        // 币金和凭信都使用此指令验证（主要是针对签名）。
        // 实参：无。
        // 返回值：无。
        // 注意：花费者地址（输入源的接收者）必须是标准格式。
        // 提示：币金和凭信遵循不同的约束，但二者的区别对待在前置检查中完成。
        //
        // 声明参考：
        // SYS_CHKPASS( 花费者, 签名类别, 授权标记, []签名, []公钥, []初级哈希 )
        // - 花费者：   从输入项检索其来源接收者
        // - 签名类别： 1-单签；2-多签。从环境提取（见证信息提前注入环境）。
        // - 授权标记： 从环境中提取。
        // - []签名：   从环境中提取，单签只有单个成员。
        // - []公钥：   同上从环境中取值，与签名集成员一一对应。
        // - []初级哈希：剩余公钥初级哈希，从环境提取，仅在多签时有用。
        //
        // 设计：
        // 作为单独的指令存在，可方便用户灵活指定系统验证启动的位置。
        // 甚至可存在于 GOTO/EMBED/SCRIPT 等引入的外部脚本中，不合理但没有限制。
        // 单签/多签地址不可区分，实参由用户解锁提供。
        //
        // 实现：
        // 验证成功后，会在系统层标注验证结果（true|false），可供需 SIGNED 指令查询。

167-168 （未用）

169     SYS_NULL        源码零点标识
        // 在脚本的当前位置设置一个NULL点，作为片段提取时的起点。
        // 主要对 SOURCE 指令有用。
        // 例：
        // SYS_NULL     // 设置起点
        // "Hai"        // 入栈字符串 Hai
        // ...          // 除了 SYS_NULL 的任意指令序列
        // SOURCE[2]    // 提取从 Hai 开始到本指令的源码（包含）
        //
        // 设计：
        // 可用于解锁脚本段，以提供「解锁<=>锁定」的衔接灵活性。
        // 这是一个特例。
```
