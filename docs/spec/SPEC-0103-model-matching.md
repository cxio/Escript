## 概述

MODEL 对一个目标（Script 或 Bytes）做结构化的模式匹配：先把目标解码为指令树，再用模式体逐层比对，并可取出目标中的部分值。匹配只读目标，不执行目标中的任何指令。

本篇定义：目标的解码，模式单元，普通指令与深匹配，通配指示 `^?` 及其编码，类型匹配与类型标识表〔P-07〕，范围与正则匹配，段通配与可选序列，求解与回溯，取值与返回值，加载期的补充规则，以及成本。


## 规格正文

### 1. 执行

`MODEL`（opcode 116）：

1. 实参：目标，Script 或 Bytes；其它类型即失败。
2. 按第 2 条解码目标。解码失败，结果为不匹配。
3. 按第 4–10 条，用模式体匹配目标的顶层。
4. 返回（SPEC-0002 第 6.11 条）：附参的「有取值」标记为 0 时，返回一个 Bool；为 1 时依次返回取值切片与 Bool，Bool 在后。不匹配时取值切片为空的 `[]any`〔R-29〕。

「不匹配」是 MODEL 的正常结果，不是失败。MODEL 只在实参类型不符、超出成本预算或硬限额，以及公共执行中取值出现 Float（第 11 条）时失败。

### 2. 目标的解码

- 按 MODEL 指令所在段的版本解码（SPEC-0007 第 2 条）。目标是 Script 时，不使用它携带的版本。
- **适用**：SPEC-0003 第 3 条的规范解码规则（第 7、8 项除外：目标中 `MODEL` 的模式体不解码，正则不编译）、块长度、块嵌套深度不超过 16。
- **不适用**：SPEC-0003 第 4 条的其它结构规则、第 7 条的段级规则。目标可以是不完整的片段，例如单独的 `ELSE`，或含有系统占位符的解锁段。
- 目标中 `MODEL` 的块体作为数据，不解码（构想层：「如果目标脚本包含 MODEL 块本身，其内容作为普通关联数据对待」）。
- 目标中、`MODEL` 块体之外出现模式指令（opcode 117–127），视为解码失败〔R-28〕。
- 目标含有 MODEL 所在段的版本未分配的码值或附参取值，也是解码失败（SPEC-0003 第 9 条）。

解码得到一棵指令树：每一层是一个指令序列；块指令（第 4 条所列）的块体是它的下一层。

### 3. 模式单元

模式体的每一层（`MODEL` 的模式体、深匹配块的块体、`?{}` 的块体）是一个单元序列：

| 单元 | 写法 | 在目标中匹配 |
| --- | --- | --- |
| 普通指令 | 模式指令以外的任一指令 | 一条指令（第 4 条） |
| 通配指示单元 | `^?` + 一条目标指令 | 一条指令；可选时也可以是 0 条（第 5 条） |
| 任一指令 | `.`（117） | 一条任意指令 |
| 指令段 | `.[n]`（118） | 恰好 n 条任意指令，n 可以为 0 |
| 类型匹配 | `!Type`、`?Type`（122） | 一条指令；`?Type` 也可以是 0 条（第 6 条） |
| 范围匹配 | `>{}`（123、124） | 一条值指令（第 7 条） |
| 正则 | `RE{}`、`?RE{}`（125） | 一条带数据的指令；`?RE{}` 也可以是 0 条（第 8 条） |
| 可选序列 | `?{}`（119） | 一段指令，或 0 条（第 9 条） |
| 任意段 | `...`（127） | 任意条指令，含 0 条（第 9 条） |

取值指令 `#`（121）与 `$[n]`（126）不是单元：它们不匹配任何指令，只在最终成功的路径上产生取值（第 11 条）。

**完整性**：模式的一层与目标的一层比对时，单元序列必须恰好覆盖目标该层的全部指令（构想层：「匹配完整性要求（匹配到脚本结束）」）。

一条块指令连同其块体在所在层中算一条指令（构想层：「指令段仅指同级关系」）。

### 4. 普通指令与深匹配

- **深匹配**：普通指令是 `IF`、`ELSE`、`SWITCH`、`CASE`、`DEFAULT`、`EACH`、`BLOCK`、`MAP`、`FILTER`（代码块体）或表达式 `()`（表达式体）时，目标指令的码值必须相同，并且模式的块体与目标的块体作为下一层完整匹配；块长度附参不参与比较（构想层「深匹配」）。
- **其它普通指令**，包括带数据而不是代码块的 `MODEL`、`CODE`、值集、`SHELL`：与目标指令逐字节相同，即码值、附参与关联数据都相同。
- 截取前缀（`@`、`&`、`~`、`_`）在字节码中是独立的指令，按普通指令逐个匹配。

### 5. 通配指示 `^?`（120）

`^?` 的附参是一个掩码，修饰紧随其后的一条**目标指令**（不能是模式指令 117–127）：

| 位 | 含义 |
| --- | --- |
| 0x01、0x02、0x04、0x08 | 目标指令的第 1–4 个附参任意 |
| 0x10 | 未定义，必须为 0 |
| 0x20 | 关联数据任意 |
| 0x40 | 整个单元可选 |
| 0x80 | 关联数据按哈希匹配 |

附参的编号按 SPEC-0002 格式表的顺序，`HostRef` 的字段依次计为附参（SPEC-0002 第 2.2 条）。

#### 5.1 部分编码〔R-27〕

`^?` 之后的目标指令只编码没有被通配的部分：

- 掩码中置位的附参不出现在字节码中；其余附参按格式表的顺序编码。
- 0x20 置位时，关联数据不出现。
- 0x80 置位时，关联数据的位置是 32 字节的哈希值，代替原数据；哈希算法为 BLAKE3，256 位输出。
- 0x20、0x80 都未置位时，关联数据照常编码，但只作为数据比较：带块体的指令在 `^?` 之后是单匹配，块体不按代码或模式解码（构想层「单匹配」）。

构想层的例子：

| 文本 | 掩码 | `^?` 之后的字节 |
| --- | --- | --- |
| `^DATA[20]{?}` | 0x20 | `DATA` 的码值、长度 20 |
| `^DATA[?]{?}` | 0x21 | `DATA` 的码值 |
| `^DATA[20]{?}?` | 0x60 | `DATA` 的码值、长度 20 |
| `^[0x80] DATA[80]{0x4f262ae8...}` | 0x80 | `DATA` 的码值、长度 80、32 字节哈希 |
| `^[0x81] CODE{0x4f262ae8...}` | 0x81 | `CODE` 的码值、长度任意，32 字节哈希 |
| `^&[?]` | 0x01 | `&[n]` 的码值 |
| `^IF[60]{?}` | 0x20 | `IF` 的码值、长度 60 |


#### 5.2 加载期约束

违反以下任一条，该段加载失败：

1. 附参位只能指向目标指令实际具有的附参。
2. 0x20、0x80 只能用于有关联数据的指令；0x80 只能用于关联数据长度由附参给出的指令（`data`、`code`、`expr`、`pattern`、`members`、大整数的绝对值，SPEC-0002 第 3 条）。0x20 与 0x80 不能同时置位。
3. 给出关联数据长度的附参被通配时，0x20 或 0x80 必须置位。
4. 0x10 为 0。

#### 5.3 匹配

目标指令的码值相同；未被通配的附参逐个相等（按解码后的值）；关联数据在 0x20 时任意，在 0x80 时目标数据的 BLAKE3-256 等于给出的哈希，否则逐字节相同。0x40 置位时，单元按第 10 条的「可选单元」处理。

### 6. 类型匹配 `!?Type`（122）〔P-07〕

附参 bit7 为 1 表示可选（`?Type`），为 0 表示必须（`!Type`）；bit0–6 为类型标识。目标指令的码值属于该标识对应的码值集合，即匹配；只看码值，不看附参与数据。

| 标识 | 类型名 | 匹配的码值 |
| --- | --- | --- |
| 0 | `Nil` | 0 |
| 1 | `Bool` | 1、2 |
| 3 | `Byte` | 3 |
| 4 | `Rune` | 4 |
| 5 | `Int` | 5 |
| 6 | `BigInt` | 6 |
| 7 | `Float` | 7 |
| 8 | `String` | 8 |
| 9 | `Values` | 9 |
| 10 | `Bytes` | 10 |
| 11 | `RegExp` | 11 |
| 12 | `Time` | 12 |
| 13 | `Dict` | 13 |
| 16 | `Script` | 16、17 |
| 22 | `Loops` | 22 |
| 64 | `Number` | 5、7 |
| 65 | `Intes` | 5、6 |
| 66 | `Char` | 3、4 |
| 80 | `Expr` | 80 |
| 116 | `Model` | 116 |

- 单一类型的标识取该类型值指令的码值（与 `ANYS` 的标识同一思路），组合类型从 64 开始。表中未列的标识未分配，含有它的段加载失败（SPEC-0007 第 4 条）。
- `!Model` 与 `^MODEL[?]{?}` 等价，`!Expr` 与 `^(?)` 等价（构想层）。

### 7. 范围匹配

**整数范围（123）**：附参为下界 lo（含）与上界 hi（不含），`varint`。目标指令为 Byte（3）、Rune（4）、整数（5）或 `DATE`（12，取毫秒时刻），且其值 v 满足 lo ≤ v < hi，即匹配。其它指令不匹配，包括大整数（构想层：「暂不支持大整数」）。

**浮点范围（124）**：附参为下界 lo、上界 hi（`f64be`）与误差 eps（`f32be`，精确转换为 binary64）。目标指令为浮点数（7），且其值 v 满足

```
( v ≥ lo  或  |v − lo| ≤ eps )  且  v < hi
```

即匹配。比较与减法按 IEEE 754 binary64。这些附参与目标的数据都是模式数据，不产生 Float 值，公共执行中可以使用（SPEC-0002 第 6.11 条）。

### 8. 正则 `RE{}`、`?RE{}`（125）与 `$[n]`（126）

附参 3 的 bit7 为 1 表示可选（`?RE{}`），为 0 表示必须（`RE{}`）；bit0–6 为查找方式〔R-28〕。

RE 单元匹配一条目标指令：

1. 附参 1 不是 `0xFF` 时，目标指令的码值必须等于附参 1。
2. 目标指令必须带有长度由附参给出的关联数据（第 5.2 条第 2 项），否则不匹配〔R-28〕。构想层写的是「执行错误，MODEL 失败」，本篇按单元不匹配处理，以便 `...` 回溯。
3. 目标是字符串指令（8）时，数据按 String 处理；否则按 Bytes 处理。块指令的块体作为字节数据（构想层）。
4. 按查找方式查找。正则的约定与全部匹配的算法见 SPEC-0104 第 1 条。

| 方式 | 查找 | 结果集 |
| --- | --- | --- |
| `f` | 首个匹配 | [全匹配] |
| `S` | 首个匹配，含捕获组 | [全匹配, 组 1, 组 2, …]，未参与匹配的组为 Nil |
| `g` | 全部匹配 | [各全匹配]，至多前 256 个 |
| `G` | 全部匹配，含捕获组 | [各匹配的 `[]any`]，每个形如 `S` 的结果集，至多前 256 个 |

5. 至少找到一个匹配，单元才匹配；没有匹配即不匹配〔R-28〕。

`?RE{}` 是可选单元（第 10 条）：第 1–5 项都满足时匹配并消耗该指令，否则跳过，不消耗指令（构想层：「有就取，没有也行」）。

结果集中的文本按数据的处理方式为 String 或 Bytes。

**`$[n]`**：取在字节顺序上位于它之前、最近的 RE 单元（同一 MODEL 的模式体内）在当前路径上的结果集的第 n 个成员，从 0 开始。n 超出结果集，或该 RE 在当前路径上没有结果集（位于不存在的 `?{}` 中，或是被跳过的 `?RE{}`），得 Nil（DEC-0005 第 10 条「宽松」）。

### 9. 段通配与可选序列

- `.` 匹配一条任意指令。
- `.[n]` 匹配恰好 n 条任意指令。n = 0 时不消耗指令（构想层：「没有意义」，但合法）。
- `...` 匹配任意多条指令，含 0 条。它是**非贪婪**的：按 0、1、2…… 条的顺序尝试，取第一个使本层其余单元完整匹配的长度（第 10 条）。
- `?{Q}`：Q 是一个单元序列。
  - 在当前位置尝试 Q 的第一个单元：不匹配，则 Q 不存在，不消耗指令，继续本层的后续单元。
  - 匹配，则 Q 存在：Q 的其余单元必须在随后的位置依次匹配，否则当前路径失败。不再回头尝试「不存在」（构想层：非回溯）。
  - Q 的本层不得含有 `...`、`?{}` 与可选单元（`^?` 的 0x40、`?Type`、`?RE{}`），在加载期检查〔R-28〕。Q 中深匹配块的块体是独立的层，不受此限。

### 10. 求解与回溯〔R-28〕

每一层的匹配是一次从左到右的搜索：

1. 单元按顺序与目标的当前位置比对。普通指令、`^?` 单元、`.`、`.[n]`、`!Type`、范围、`RE{}` 消耗确定条数的指令；不匹配时，当前路径失败。
2. **可选单元**（`^?` 的 0x40、`?Type`、`?RE{}`）：当前位置匹配就消耗它，不匹配就跳过；不回头尝试另一种选择（贪婪、无回溯）。
3. `?{}`：按第 9 条决定，也不回头。
4. `...` 是唯一的回溯点。当前路径失败时，回到本层最近的 `...`，让它多匹配一条再试；它已经延伸到本层末尾仍然失败，再回到本层更早的 `...`。本层没有可回溯的 `...` 时，本层匹配失败。
5. 本层的单元用完时，目标的本层也必须恰好用完，否则当前路径失败。
6. 深匹配的块体是下一层，独立求解，取按上述顺序找到的第一个解。外层的成败与内层选了哪个解无关，所以外层回溯时不再进入已经匹配成功的内层。
7. 顶层匹配失败，MODEL 的结果为不匹配。

构想层中 `!Type`「如果失败则结束 Model 块」、`?{}`「前段局部匹配时视为失败，整个 MODEL 不匹配」，本篇统一为「当前路径失败」：有 `...` 可以回溯时继续尝试，没有时就是整个 MODEL 不匹配。否则 `...` 的非贪婪语义不完整，例如 `... !Int ...` 在第一次尝试的位置不是整数时就会直接失败。

### 11. 取值与返回值〔R-29〕

**`#[mask]`（121）** 紧跟在一个**单指令单元**之后：普通指令、`^?` 单元、`.`、`!?Type`、范围或 RE。它从该单元匹配的目标指令中取值，按掩码位从低到高依次产生：

| 位 | 取值 |
| --- | --- |
| 0x01–0x08 | 目标的第 1–4 个附参。整数编码（`u8`、`i8`、`u16be`、`u32be`、`varint`、`uvarint`）为 Int，`uvarint` 大于 2⁶³−1 时为 BigInt；`f32be`、`f64be` 为 Float；`bytes(N)` 为 Bytes |
| 0x10 | 未定义，必须为 0 |
| 0x20 | 关联数据。Byte、Rune、整数、浮点数、`DATE` 为其值（Byte、Rune、Int、Float、Time）；大整数为其值（BigInt）；字符串与正则字面量为 String；其余（`DATA`、`CODE`、值集、块体等）为 Bytes |
| 0x40 | 码值，Byte |
| 0x80 | 完整的指令（码值、附参与关联数据），Bytes |

- 目标指令没有掩码所指的部分时，该位取 Nil。
- 可选单元没有匹配任何指令时，其后 `#` 的每一位都取 Nil；被跳过的 `?RE{}`，其 `$[n]` 也取 Nil（第 8 条）。
- `?{}` 不存在时，其中的 `#` 与 `$[n]` 都取 Nil。
- 因此取值的个数是静态的：每个 `#` 产生其掩码中置位的个数，每个 `$[n]` 产生 1 个。
- 全部取值按它们在模式体中的字节顺序排成一个 `[]any`，作为 MODEL 的第一个返回值。只保留最终成功的路径上的取值，回溯放弃的路径的取值丢弃。
- 不匹配时，取值切片为空的 `[]any`。
- 取值中出现 Float（浮点数的数据、浮点附参），在公共执行中即失败（SPEC-0004 第 3 条）。

`#` 取的总是目标指令的部分，与模式中对该部分写的是通配、哈希还是具体值无关。

### 12. 加载期的补充规则

在 SPEC-0003 第 6 条之外，模式体还须满足以下各条，违反即该段加载失败：

1. `^?` 后随一条目标指令，并满足第 5.2 条。
2. `#` 的前一个单元是单指令单元（第 11 条；构想层：「本指令需紧跟在目标指令之后」）：不能位于一层的开头，也不能跟在 `.[n]`、`...`、`?{}`、`#` 或 `$[n]` 之后。掩码不为 0，且 0x10 为 0〔R-29〕。
3. `$[n]` 之前（字节顺序，同一 MODEL 的模式体内）至少有一个 RE〔R-29〕。
4. 整数范围 lo < hi；浮点范围 lo < hi 且 eps ≥ 0（NaN、±Inf 已由 SPEC-0003 第 3 条第 4 项排除）〔R-28〕。
5. RE 的附参 1 是 `0xFF`，或当前版本已分配、且关联数据长度由附参给出的码值〔R-28〕；附参 3 的 bit0–6 是 `g`、`G`、`f`、`S` 之一；正则按 RE2 编译（SPEC-0003 第 3 条第 8 项）。
6. `!?Type` 的类型标识已分配（第 6 条）。
7. `?{}` 的本层满足第 9 条的限制。

`MODEL` 附参的「有取值」标记见 SPEC-0003 第 3 条第 7 项。

### 13. 成本

```
K + m + 10 + B(目标字节) + 比较次数 + 正则匹配成本 + 哈希成本
```

- `K`：a = 1，r 为 1 或 2；`D` 为取值中新产生的变长内容的字节数；m 为取值的个数。
- `10 + B(目标字节)`：目标的解码，在匹配之前计入。
- 比较次数：单元与目标指令的每一次比对计 1（深匹配的块指令计 1，其块体内的比对另计）；`...` 的每一次尝试计 1；`?{}` 的每一次存在判定计 1。
- 正则匹配：每次求值 RE，计 ⌈数据字节 × 正则字节 / 8⌉（SPEC-0006 第 3 条）。
- 哈希：每次计算目标数据的哈希，计 20 + B(数据字节)（BLAKE3，k = 1）。

比较、正则与哈希的成本在发生时计入，超出预算立即失败。


## 边界与限制

- MODEL 只看字节码的结构，不执行目标，因此不能判断目标在运行时走哪条路径。
- 文本写法（`^DATA[20]{?}?`、`!Bool`、`RE{8/.../S}`、`?RE{...}` 等）与字节码的对应由 SPEC-0201 定义。
- 模式体至多 32767 字节（SPEC-0002 第 6.11 条）。多个 `...` 的搜索量可能很大，由成本预算约束。
