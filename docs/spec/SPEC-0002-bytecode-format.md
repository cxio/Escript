## 概述

链上存储的字节码就是执行格式。本篇定义字节码的编码基元，以及全部 256 个码值的格式：附参的个数与编码、关联数据、实参个数、返回值个数，以及使用位置的限制。

本篇只定义「怎样解码」。加载期的校验规则见 SPEC-0003，各指令的语义见 SPEC-0101 ～ 0106。


## 规格正文

### 1. 指令的结构

一条指令依次由三部分组成：

```
指令码（1 字节） 附参 1 … 附参 k（按格式表顺序） 关联数据（可选）
```

- 指令码之后的附参个数与编码由格式表给出，没有分隔符，也没有长度前缀。
- 关联数据的长度由某个附参给出，或由数据本身的编码确定（内联值）。
- 一段字节码是若干条指令首尾相接。段的全部字节必须恰好被完整的指令覆盖。
- 空段（0 字节）是合法的。

### 2. 附参的编码类型

| 类型 | 长度 | 解码 |
| --- | --- | --- |
| `u8` | 1 | 无符号整数 0–255 |
| `i8` | 1 | 二进制补码整数 −128–127〔R-03〕 |
| `u16be` | 2 | 大端无符号整数〔R-02〕 |
| `u32be` | 4 | 大端无符号整数〔R-02〕 |
| `f32be` | 4 | IEEE 754 binary32，大端〔R-02〕 |
| `f64be` | 8 | IEEE 754 binary64，大端〔R-02〕 |
| `bytes(N)` | N | 原样的 N 个字节 |
| `uvarint` | 1–10 | LEB128 无符号变长整数，见 2.1〔R-01〕 |
| `varint` | 1–10 | ZigZag 编码的有符号变长整数，见 2.1〔R-01〕 |
| `HostRef` | 可变 | 外部脚本引用，形状由宿主规格声明，见 2.2〔R-04〕 |

#### 2.1 变长整数

`uvarint` 与 Go `encoding/binary` 的 `Uvarint` 相同：每字节低 7 位为数据，最高位为 1 表示后面还有字节，低位组在前。`varint` 与 `binary.Varint` 相同：先按 ZigZag 映射为无符号数（`0→0, -1→1, 1→2, -2→3, …`），再按 `uvarint` 编码。

两者都必须满足**最短编码**（DEC-0003 第 2 条第 1 项），否则为无效编码：

1. 编码不超过 10 字节，值不超出 64 位：第 10 字节只能是 `0x00` 或 `0x01`，且不得带延续位。
2. 多于 1 字节时，末字节不得为 `0x00`。

用途〔R-01〕：

- `uvarint` 用于长度、数量与序位：`DATA`、字符串、值集、`CODE`、块指令、`SHELL` 的长度，`SUBSTR` 的符文数，`.[n]` 的指令数，`OUT` / `INOUT` 的输出序位，以及 Evidcoin `HostRef` 中的年度与输出序位。
- `varint` 用于取值：整数字面量（opcode 5）、`DATE`（opcode 12）、整数范围匹配（opcode 123）的两个边界。

作为长度使用时，值还不得超过所在范围（段、父块）剩余的字节数，否则为无效编码。

#### 2.2 外部脚本引用（HostRef）

`GOTO`、`EMBED`、`SCRIPT` 的附参是一个外部脚本引用。引用的格式属于宿主（DEC-0002 第 1 条），但核心必须能解码它，才能确定指令长度。因此〔R-04〕：

- 宿主规格以本节第 2 条中除 `HostRef` 以外的类型声明引用的**字段序列**，例如 Evidcoin 为 `uvarint（年度）, bytes(48)（交易 ID）, uvarint（输出序位）`。
- 核心按该序列解码，把各字段作为该指令的附参 1、2、3……（MODEL 的 `^?`、`#` 按此编号）。
- 字段的含义与取数由宿主负责（SPEC-0008）。

### 3. 关联数据的种类

| 种类 | 说明 | 加载期是否解码 |
| --- | --- | --- |
| 内联值 | 无附参给出长度，长度由编码本身确定：Byte 1 字节、Rune 4 字节（`u32be`）、Float 8 字节（`f64be`）、整数与 DATE（`varint`） | 按值校验（SPEC-0003） |
| 数据 `data(L)` | L 个原样字节：`DATA`、字符串、正则、`CODE`、`SHELL`、MODEL 中 `RE` 的正则 | 否（正则在加载期编译） |
| 代码块 `code(L)` | L 字节的指令序列 | 是 |
| 表达式体 `expr(L)` | L 字节的指令序列，按表达式文法解析（SPEC-0003 第 5 条） | 是 |
| 模式体 `pattern(L)` | L 字节的指令序列，按模式体规则解析（SPEC-0003 第 6 条） | 是 |
| 成员序列 `members(L)` | L 字节的值指令序列（值集） | 是 |
| 大整数绝对值 | L 字节大端绝对值，L 由附参给出 | 按值校验 |

### 4. 实参与返回值

**实参个数**沿用构想层的记号（`Design.md`「指令的参数配置」），取值规则见 SPEC-0005 第 4 条：

| 记号 | 含义 |
| --- | --- |
| `0` | 不读取实参区，也不从数据栈取实参 |
| `n` | 固定 n 个 |
| `-1` | 不定数量：取实参区全部（可以为 0 项），不访问数据栈 |
| `-1≤1` | 不定数量，但实参区至多 1 项，否则失败〔R-07〕 |
| `-1≥1` | 不定数量，但实参区至少 1 项，否则失败 |
| `-2` | 由附参给出（仅 `CALL`） |

**返回值个数**：

| 记号 | 含义 |
| --- | --- |
| `—` | 没有返回值。截取前缀不能作用于它（DEC-0003 第 3 条） |
| `k` | 静态确定的 k 个（k ≥ 1） |
| `*` | 个数在运行时才确定（可以为 0） |

返回值的默认去向是数据栈，按返回顺序依次入栈（最后一个在栈顶）。唯一的例外是 `&[n]`（opcode 21），其默认去向是实参区（构想层：「本系列指令……取值时直接放入实参区」）。截取前缀改变去向，见 SPEC-0005 第 5 条。

### 5. 标记

格式表的「标记」一列：

| 标记 | 含义 |
| --- | --- |
| U | 解锁段可用（`Design.md`「解锁数据」：`[0-45]`，以及 `SYS_NULL`、系统占位符） |
| P | 私有专属：公共验证执行到即失败 |
| H | 语义由宿主规格定义，核心只规定格式与接口契约（SPEC-0008） |
| E | 只能直接位于表达式体内 |
| M | 只能位于模式体内 |
| 块 | 带代码块、表达式体或模式体 |
| 前缀 | 截取前缀，作用于紧随其后的一条指令 |

附参后标注「**索引**」的，其取值由版本的取值表给出（字段表、方法表、见证条目表等），表中没有的取值是未分配取值（SPEC-0007 第 4 条）。没有标注的附参，取值范围就是格式表所列的范围。两种情形的处理相同：取值不在范围或取值表内，该段加载失败（DEC-0003 第 2 条第 10 项、SPEC-0003）。

### 7. 解锁段可用的码值

按 `Design.md`「解锁数据」与上表的 U 标记：0–13、16–45、169、254。其中未分配的 14、15 不可用。

### 8. 值集的成员

值集（opcode 9）的 `members(L)` 只能由以下值指令组成：`TRUE`、`FALSE`、Byte、Rune、整数、大整数、浮点数、字符串（opcode 1–8）。成员的类型约束见 SPEC-0003 第 3 条。


## 边界与限制

- 本篇不定义文本语法。文本中的别名（如 `ENV{Height}`、`MO_MATH{Abs}`、`FN_HASH256{blake3}`）由 SPEC-0201 映射到附参取值。
- 长度类附参的上限受段长度与 SPEC-0006 的限额约束。例如表达式体至多 255 字节（`u8`），MODEL 的模式体至多 32767 字节（15 位），实际上还受脚本长度上限约束。

## 对 Plan 的约束

- 格式表必须实现为一张数据表（码值 → 附参类型序列、关联数据种类、实参与返回记号、标记），解码器、加载期校验、反编译器与 MODEL 共用这一张表，不得在各处分别硬编码。
- 变长整数的解码必须在 `binary.Uvarint` / `binary.Varint` 之外另行检查最短编码。
- 表中的每个码值至少要有一个「解码成功」与一个「无效编码」的测试向量（DEC-0001 第 5 条）。
