## 概述

核心 VM 是纯粹的执行引擎：输入字节码、版本、宿主提供的环境与成本预算，输出结果、实际成本与执行标记，内部没有 I/O。凡是与具体区块链有关的内容（字段、引用格式、签名、地址、参数）都由宿主定义。

本篇规定：宿主规格必须包含的内容；环境字段的索引划分与核心字段；宿主在执行前提供的环境；执行中的接口调用及其契约；执行结果与执行标记；私有执行的要求。


## 规格正文

### 1. 分层

| 归属 | 内容 |
| --- | --- |
| 核心 | 值类型与编码；解码与加载期校验；数据栈、实参区、局部域、全局域；控制流与表达式；运算、比较、逻辑、转换；集合；MODEL；EVAL；通关状态机；校验域记录；成本计量与限额；版本门控；系统占位符的执行；公共 / 私有两种执行模式；`ENV` 的核心字段（第 3 条） |
| 宿主 | 环境字段表（`GVAL`、`ENV` 的宿主字段、`IN`、`OUT`、`INOUT`、`XFROM`）；外部脚本的引用格式与取数；签名验证；公钥哈希与地址方案；见证条目表；宿主专属的系统指令；私有域通道；各项参数的取值 |

- 指令码统一，不为不同宿主划分码位。SPEC-0002 中标记 H 的指令，核心规格写明附参、实参个数、返回值个数与失败条件，算法与取值由宿主规格给出（第 5 条）。
- 宿主规格没有实现的宿主指令，对该宿主而言是未分配码位，含有它的段加载失败（SPEC-0007 第 3、4 条）。
- 核心规格与核心实现不得依赖任何宿主的具体类型或取值。

### 2. 宿主规格必须包含的内容

| 项 | 内容 | 相关规格 |
| --- | --- | --- |
| 版本 | 从输出结构的哪个字段取得脚本版本，以及取值与核心版本号的对应 | SPEC-0007 第 1 条 |
| 环境字段表 | `GVAL`、`ENV`（宿主区间）、`IN`、`OUT`、`INOUT`、`XFROM` 每个字段的索引、名称、值类型、是否属于源码类、是否与高度相关、取不到时的处理 | 第 3、4 条 |
| 外部脚本引用 | 引用的字段序列（用 SPEC-0002 第 2 条的类型声明）与每个字段的约束；目标的含义、取数与证明的验证 | SPEC-0002 第 2.2 条，第 5.1 条 |
| 见证条目表 | 每个条目的索引、名称（`<Sig>`、`<PubKey>`、`<Sigs>`、`<PubKeys>`、`<Rests>` 等）、值类型 | 第 4 条 |
| 签名验证 | `FN_CHECKSIG`、`FN_MCHECKSIG`、`SYS_CHKPASS` 的实参类型、签名算法、签名消息的构造、校验域的写入序位、成本 | 第 5.2 条 |
| 公钥哈希与地址 | `FN_PUBHASH`、`FN_MPUBHASH`、`FN_ADDRESS` 的算法、实参与返回值类型、失败条件、成本 | 第 5.3 条 |
| 宿主系统指令 | `SYS_AWARD` 等的语义，或声明不实现 | 第 5.3 条 |
| 参数 | `MaxTxScriptCost`、`MaxBlockScriptCost`，是否改写 `MaxInputScriptCost`；锁定脚本在创建时的长度检查；其它宿主参数 | SPEC-0006 第 4 条 |
| 新版本的接受 | 新的脚本版本从何时起被接受〔P-04〕 | SPEC-0007 第 6 条 |
| 私有域 | 私有域通道的提供方式；`SHELL` 白名单的配置方式 | 第 7 条 |

宿主的前置检查（例如 Evidcoin 中币金与凭信的区别对待）在脚本执行之前完成，不属于脚本系统，宿主规格可以描述，但不在本篇约束之内。

### 3. 环境字段的索引划分

`GVAL`、`IN`、`OUT`、`INOUT`、`XFROM` 的字段全部由宿主定义。

`ENV` 的字段索引（`u8`）划分如下〔R-15〕：

| 区间 | 归属 |
| --- | --- |
| 0–31 | 核心。v1 分配 0–9，10–31 未分配 |
| 32–255 | 宿主 |

v1 的核心字段〔R-16〕：

| 索引 | 名称 | 类型 | 取值 |
| --- | --- | --- | --- |
| 0 | `Passed` | Bool | 当前脚本域的通关状态：未决与通过为 `true`，未通过为 `false`（SPEC-0005 第 7 条） |
| 1 | `InGoto` | Bool | `Gotos` 大于 0 |
| 2 | `InEmbed` | Bool | 当前指令位于 `EMBED` 目标段中 |
| 3 | `InScript` | Bool | 当前指令位于 EVAL 代码中，且该 Script 由 `SCRIPT` 创建 |
| 4 | `InCode` | Bool | 当前指令位于 EVAL 代码中，且该 Script 由 `CODE` 创建 |
| 5 | `Gotos` | Int | 当前脚本域的 `GOTO` 深度：顶层为 0，每经一次 `GOTO` 加 1 |
| 6–9 | `Embed1` ～ `Embed4` | Bytes 或 Nil | 当前脚本域中第 1 ～ 4 次执行的 `EMBED` 所嵌入的段的字节码；尚未发生的为 Nil |

在 EVAL 代码中：`Passed` 是 EVAL 环境自己的通关状态；`Embed1` ～ `Embed4` 为 Nil（EVAL 环境不能 `EMBED`）；`InGoto`、`InEmbed`、`Gotos` 取发起 `EVAL` 之处的值。

### 4. 执行前由宿主提供的环境

宿主在执行之前一次性提供：

| 内容 | 用途 |
| --- | --- |
| 被花费输出的锁定脚本及其版本 | 锁定段 |
| 解锁脚本 | 解锁段 |
| 环境字段的值 | `GVAL`、`ENV`（宿主区间）、`IN`、`XFROM` 按索引取值；`OUT`、`INOUT` 按输出序位与索引取值 |
| 见证条目 | 系统占位符按索引取值 |
| 成本预算 | `MaxInputScriptCost` |
| 执行模式 | 公共验证或私有执行 |

要求：

1. **确定性**：环境字段的值只取决于交易本身与它将进入的区块之前的链状态。`BlockTime` 这类字段必须是确定性的（构想层：Evidcoin 的区块时间按固定间隔计算）。
2. **类型**：字段的值必须是 SPEC-0004 定义的类型，并与宿主字段表声明的类型一致。宿主不得提供 Float。
3. **限额**：字段的值在被取用时按 SPEC-0006 第 1 条检查（源码类字段上限 16KB，其它 8KB）。
4. **取不到**：宿主字段表为每个字段声明取不到时的处理：返回 Nil（字段在该交易中不适用，例如币金输出的凭信字段），或数据不可用（节点暂时缺少数据）。字段索引未分配不属于这里，它在加载期即失败（SPEC-0007 第 4 条）。
5. **`XFROM`**：字段描述「源交易」，即正在验证的交易，从 `GOTO` / `EMBED` 目标的角度看。`XFROM` 位于 `GOTO` / `EMBED` 目标以外即失败（SPEC-0003 第 9 条）。
6. **见证条目**：本次验证没有某个条目时，执行到对应的系统占位符即失败（SPEC-0005 第 13 条）。
7. **高度相关**：宿主字段表标注哪些字段与高度相关（Evidcoin 至少包括 `Height`、`BlockTime`、`TipHeight`，以及 `GVAL` 中的同类字段），核心据此设置执行标记（第 6 条）。

宿主可以在执行前扫描字节码，预先取齐 `GOTO`、`EMBED`、`SCRIPT` 的目标（它们写在附参中，是静态的）。预取不改变加载期校验的时点（SPEC-0003 第 1 条）。

### 5. 执行中的接口调用

接口只承载粗粒度、低频的操作：加载外部脚本、签名验证、宿主定义的函数。高频的环境取值不经过接口（第 4 条）。

共同契约：

- 同样的输入，在所有拥有完整数据的节点上得到同样的输出。
- 每次调用的成本在调用之前确定并计入（SPEC-0006 第 2 条）；预算不足即失败，不发起调用。成本只取决于请求本身（算法、长度、个数），不取决于调用的结果。
- 调用可以报告「数据不可用」。核心收到后，本次验证的结果即为数据不可用（SPEC-0005 第 9 条）。

#### 5.1 加载外部脚本

用于 `GOTO`、`EMBED`、`SCRIPT`。输入：按宿主声明解码的引用字段。输出：以下三者之一〔R-17〕：

| 输出 | 核心的处理 |
| --- | --- |
| 字节码与版本 | 继续：计 ⌈字节数 / 64⌉，按 SPEC-0003、SPEC-0007 加载（`SCRIPT` 则创建 Script 值） |
| 不存在：宿主能确定引用的目标不存在，或不是一个可引用的输出 | 失败 |
| 数据不可用：节点暂时取不到目标 | 数据不可用 |

- 默克尔证明（用户携带或节点自查）的验证由宿主完成。外部加载按固定成本计，与证明的来源无关（SPEC-0006 第 3 条）。
- 返回的版本是宿主按 SPEC-0007 第 1 条映射后的核心版本号，或「未知版本」。

#### 5.2 签名验证

用于 `FN_CHECKSIG`、`FN_MCHECKSIG`、`SYS_CHKPASS`。

- 输入：指令种类，以及该指令取得的实参（`SYS_CHKPASS` 没有实参，签名与公钥等由宿主从见证信息中取得）。
- 输出：验证是否成功；以及要写入校验域的序位与各序位的状态（SPEC-0005 第 13 条）。
- 核心负责写入校验域：EVAL 环境中不写；`SYS_CHKPASS` 只在成功时写，失败则本次验证失败。
- 签名消息的构造（包括授权标识）由宿主规格定义。授权标识不设系统占位符：标准验证中它随见证信息导入，定制验证中它作为普通值经实参传入；两种情形下签名消息都包含授权标识（DEC-0002 第 2 条）。
- 实参的类型或个数不符合宿主声明即失败。

#### 5.3 宿主定义的函数与系统指令

用于 `FN_PUBHASH`、`FN_MPUBHASH`、`FN_ADDRESS`、`SYS_AWARD`。

- 输入：码值、附参、实参。核心已按 SPEC-0002 的格式取得实参（实参个数是固定的，见格式表）。
- 输出：返回值（个数与 SPEC-0002 格式表一致），或失败。
- 实参类型的要求、失败条件与成本由宿主规格给出。

#### 5.4 示意

```go
// 示意，非规范。
type Host interface {
    LoadScript(ref []AuxField) (code []byte, ver Version, err error) // ErrNotFound → 失败；ErrUnavailable → 数据不可用
    SigCost(req SigRequest) uint64
    VerifySig(req SigRequest) (SigResult, error)                     // 结果含要写入校验域的序位与状态
    CallCost(op byte, aux []AuxField, args []Value) uint64
    SysCall(op byte, aux []AuxField, args []Value) ([]Value, error)
}
```

### 6. 执行结果与执行标记

核心 VM 对一个输入的验证返回：

| 项 | 内容 |
| --- | --- |
| 结果 | 通过、失败、数据不可用（SPEC-0005 第 9 条） |
| 实际成本 | 至结束时累计的成本，包括加载期成本 |
| 执行标记 | 见下 |
| 退出值 | 顶层 `EXIT` 的实参（如有）。宿主规格规定其用途；不使用时忽略 |

执行标记（DEC-0002 第 5 条）：

| 标记 | 含义 |
| --- | --- |
| 高度相关 | 本次执行读取过宿主标注为「与高度相关」的字段（第 4 条第 7 项）。带此标记的交易，宿主的内存池在每个新区块之后需要重验 |

只有执行到的读取才设置标记；跳过的代码不设置。

宿主对结果的处理：

| 结果 | 宿主的处理 |
| --- | --- |
| 通过 | 收录 |
| 失败 | 拒绝；可以降低转发者的信任 |
| 数据不可用 | 稍后重试；不丢弃交易，不惩罚转发者。没有数据的节点不把这类交易打包进区块 |

实现可以附带失败的位置、原因等诊断信息，它们不属于共识。原因中应能区分「版本未知」：没有升级的节点据此可以不降低转发者的信任，因为对方可能只是已经升级〔R-21〕。

### 7. 私有执行的要求

- 私有域通道（`INPUT`、`OUTPUT`、`BUFDUMP`、`PRINT`、`SYS_TIME`、`SHELL`、`FN_PRIV`、`EXT_PRIV`）只在私有执行中由宿主提供；公共验证中的行为见 SPEC-0005 第 10 条。
- **私有节点必须默认关闭 `SHELL`**，只有显式配置白名单（例如按脚本哈希，或按签名者授权）才执行。任何人都能发一笔交易让私有节点运行其中的命令，这是强制要求。
- 私有域通道的数据只影响本地，不参与共识。


## 边界与限制

- 核心 VM 只验证一个输入。交易与区块预算的累计、输入之间的并行与缓存，由宿主负责。
- 交易的结构与 TxID 的计算属于宿主。Evidcoin 的 TxID 既不含见证信息，也不含解锁脚本，所以解锁段的灵活性不造成交易延展性（DEC-0002 影响）。其它宿主必须自行保证这一点。
- 超级赎回不在本规格集的范围内（SPEC-0001 第 6.1 条）。

## 对 Plan 的约束

- 核心包定义接口与环境的数据结构，宿主包实现它们；核心包不得引用宿主包（SPEC-0001）。
- 核心必须提供一个不依赖任何链的测试宿主（固定字段表、确定性的伪签名、内存中的脚本库），用于生成核心测试向量。
- 接口的每种输出（成功、不存在、不可用、失败）都要有测试向量；预算恰好不足以支付一次接口调用的情形，必须断言没有发起调用。
