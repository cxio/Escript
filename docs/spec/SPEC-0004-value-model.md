## 概述

本篇定义脚本运行时的值：有哪些类型，各类型的取值范围，Float 在公共验证中的限制，数值的提升，相等与大小比较的类别，值的可变性，以及用于限额与成本的「值的大小」。

各指令对类型的具体要求与转换规则见 SPEC-0101 ～ 0106。


## 规格正文

### 1. 类型一览

| 类型 | 取值 | 字面量（opcode） | 可变 |
| --- | --- | --- | --- |
| Nil | 唯一的值 `nil` | 0 | 否 |
| Bool | `true`、`false` | 1、2 | 否 |
| Byte | 0–255 | 3 | 否 |
| Rune | Unicode 标量值：0–`0x10FFFF`，不含 `0xD800–0xDFFF` | 4 | 否 |
| Int | int64：−2⁶³ ～ 2⁶³−1 | 5 | 否 |
| BigInt | 绝对值小于 2¹⁰¹⁶ 的整数 | 6 | 否 |
| Float | IEEE 754 binary64，**私有执行专用** | 7 | 否 |
| String | 字节序列，按 UTF-8 解释但不检查合法性 | 8 | 否 |
| Bytes | 字节序列，即成员类型为 Byte 的切片 | 10 | 否 |
| RegExp | 一个已编译的 RE2 正则及其源文本 | 11 | 否 |
| Time | 毫秒时刻与固定时区偏移〔R-05〕 | 12 | 否 |
| Script | 字节码与版本号 | 16、17 | 否 |
| 切片 | 有序的成员序列，带成员类型 | 9（值集） | 否 |
| Dict | 有序的「String 键 → 值」映射 | 13（由实参构造） | **是** |
| 模块对象 | 由模块的构造方法创建 | — | 否 |

数据栈、实参区、局部域、全局变量区存放的都是上表中的值。实现中的表示（例如 Go 的 `[]any`）不属于规格。

### 2. 各类型的补充定义

**Rune。** 运行时的 Rune 总是合法的 Unicode 标量值。产生代理区或超出范围的 Rune 的运算即失败（DEC-0005 第 7 条）。

**BigInt。** 运行时的 BigInt 可以落在 int64 范围内（例如 `BIGINT` 转换的结果），不会自动变回 Int（DEC-0005 第 3 条）。字面量编码要求超出 int64 范围（SPEC-0003），这只是编码规则，不是值的约束。运算结果的绝对值达到 2¹⁰¹⁶ 即失败。

**String 与 Bytes。** 两者都是字节序列，但属于不同类型，不会隐式互相转换。String 的「字符」操作（`SUBSTR`、`RUNES` 等）按 UTF-8 解码，非法字节的处理由各指令规定。

**Bytes 与切片。** Bytes 就是成员类型为 Byte 的切片：`SLICE`、`INDEX`、`SIZE` 等切片操作对它适用，`INDEX` 取出的成员是 Byte（DEC-0005 第 1 条）。值集 `{'A', 'B'}` 的结果就是 Bytes。

**切片的成员类型。** 每个切片带一个成员类型 E：E 可以是任一值类型，也可以是 `any`。成员类型为 E 的切片记作 `[]E`，其中每个成员都是 E 类型；`[]any` 的成员可以是任意值。切片的成员类型由产生它的指令决定（例如值集按成员的提升结果，`SHIFT` 产生 `[]any`，`RANGE` 产生 `[]Int`），见各指令的规格。

**Time**〔R-05〕。一个 Time 值由两部分组成：

- 时刻：int64 Unix 毫秒数，取值为 int64 全域（DEC-0003 第 2 条第 11 项）；
- 时区偏移：以秒计的固定偏移，绝对值小于 24 小时，且为整分钟（RFC 3339 的 `±hh:mm`）。

只有从 RFC 3339 文本构造（`TIME(String)`）时，偏移才可能不为 0。`DATE` 字面量、`TIME(Int)`、`TIME(Nil)` 产生的 Time 偏移为 0（UTC）。偏移只影响按日历取值的方法（年、月、日、时等，见 SPEC-0105）；相等与大小比较、`INT(Time)`、`BYTES(Time)` 都只看时刻。`DATE` 字面量只编码时刻，因此带偏移的 Time 反编译为文本时按 UTC 书写。公共执行中不使用时区数据库，只认 UTC 与固定偏移（DEC-0001 第 3 条）。

**Script。** 由 `CODE`（取其所在段的版本）或 `SCRIPT`（取被引用输出的版本）创建，携带版本号（DEC-0004 第 1 条）。不能由 Bytes 或其它类型转换得到（构想层 `8.转换指令.md`）。

**RegExp。** 由正则字面量或 `REGEXP(String)` 创建，保存编译结果与源文本。

**Dict。** 键是 String（按字节比较是否相同），按插入顺序迭代。字典的值，以及值中切片的成员（递归地），都不能是 Dict（DEC-0005 第 11 条）。

**模块对象。** 由 `MO_MATH[0]`、`EXT_MO{Module}` 等构造方法创建，可以作为 `CALL` 的目标。模块对象没有可见的内部状态。

### 3. Float 与公共验证

**公共验证中，任何指令产生 Float 值即失败**（DEC-0005 第 2 条）。「产生」包括：Float 进入数据栈、实参区、局部域、全局变量区，成为集合的成员，或作为表达式的中间操作数。

此外〔R-06〕，产生成员类型为 Float 的切片（`[]Float`）也即失败，即使切片为空（例如 `NIL ANYS[7]`）。

实现必须把这一检查集中在构造 Float 值（与 `[]Float` 切片）的一处，不在各指令中分别检查。私有执行中 Float 照常使用，NaN、±Inf 可以在运算中产生。

### 4. 数值类与提升

**数值类**包括 Byte、Rune、Int、BigInt、Float。按 DEC-0005 第 3 条：

- 整数类按 Byte → Rune → Int → BigInt 提升。Byte、Rune 参与算术运算时先提升为 Int，算术结果至少是 Int。
- 有 BigInt 参与时结果为 BigInt，不自动降回 Int。
- 私有执行中，Int 与 Float 运算提升为 Float；BigInt 与 Float 没有共同类型，二者一起参与运算或比较即失败。
- Bool、String、Bytes、Nil、Time 等不是数值，参与算术运算即失败（`ADD` 的拼接与字典合并另见 SPEC-0102）。
- 表达式 `()` 不接受 BigInt 操作数（DEC-0005 第 3 条）。

值集（opcode 9）的成员在运行时按 Byte → Rune → Int → BigInt 或 Byte → Rune → Int → Float 统一为最大的类型（构想层 `1.值指令.md`），得到相应成员类型的切片。

### 5. 相等与大小比较的类别

比较按**类别**进行：

| 类别 | 成员 | 相等比较 | 大小比较 |
| --- | --- | --- | --- |
| 数值 | Byte、Rune、Int、BigInt、Float | 先提升再按值比较 | 可以 |
| String | String | 按字节 | 按字节，从左到右 |
| Bytes | Bytes | 按字节 | 按字节，从左到右 |
| Time | Time | 按时刻 | 可以，按时刻 |
| Script | Script | 按字节（不比较版本） | 不可以 |
| Bool | Bool | 按值 | 不可以 |
| Nil | Nil | 只等于 Nil | 不可以 |
| 不可比较 | 成员类型不是 Byte 的切片、Dict、RegExp、模块对象 | 失败 | 失败 |

- 两边属于不同类别时：`EQUAL` 为 `false`、`NEQUAL` 为 `true`，不失败；`LT` 等大小比较即失败。任一边是不可比较的类型时，相等与大小比较都失败（DEC-0005 第 5 条）。
- 数值的提升按第 4 条；Byte 65 等于 Int 65，Int 与值相同的 BigInt 相等。私有执行中 BigInt 与 Float 比较即失败。
- Float 按 IEEE 754 比较：NaN 不等于任何值（包括自身），`+0` 等于 `-0`。
- Time 与 Int 属于不同类别（DEC-0005 第 5 条）。
- 「按字节从左到右」：逐字节按无符号值比较，较短者是较长者的前缀时较短者为小。

### 6. 值语义

按 DEC-0005 第 11 条：

- 除 Dict 外，所有值不可变。产生新内容的运算总是返回新值。
- 切片的子切片（`SLICE`）可以与原切片共享底层存储；因为切片不可变，共享不可见。扩展切片（`EXTEND`）不得改变任何已有的切片。
- Dict 是引用：多个位置（数据栈、局部域、全局变量、切片成员）可以引用同一个 Dict，`SET`、`DEL`、`CLEAR` 的修改对所有引用可见。`COPY` 产生一个新 Dict，键值浅复制。
- 字典不能直接或间接地包含字典（第 2 条），因此任何值都不会形成环。

### 7. 值的大小

`size(v)` 用于单项大小上限（SPEC-0006 第 1 条）与按字节计的成本（SPEC-0006 第 2 条）：

| 类型 | `size(v)`（字节） |
| --- | --- |
| Nil、Bool、Byte | 1 |
| Rune | 4 |
| Int、Float、Time | 8 |
| BigInt | 绝对值的最少字节数，至少 1 |
| String、Bytes | 字节数 |
| RegExp | 源文本的字节数 |
| Script | 字节码的字节数 |
| 其它切片 | 各成员 `size` 之和 |
| Dict | 各条目「键的字节数 + 值的 `size`」之和 |
| 模块对象 | 1 |

被多处引用的同一个 Dict，在每一处分别计算。


## 边界与限制

- 本篇不定义值的文本形式（`STRING` 的输出、`PRINT` 的格式、反编译的写法），见 SPEC-0102 与 SPEC-0201。
- 本篇不定义各指令对类型的要求，例如 `IF` 是否只接受 Bool，见 SPEC-0101。
- 集合（切片、Dict）的成员数与单项大小的上限见 SPEC-0006。

## 对 Plan 的约束

- 值的内部表示必须能区分 String 与 Bytes、Byte 与 Int、Int 与值相同的 BigInt，以及切片的成员类型。
- Float 与 `[]Float` 的构造必须集中在一个函数中，该函数在公共执行中直接失败。
- Time 的实现不得调用依赖时区数据库的方法（如 `time.LoadLocation`、`Local`）参与公共执行。
- 测试向量须覆盖第 5 条表中每一对类别的相等与大小比较。
