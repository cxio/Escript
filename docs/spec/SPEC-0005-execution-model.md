## 概述

本篇定义一次输入验证从开始到得出结果的全过程：执行状态由哪些部分组成，指令如何取得实参、返回值去往何处，块与局部域，通关状态与各种结束方式，表达式的求值，子执行（`GOTO`、`EMBED`、`EVAL`、`MAP` / `FILTER`）的环境，以及公共执行与私有执行的差别。

各指令自身的语义见 SPEC-0101 ～ 0106。


## 规格正文

### 1. 一次验证的输入与输出

核心 VM 以**一个输入**为单位验证。

输入：

| 项 | 说明 |
| --- | --- |
| 解锁脚本 | 字节码 |
| 锁定脚本 | 字节码，及其版本号（宿主从输出结构中取得） |
| 执行模式 | 公共或私有（第 10 条） |
| 环境 | 宿主提供的字段、见证条目与接口（SPEC-0008） |
| 预算 | `MaxInputScriptCost`（SPEC-0006） |

输出：

| 项 | 说明 |
| --- | --- |
| 结果 | 通过、失败、数据不可用（第 9 条） |
| 成本 | 本次验证累计的成本。只有结果为通过时，成本才属于共识（SPEC-0006 第 2 条） |
| 执行标记 | 见 SPEC-0008 第 6 条 |
| 退出值 | 顶层 `EXIT` 的实参（如有），交给宿主 |
| 诊断（非规范） | 失败的原因与位置，供日志与测试使用，不参与共识 |

### 2. 验证的流程

1. 按 SPEC-0003 第 2.1 条确认版本、加载解锁段与锁定段。失败即结束。
2. 建立**顶层脚本域**（第 3 条）。
3. 执行解锁段。解锁段中发生的任何错误都使验证失败，不适用「未决即通过」（构想层 `6.结果指令.md`：锁定脚本必须已经开始执行）。
4. **边界**（`Design.md`「边界处理」）：实参区必须为空，否则失败；解锁段的局部域与 IF 状态丢弃。数据栈、全局变量区与通关状态保留。
5. 执行锁定段，从一个新的顶层局部域开始。
6. 按第 7 条得出结果。

解锁段只能使用 `[0-45]`、`SYS_NULL` 与系统占位符（SPEC-0003 第 7 条），所以解锁段中不会改变通关状态，也不会提前结束。

### 3. 执行状态

#### 3.1 验证级（一个输入共享）

| 状态 | 说明 |
| --- | --- |
| 成本计数 | 累计成本，超过预算即失败（SPEC-0006） |
| 校验域 | 按序位记录的签名验证结果（第 13 条），由顶层与 `GOTO` 链共享 |
| 外部加载计数 | `GOTO`、`EMBED`、`SCRIPT` 的加载总数，上限 8（SPEC-0006） |
| 执行模式、执行标记 | 第 10 条、SPEC-0008 第 6 条 |
| 私有缓存区 | `INPUT` 与 `OUTPUT` 的缓存区，只在私有执行中使用 |

#### 3.2 脚本域

脚本域是拥有以下状态的执行单位（DEC-0006 第 1 条）：

| 状态 | 初值 | 上限 |
| --- | --- | --- |
| 数据栈 | 空（`GOTO` 目标见第 11.1 条） | 高度 < 256 |
| 实参区 | 空 | ≤ 1024 项 |
| 全局变量区 | 256 个位置，全为 Nil | — |
| 通关状态 | 未决 | — |
| `GOTO` 次数 | 0 | ≤ 2 |
| `EMBED` 次数与已嵌入的脚本 | 0 | ≤ 4 |

脚本域有三种：顶层（解锁段与锁定段共用一个）、每个 `GOTO` 目标各一个、每次 `EVAL` 各一个（EVAL 环境，结构相同）。`EMBED` 的代码、`MAP` / `FILTER` 的块体不是脚本域。

#### 3.3 块的活动记录

每次进入一个块体，建立一个活动记录：

| 状态 | 说明 |
| --- | --- |
| 局部域 | 空，容量 128 项（第 6 条） |
| IF 状态 | 本层级最近一个 `IF` 的条件结果，初始为无 |

段的顶层也有一个活动记录。

### 4. 实参的取得

指令执行时，按 SPEC-0002 格式表中的实参记号取得实参（构想层「实参空间」「指令的参数配置」）：

| 记号 | 有 `~` 前缀 | 无 `~`，实参区非空 | 无 `~`，实参区为空 |
| --- | --- | --- | --- |
| `0` | —（加载期已禁止） | 不读取 | 不读取 |
| `n` | 从数据栈取 n 项，实参区不动 | 实参区必须恰好 n 项，全部取出；否则失败 | 从数据栈取 n 项 |
| `-1` 及其变体 | —（加载期已禁止） | 实参区全部取出 | 0 项 |
| `-2`（`CALL[n]`） | n ≥ 1 时同 `n` | n ≥ 1 时同 `n`；n = 0 时同 `-1≥1` | 同左 |

- 从数据栈取 n 项时，栈高度必须不小于 n，否则失败。取出的 n 项中，**实参 1 是最深的一项**（最早入栈的），实参 n 是栈顶。
- 从实参区取出时，**实参 1 是最先加入实参区的一项**（实参区是队列）。
- 取完实参后再检查变体约束：`-1≤1` 多于 1 项、`-1≥1` 为 0 项，即失败〔R-07〕。
- 实参区一经读取即全部清空（构想层：取出是一次性的）。
- 栈操作指令（`POP`、`TOP`、`PEEK` 等）的实参记号为 `0`，它们直接读写数据栈，与实参区无关。

### 5. 返回值的去向

指令执行后，按以下规则放置返回值；有多个返回值时按返回顺序逐个放置（构想层「自动展开」）：

| 情形 | 去向 |
| --- | --- |
| 无前缀 | 数据栈（`&[n]` 例外：实参区） |
| `@` 前缀 | 依次加入实参区 |
| `&` 前缀 | 依次加入当前局部域 |
| `_` 前缀 | 丢弃 |
| 表达式的操作数 | 成为该操作数的值（第 8 条） |

- 放置时检查容量：数据栈高度达到 256、实参区超过 1024 项、局部域超过 128 项，即失败。
- 返回值个数为 `*` 的指令，在运行时可能返回 0 个值，此时前缀不放置任何内容。
- 多值返回的顺序由各指令规定，例如 `POPS[n]` 按原来在栈中的顺序（自底向上），`DIVMOD` 先商后余数。

### 6. 块、局部域与 IF 状态

- **进入块体就新建局部域**（DEC-0006 第 8 条）：`IF`、`ELSE`、`SWITCH`、`CASE`、`DEFAULT`、`BLOCK` 的块体，`EACH`、`MAP`、`FILTER` 的每一轮迭代，以及 `EMBED` 的代码。离开块体时丢弃其局部域。表达式 `()` 不是块，没有局部域。
  - DEC-0006 第 8 条的清单没有列出 `SWITCH`。`SWITCH` 有自己的块体（`CASE` 之间可以有其它指令），按同一原则也有局部域〔R-13〕。
- 局部域只能由当前块体内的指令访问，块体之间不继承（构想层 `0.基本约束.md`）。`&[n]` 的 n ≥ 0 从最早加入的一项算起，n < 0 从最后加入的一项算起；越界即失败。
- **IF 状态**：`IF` 执行时把条件结果记入当前活动记录的 IF 状态，条件为真则执行块体。`ELSE` 在 IF 状态为假时执行块体。加载期保证 `ELSE` 之前最近的 IF 类指令是 `IF`（SPEC-0003 第 4 条），因此 `ELSE` 执行时 IF 状态总是有定义的。
- **跳过的块体不执行**，不计执行成本（SPEC-0006 第 2 条）。块体中的 `SYS_NULL` 仍按字节位置参与 `SOURCE` 的计算（第 13 条）。

### 7. 通关状态与结束方式

#### 7.1 通关状态机

每个脚本域的通关状态取值为**未决**（初值）、**通过**、**未通过**（DEC-0006 第 1 条）：

| 事件 | 效果 |
| --- | --- |
| `PASS(true)`、`CHECK(true)`、`SYS_CHKPASS` 成功 | 当前脚本域置为「通过」，继续执行 |
| `CHECK(false)` | 当前脚本域置为「未通过」，继续执行 |
| `PASS(false)`、`SYS_CHKPASS` 失败 | **否决**，见 7.2 |
| 运行错误 | 见 7.2 |

`ENV{Passed}` 读取当前脚本域的状态：未决与通过为 `true`，未通过为 `false`。

#### 7.2 结束方式与执行上下文

| 在哪里发生 | 否决 | `EXIT` | `END` / `INPUT`（公共执行） | 运行错误 |
| --- | --- | --- | --- | --- |
| 顶层 | 验证失败 | 结束顶层，按 7.3 判定 | 同 `EXIT` | 验证失败 |
| `EMBED` 的代码 | 同其所在脚本域 | 结束其所在脚本域 | 同 `EXIT` | 验证失败 |
| `GOTO` 目标 | 验证失败（透传） | 结束目标，回到调用者 | 同 `EXIT` | 验证失败 |
| `MAP` / `FILTER` 块体 | 同其所在脚本域 | 结束其所在脚本域 | 同 `EXIT` | 验证失败 |
| `EVAL` 代码 | `PASS(false)` 结束 EVAL，回到调用者 | 结束 EVAL，回到调用者 | 同 `EXIT` | 验证失败（向外传递） |

- 「结束其所在脚本域」：所在脚本域是顶层时按 7.3 判定；是 `GOTO` 目标时回到其调用者；是 EVAL 环境时结束 EVAL。
- 段执行完毕（到达段末）与 `EXIT` 相同。`EMBED` 代码执行完毕则回到嵌入点之后继续。
- `EXIT` 的实参只在结束顶层时交给宿主；在 `GOTO` 目标与 EVAL 中丢弃（DEC-0006 第 2 条）。
- `GOTO` 目标结束时，它自己的通关状态（通过或未通过）丢弃，不影响调用者（只能否决，不能放行）。
- 私有执行中 `END` 被忽略；`INPUT` 数据不足时「中断退出」，效果同上表 `END` / `INPUT` 一列。

#### 7.3 顶层的判定

顶层正常结束（段末、`EXIT`、公共执行中的 `END` / `INPUT`）时：通关状态为未决或通过，验证**通过**；为未通过，验证**失败**。

### 8. 表达式的求值

表达式 `()` 的块体按 SPEC-0003 第 5 条解析。求值规则（DEC-0006 第 10 条）：

1. **顺序**：按语法树后序、左先右后求值。每个运算符在其操作数都求得之后立即计算。因此操作数严格按书写顺序执行，例如 `( POP - POP )` 先执行左边的 `POP`；`( a / 0 * POP )` 在执行 `POP` 之前就因除零失败。
2. **操作数**：操作数指令按第 4 条取得实参，其返回值不入栈，而是成为操作数。返回值个数在运行时不是恰好 1 个（`*` 类指令），即失败。
3. **类型**：Byte、Rune 先提升为 Int；Int 照常；Float 只在私有执行中出现（公共执行中产生 Float 已经失败）；其它类型（含 BigInt）即失败（DEC-0005 第 3 条）。
4. **运算**：Int 运算按 DEC-0005 第 4 条：加、减、乘、取负溢出即失败；`/`、`%` 的除数为零即失败；除法向零截断，余数与被除数同号。一元 `+` 不改变值。私有执行中有 Float 参与时按 Float 运算。
5. **结果**：Int，或私有执行中的 Float。顶层表达式的结果按第 5 条放置；嵌套的 `()` 的结果是外层的操作数。

### 9. 结果与错误

一次验证的结果有三种（DEC-0002 第 4 条）：

| 结果 | 何时产生 |
| --- | --- |
| 通过 | 顶层按 7.3 判定为通过 |
| 失败 | 版本未知或加载失败（SPEC-0003、SPEC-0007）；任何运行错误；否决传到顶层；顶层结束时通关状态为未通过；超出成本预算或硬限额 |
| 数据不可用 | 宿主报告外部脚本或环境数据取不到（SPEC-0008 第 5 条） |

- 执行是顺序的，**最先发生的结束事件决定结果**。例如 `EVAL` 代码中发生数据不可用，结果就是数据不可用，而不是失败。
- 「运行错误」是各指令规格中写明的「失败」情形，包括类型不符、越界、溢出、实参个数不符、私有专属指令在公共执行中执行等。
- 诊断信息（错误原因、字节位置）不属于结果，不得影响共识。

### 10. 公共执行与私有执行

| 指令 | 公共执行 | 私有执行 |
| --- | --- | --- |
| `PRINT`、`FN_PRINTF`、`OUTPUT`、`BUFDUMP` | 空操作，照常消费实参，计基础成本 | 按指令执行 |
| `INPUT` | 同 `END` | 从 INPUT 缓存区读取；数据不足即中断退出 |
| `END` | 结束（7.2） | 忽略 |
| 私有专属指令（SPEC-0002 标记 P） | 执行到即失败 | 按指令执行（`SHELL` 须经白名单，SPEC-0008） |
| 产生 Float 的任何指令 | 即失败（SPEC-0004 第 3 条） | 照常 |

- 空操作仍要消费实参，否则同一脚本在两种模式下的实参区状态不同（DEC-0006 第 11 条）。
- 公共执行的结果是共识。私有执行的结果只影响本地。

### 11. 子执行

#### 11.1 GOTO

1. 检查：当前脚本域的 `GOTO` 次数小于 2，`GOTO` 深度小于 3，外部加载计数小于 8；否则失败。
2. 计费、取数与加载（SPEC-0006 第 2、3 条，SPEC-0008 第 5 条，SPEC-0003 第 2.2 条）。外部加载计数与当前脚本域的 `GOTO` 次数各加 1。取不到即数据不可用；版本未知或加载失败即整个验证失败。
3. 按第 4 条取得实参（记号 `-1`）：实参区的全部条目按顺序成为目标的初始数据栈，第一项在栈底。初始栈高度达到 256 即失败。
4. 建立新的脚本域（第 3.2 条），其中数据栈为上一步的初始栈；`GOTO` 深度为调用者的深度加 1。
5. 执行目标段。共享：校验域、成本计数、外部加载计数、执行模式与标记。
6. 目标结束（7.2）后，丢弃目标的全部状态，回到调用者，在 `GOTO` 之后继续。

#### 11.2 EMBED

1. 检查：当前脚本域的 `EMBED` 次数小于 4，外部加载计数小于 8；否则失败。
2. 计费、取数与加载，同 GOTO 第 2 步。外部加载计数与 `EMBED` 次数各加 1，记录嵌入的脚本（供 `ENV{Embed1}` ～ `ENV{Embed4}`）。
3. 在当前脚本域中执行目标段：共享数据栈、实参区、全局变量区与通关状态；从一个新的顶层活动记录（局部域、IF 状态）开始。
4. 目标段执行完毕，回到嵌入点之后继续；其中的 `EXIT`、`END` / `INPUT` 结束其所在脚本域（7.2）。

嵌入的代码单独解析（SPEC-0003），按其自身的版本解码与执行（DEC-0004 第 1 条）。

#### 11.3 EVAL

1. 实参必须是 Script，否则失败。Script 的版本未知，或高于发起 `EVAL` 的段的版本，即失败（SPEC-0007 第 5 条）。
2. 计费与加载（段的种类为 `EVAL` 代码）。`EVAL` 不计入外部加载计数（Script 值在创建时已经计入，`SCRIPT` 指令见 SPEC-0101）。
3. 建立 EVAL 环境：数据栈为空，实参区为空，全局变量区全为 Nil，通关状态为未决，新的顶层活动记录。校验域对其只读。
4. 执行代码，直到 7.2 所列的结束（正常结束、`EXIT`、`PASS(false)`、`END` / `INPUT`）。
5. EVAL 的数据栈剩余项按自底向上的顺序封装为一个 `[]any` 切片，作为 `EVAL` 的返回值。EVAL 环境的其余状态丢弃。
6. EVAL 内的运行错误使整个验证失败；数据不可用使整个验证的结果为数据不可用。

#### 11.4 MAP 与 FILTER

1. 按第 4 条取得实参（记号 `-1≥1`）：实参 1 是目标集（切片、Bytes 或 Dict），其余实参按顺序成为私有数据栈的初始内容。目标集为其它类型即失败。
2. 建立**私有块域**：自己的数据栈与实参区，在各轮迭代之间共享；全局变量区、通关状态、校验域属于所在脚本域。
3. 逐个成员迭代（Dict 按插入顺序，并按第 12 条的快照规则〔R-12〕）。每一轮新建局部域，循环变量见第 12 条。
4. 每一轮的结果：`RETURN` 的实参（无实参为 Nil）；块体执行完而没有 `RETURN`，结果为 Nil。
5. `MAP` 把非 Nil 的结果按顺序收集为一个 `[]any` 切片。`FILTER` 的每轮结果必须是 Bool 或 Nil（Nil 视为不选取），否则失败；结果与目标集同类型：切片得到相同成员类型的切片，Bytes 得到 Bytes，Dict 得到一个新 Dict（保持原插入顺序）。
6. 迭代结束后，私有数据栈与实参区丢弃。块体中的 `EXIT` 结束所在脚本域，`PASS(false)` 是所在脚本域的否决（7.2）。

### 12. 迭代与分支

**EACH。** 实参是切片（含 Bytes）或 Dict，否则失败。`EACH` 没有私有数据栈，块体直接使用所在脚本域的数据栈与实参区；每一轮新建局部域。

**循环变量**（`$X`）引用词法上最近的 `EACH`、`MAP` 或 `FILTER` 的当前迭代：

| 变量 | 值 |
| --- | --- |
| `$Value` | 当前成员的值（Dict 为当前键此刻的值） |
| `$Key` | 切片为 Int 下标（从 0 开始），Dict 为 String 键 |
| `$Object` | 目标集本身 |
| `$Size` | 迭代的轮数：切片的长度，或 Dict 的键快照的长度 |

**Dict 的迭代**（构想层 `7.流程控制.md`，DEC-0006 第 7 条）：进入迭代时取键的快照，按快照逐轮迭代；迭代中被删除的键，其轮次跳过块体（仍算一轮）；新增的键不进入本次迭代，但可以被块体读取。〔R-12〕`MAP`、`FILTER` 对 Dict 的迭代采用相同的快照规则。

**SWITCH。** 实参 1 是标的值，实参 2 是分支值切片。

1. 分支值切片的长度必须等于 `SWITCH` 块体内直接 `CASE` 的个数，否则失败。
2. 按顺序执行 `SWITCH` 块体中的指令。执行到第 i 个 `CASE` 时，按 `EQUAL` 的语义（SPEC-0004 第 5 条）比较标的值与第 i 个分支值：相等则执行该 `CASE` 的块体，执行完后整个 `SWITCH` 结束；不相等则跳过该块体继续。
3. 执行到 `DEFAULT` 时（此前没有 `CASE` 相等），执行其块体，然后 `SWITCH` 结束。
4. 比较在执行到该 `CASE` 时才进行。不可比较的值在比较时失败。

**BREAK 与 CONTINUE。** 实参可选：有实参时必须是 Bool，为 `true` 才生效，为 `false` 则什么都不做；无实参时直接生效。

- `BREAK` 的目标是词法上最近的 `EACH` 或 `SWITCH`：结束目标及其内部的全部块体，在目标之后继续。
- `CONTINUE` 的目标是词法上最近的 `EACH`：结束当前一轮，进入下一轮。位于 `CASE` 内时，同时结束该 `SWITCH`（DEC-0006 第 7 条）。

### 13. 校验域、系统占位符与 NULL 点

**校验域**（DEC-0006 第 12 条）是一组按序位记录的布尔值，属于验证级状态：

- 单签验证写序位 0；多签验证写序位 `0 … N-1`（N 为完整公钥哈希清单的长度，序位的排列由宿主定义）。后写的值覆盖先写的值。
- 写入者：顶层、`EMBED` 代码、`GOTO` 目标、`MAP` / `FILTER` 块体中的 `SYS_CHKPASS`（仅成功时）、`FN_CHECKSIG`、`FN_MCHECKSIG`。EVAL 环境中只读：`FN_CHECKSIG`、`FN_MCHECKSIG` 只返回结果。
- `SIGNED[n]` 读取的序位从未写入即失败。

**系统占位符**（DEC-0003 第 5 条）：执行到 `254(n)` 时，从宿主提供的见证条目中取第 n 项，按值指令处理（默认入栈，可被截取）。本次验证没有该条目即失败。字节码不改写。

**NULL 点**按字节位置确定，与执行路径无关（构想层 `13.环境指令.md`）：`SOURCE` 所用的「最近的 NULL 点」是该 `SOURCE` 之前、在字节顺序上最近的 `SYS_NULL`，不论它是否被执行。顶层的取码视图把解锁段与锁定段视为一段（`Design.md`「边界处理」）。`SOURCE` 的完整规则见 SPEC-0104。


## 边界与限制

- 核心 VM 只验证一个输入。交易与区块层面的成本累计、输入之间的并行，由宿主负责（SPEC-0008）。
- 本篇不定义各指令的类型要求与运算结果，只定义它们共同遵循的执行框架。
