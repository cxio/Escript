## 概述

本篇定义 opcode 128–220：环境取值、工具、系统指令与函数指令。由宿主定义的部分（环境字段、签名验证、公钥哈希与地址、`SYS_AWARD`）只写核心的处理，语义见 SPEC-0008 与宿主规格。私有专属指令（`SHELL`、`SYS_TIME`、`FN_PRIV`）与私有执行中的 `FN_PRINTF` 见 SPEC-0106。

第 1 条是正则的共同约定，`MATCH`、`REPLACE`、MODEL 的 `RE`（SPEC-0103）与 `MO_RE`（SPEC-0105）都按它执行。


## 规格正文

### 1. 正则的约定

#### 1.1 语法与匹配语义

- 语法为 RE2，即 Go `regexp/syntax` 接受的语法（含 `(?flags)`、命名组 `(?P<name>...)`）。不支持反向引用与环视。
- 匹配语义为**最左优先**（leftmost-first，与 Perl 相同）：在最左的起点上，按选择支与量词的优先次序取第一个成功的匹配，不是 POSIX 的最长匹配。
- 输入为 String 时按文本匹配，为 Bytes 时按字节匹配。两者使用同一个引擎：输入中的非法 UTF-8 字节按 U+FFFD 处理，宽度为 1 字节。位置都是字节偏移。
- 参考实现为 Go `regexp`（`regexp.Compile`，不使用 `CompilePOSIX`）。字符类所用的 Unicode 版本见〔P-01〕。

#### 1.2 全部匹配的算法

需要「全部匹配」时（`MATCH` 的 `g` / `G`、`REPLACE` 的正则形式、MODEL 的 `g` / `G`、`MO_RE` 的 `FindAll*`、`ReplaceAll*`），按以下算法从左到右查找，至多取 limit 个：

```
pos = 0; prevEnd = -1; count = 0
while count < limit and pos ≤ len(input):
    m = 从 pos 起最左优先的第一个匹配（^、\b 等断言按整个输入判断）
    if 没有 m: break
    accept = true
    if m.end == pos:                       // 空匹配
        if m.start == prevEnd: accept = false
        pos += pos 处符文的宽度（非法字节为 1；已在末尾则为 len(input) + 1）
    else:
        pos = m.end
    prevEnd = m.end
    if accept: 收入 m; count += 1
```

这与 Go `Regexp.allMatches` 相同。例：`/a*/` 在 `"baaac"` 中依次得到 `[0,0)`、`[1,4)`、`[5,5)`。

### 2. 环境指令 `[128-137]`

#### 2.1 `ENV`、`IN`、`OUT`、`INOUT`（128–131）

| 指令 | 取值 |
| --- | --- |
| `ENV[i]` | i 为 0–31 时是核心字段，由核心按 SPEC-0008 第 3 条计算；i 为 32–255 时是宿主字段 |
| `IN[i]` | 当前输入的宿主字段 |
| `OUT[n, i]` | 当前交易第 n 个输出的宿主字段 |
| `INOUT[n, i]` | 当前输入的来源交易第 n 个输出的宿主字段 |

- 字段表、值的类型、是否属于源码类、取不到时得 Nil 还是数据不可用，由宿主规格定义（SPEC-0008 第 4 条，Evidcoin 见 SPEC-0901〔P-08〕）。未分配的字段索引在加载期即失败。
- `OUT`、`INOUT` 的 n 不小于对应输出集的大小，即失败（按位置）。
- 读取到宿主标注为「与高度相关」的字段时，设置执行标记（SPEC-0008 第 6 条）。
- 成本：`K`，`D` 为字段值中变长内容的字节数。

#### 2.2 `XFROM`（133）

- 取「源交易」的宿主字段（SPEC-0008 第 4 条第 5 项）。
- 只能在 `GOTO` 或 `EMBED` 的目标中执行：`ENV{InGoto}` 与 `ENV{InEmbed}` 都为 false 时即失败。这是运行时检查（SPEC-0003 第 9 条）。
- 在 EVAL 代码中，按发起 `EVAL` 之处判断，与 SPEC-0008 第 3 条中 `InGoto`、`InEmbed` 在 EVAL 中的取值一致〔R-31〕。
- 成本：同 2.1。

#### 2.3 `SIGNED[n]`（134）

- 读取校验域的序位 n（SPEC-0005 第 13 条），返回 Bool。
- 序位 n 从未写入即失败。在 `GOTO` 目标与 EVAL 代码中也可以读取。
- 成本：`K`。

#### 2.4 `VAR[n]`、`SETVAR[n]`（135、136）

- `VAR[n]` 返回当前脚本域全局变量区位置 n 的值（初值 Nil）；`SETVAR[n]` 把实参写入该位置，覆盖原值。
- 全局变量区属于脚本域：`EMBED` 的代码与 `MAP` / `FILTER` 的块体使用所在脚本域的全局变量区；`GOTO` 目标与 EVAL 环境各有自己的全局变量区（SPEC-0005 第 3.2 条）。
- 成本：`K`。

#### 2.5 `SOURCE[f]`（137）〔R-30〕

返回字节码的一个片段，Bytes。

**取码范围**：块内标识（`0x00`～`0x04`）在 `SOURCE` 所在的**段**内取码，跨块标识（`0x80`～`0x84`）在**脚本**内取码：

| `SOURCE` 的位置 | 段 | 脚本 |
| --- | --- | --- |
| 顶层 | 锁定段 L | 解锁段与锁定段首尾相接的字节序列 U‖L |
| `GOTO` / `EMBED` 目标、EVAL 代码 | 该段自身 | 该段自身（构想层：「外部脚本中的 SOURCE 指令只针对其脚本自身」） |

- 解锁段只能使用 SPEC-0002 第 7 条列出的码值，不含 `SOURCE`，所以顶层的 `SOURCE` 总在锁定段中。解锁段中可以有 `SYS_NULL`。
- 因此在顶层，只有 `0x80`、`0x81`、`0x82` 的结果可能含解锁段：`0x00`～`0x04` 的结果不超出锁定段；`0x84` 的结果在 `SOURCE` 之后，也不含解锁段（构想层：「解锁段 => 锁定段也属于『跨块』逻辑」）。
- 以下位置都是脚本中的字节偏移。顶层的锁定段从位置 len(U) 开始。

**当前块**：包含该 `SOURCE` 的最内层代码块的块体（`IF`、`ELSE`、`SWITCH`、`CASE`、`DEFAULT`、`EACH`、`BLOCK`、`MAP`、`FILTER`）；不在任何块体内时为整个段，顶层即锁定段。bs、be 为当前块的起止位置，se 为该 `SOURCE` 指令之后的位置，end 为脚本的长度。

| f | 区间 | 说明 |
| --- | --- | --- |
| `0x00` | [bs, be) | 当前块的完整代码 |
| `0x01` | [bs, se) | 当前块的前阶，含 `SOURCE` 本身 |
| `0x02` | [n, se) | 同上，从当前块最近的 NULL 点开始 |
| `0x04` | [se, be) | 当前块的后阶 |
| `0x80` | [0, end) | 完整的脚本，顶层含解锁段 |
| `0x81` | [0, se) | 脚本的前阶，顶层含解锁段 |
| `0x82` | [n, se) | 同上，从脚本中最近的 NULL 点开始 |
| `0x84` | [se, end) | 脚本的后阶 |

- **NULL 点**按字节位置确定，与执行路径无关（SPEC-0005 第 13 条）。
  - `0x02`：n 是位于 [bs, se) 之内、作为当前块**直接成员**的最后一条 `SYS_NULL` 之后的位置；没有这样的 `SYS_NULL` 时 n = bs。顶层时只看锁定段，解锁段中的 `SYS_NULL` 不参与。
  - `0x82`：n 是位于 [0, se) 之内、**任意嵌套层级**的最后一条 `SYS_NULL` 之后的位置，顶层包括解锁段中的 `SYS_NULL`；没有时 n = 0。因此结果可能从某个块的中间开始（构想层：「块被解剖」），也可能从解锁段的中间开始。
- 只排除作为起点的那条 `SYS_NULL`（构想层：「取码时分界点 NULL 都不包含」）。区间之内的其它 `SYS_NULL` 照常包含在结果中，例如 `<Source.1>` 处的 `SOURCE[1]` 为「SIGNED ~ <Source.1>」，含 NULL.2。
- 后阶（`0x04`、`0x84`）总是取到当前块或脚本的末尾，没有以 NULL 点为终点的取码（构想层「设计」）。
- 结果属于源码类（上限 16KB，SPEC-0006 第 1 条）。
- 成本：`K`，`D` 为结果字节数。

### 3. 工具指令 `[138-163]`

#### 3.1 `EVAL`（138）

- 按 SPEC-0005 第 11.3 条执行。实参必须是 Script。
- 返回 EVAL 数据栈的剩余项，按自底向上的顺序组成的 `[]any`。
- 成本：`K + m + 10`，m 为返回切片的成员数；另计代码的加载期成本（SPEC-0003 第 8 条）；代码中各指令的成本照常计入。

#### 3.2 `COPY`（139）

- 实参：Dict。返回实参本身与一个新 Dict：新 Dict 的条目与顺序与原 Dict 相同，值是同一引用（浅复制）。
- 由于字典约束，值不含 Dict，浅复制后两者互不影响。
- 成本：`K + m`，m 为条目数。

#### 3.3 `KEYVAL[k]`（140）

- 实参：Dict。按插入顺序：
  - k = 0：先返回键的 `[]String`，再返回值的 `[]any`，两者按位置一一对应。
  - k = 1：只返回键的 `[]String`。
  - k = 2：只返回值的 `[]any`。
- 空 Dict 得到空切片。
- 成本：`K + m`，m 为产生的成员数。

#### 3.4 `MATCH[f]`（141）

- 实参 1：String 或 Bytes。实参 2：RegExp。
- 按 f 查找（第 1 条）。结果中的文本与实参 1 同类型（String 或 Bytes）〔R-31〕：

| f | 结果 | 没有匹配时 |
| --- | --- | --- |
| `0x00` | Bool：是否存在匹配 | false |
| `f` | 首个匹配的文本 | Nil |
| `S` | `[]any`：首个匹配的全文，随后依次为各捕获组；未参与匹配的组为 Nil | Nil |
| `g` | 全部匹配的全文：`[]String` 或 `[]Bytes` | 空切片 |
| `G` | `[]any`，每个成员是一个形如 `S` 的 `[]any` | 空的 `[]any` |

- `g`、`G` 的匹配超过 1024 个即失败（集合成员数，SPEC-0006 第 1 条）。实现可以在找到第 1025 个匹配时停止并失败。
- 「没有匹配」不是失败。
- 成本：`K + m + ⌈s × re / 8⌉`，s 为实参 1 的字节数，re 为正则源文本的字节数。

#### 3.5 `SUBSTR[n]`（142）

- 实参 1：String。实参 2：起始位置 p（整数类），按符文计，从 0 开始。附参 n：符文数，0 表示之后的全部。
- 先按 SPEC-0102 第 2.6 条解码实参 1，**丢弃**非法字节〔R-25〕，得到 N 个符文。
- p < 0 即失败〔R-31〕；p ≥ N 时结果为 `""`；否则取第 p 个符文起的 n 个（n = 0 或不足 n 个时取到末尾），编码为 String（宽松：长度不足时返回已截取的部分）。
- 因此 `{0} SUBSTR` 可以用来滤除非法字节（构想层）。
- 成本：`K + B(实参 1 的字节数)`，`D` 为结果字节数。

#### 3.6 `REPLACE[n]`（143）

- 实参 1：String，目标。实参 2：String（子串形式）或 RegExp（正则形式）。实参 3：String，替换串。附参 n：替换次数，0 表示全部。
- **子串形式**：实参 2 不能为空串，否则失败〔R-31〕。从左到右查找不重叠的出现，替换前 n 个（或全部）为实参 3 的原文。
- **正则形式**：按第 1.2 条查找匹配，替换前 n 个（或全部）。实参 3 是模板，按以下规则展开（同 Go `Regexp.Expand`）：
  - `$$` 为一个 `$`。
  - `$name` 与 `${name}`：name 是由字母、数字、下划线组成的最长序列（字母与数字的判断按 Unicode，〔P-01〕）。name 全为十进制数字且没有前导零时为组号，否则为组名。组不存在或未参与匹配时，替换为空串。
  - `$` 之后不能构成 name（包括 `${` 没有闭合）时，`$` 按原文保留。
  - 注意 `$1x` 中的 name 是 `1x`（组名，通常不存在，得空串）；需要组 1 之后紧跟 `x` 时写 `${1}x`。
- 结果是新的 String。没有任何替换时，结果与实参 1 相同。
- 成本：`K + B(实参 1 的字节数)`，`D` 为结果字节数；正则形式另加 `⌈s × re / 8⌉`。

#### 3.7 `RANDOM`、`SLRAND`（144、145）

伪随机流（构想层）：

```
stream(seed, tag) = BLAKE3 的 keyed 模式，key = seed，输入 = tag 的 ASCII 字节，从偏移 0 起读取 XOF 输出
next64()          = 从流中读取下 8 字节，按大端序解释为 uint64
uniform(n), n ≥ 1 = r = (2⁶⁴ − n) mod n；循环 x = next64()，直到 x ≥ r；返回 x mod n
```

- 种子（实参 1）必须是恰好 32 字节的 Bytes，否则失败。每条指令重新建立流，因此相同的种子与实参得到相同的结果。
- **`RANDOM`**：tag 为 `"Escript/RANDOM/v1"`。实参 2 为上界，结果的类型与它相同（构想层）：
  - Int：上界 ≥ 1，否则失败；返回 Int，即 uniform(上界)。
  - Float（私有）：上界必须是正的有限数，否则失败；返回 Float，即 (next64() >> 11) / 2⁵³ × 上界。
  - 其它类型即失败，包括 Byte、Rune（上界不属于 SPEC-0101 第 1.2 条的整数类实参）。
- **`SLRAND`**：tag 为 `"Escript/SLRAND/v1"`。实参 2 为切片或 Bytes（DEC-0005 第 1 条，Bytes 按字节重排）。复制为 t，i 从 len(t) − 1 递减到 1：j = uniform(i + 1)，交换 t[i] 与 t[j]（Fisher–Yates）。全部抽取来自同一个流。返回 t，与实参 2 同类型，切片的成员类型不变。
- 成本：`RANDOM` 为 `K + 20`；`SLRAND` 为 `K + 20 + m`，m 为成员数（Bytes：`D` 为字节数）。

#### 3.8 `CMPFLO[k]`（146）

- 实参 1、2：待比较的值。实参 3：误差 eps。三者都必须是 Float〔R-31〕，因此只在私有执行中有用。
- k = 0：|a − b| ≤ eps；k = −1：a < b 或 |a − b| ≤ eps；k = 1：a > b 或 |a − b| ≤ eps。
- 任一实参是 NaN 时结果为 false。
- 成本：`K`。

#### 3.9 `CALL[n]`（147）

1. 按 SPEC-0005 第 4 条取得实参（记号 `-2`）。实参 1 为目标，实参 2 为方法名，其余为方法的实参。
2. 只有 1 个实参，或实参 2 为 `""`：什么都不做，不返回值，实参照常消费〔R-31〕。实参 2 不是 String 即失败。
3. 按目标的类型确定方法集（SPEC-0105 第 1 条）：Time 为 `MO_TIME`，RegExp 为 `MO_RE`，BigInt 为 `MO_BINT`，模块对象为构造它的模块，Dict 为字典方法（SPEC-0105 第 7 条）。其它类型即失败。
4. 在 **`CALL` 所在段的版本**的方法集中按名称查找（区分大小写）。找不到即失败。
5. 传参：目标是 Time、RegExp、BigInt 时，目标作为方法的实参 1，其后依次为 `CALL` 的实参 3、4……；目标是模块对象或 Dict 时，目标不作为方法的实参，方法的实参从 `CALL` 的实参 3 开始。
6. 方法的实参个数与类型按方法表检查，不符即失败。私有方法（方法表标记 P）在公共执行中即失败。
7. 返回：方法没有返回值时不返回；有一个返回值时返回它；有多个返回值时封装为一个 `[]any` 返回（构想层）。

成本：第 2 步的空操作为 `K`；其余为方法表所列的成本，其中 a 计入 `CALL` 取得的全部实参（含目标与方法名）。

#### 3.10 `RANGE[n]`（152）

- 实参 1：起始值。实参 2：步进值。两者是整数类或 Float（私有）。
- 两者都是整数类：结果为 `[]Int`，v₀ = 起始值，vᵢ₊₁ = vᵢ + 步进值，共 n 个；n − 1 次加法中溢出即失败。
- 任一为 Float（私有）：结果为 `[]Float`，vᵢ = 起始值 + i × 步进值，i 转为 Float。
- n = 0 时结果为空切片，实参只用于确定类型。BigInt 与其它类型即失败。
- 成本：`K + m`，m = n。

#### 3.11 `MAP`、`FILTER`（153、154）

- 按 SPEC-0005 第 11.4 条执行。块体是函数域：有自己的数据栈与实参区，全局变量区与通关状态属于所在脚本域（构想层 `13.环境指令.md` 的「函数域」）。
- 成本：`K + 5` + 每轮 2（块体的成本另计），每轮的成本在该轮开始时计入。

#### 3.12 `SHELL`（155）

私有专属，见 SPEC-0106 第 5 条。公共执行中执行到即失败。

### 5. 函数指令 `[170-220]`

#### 5.1 `FN_BASE58`（170）

- 实参为 Bytes 时编码，返回 String；为 String 时解码，返回 Bytes〔R-32〕。
- 字母表：`123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`（第 i 个字符表示数值 i）。
- 编码：每个前导 `0x00` 字节输出一个 `1`；其余字节作为大端无符号整数，按 58 进制输出，最高位在前，没有前导的 `1`。空 Bytes 得到 `""`。
- 解码：每个前导 `1` 得到一个 `0x00`；其余字符按 58 进制解释为整数，输出其最少字节的大端表示。含字母表以外的字符即失败。`""` 得到空 Bytes。
- 不含校验和（不是 Base58Check）。编码与解码互为逆运算，每个 Bytes 恰有一个编码。
- 输入超过 256 字节即失败。
- 成本：`K + ⌈L² / 128⌉`，L 为输入字节数。

#### 5.2 `FN_BASE32`（171）

- 编码与解码的方向同 5.1〔R-32〕。
- 字母表：RFC 4648 第 6 节，`A–Z`、`2–7`。编码不输出填充字符 `=`。
- 解码只接受规范形式，否则失败：
  - 只含上述 32 个大写字符，不含 `=`、小写字母与空白；
  - 长度除以 8 的余数是 0、2、4、5、7 之一；
  - 最后一个字符中未用的低位为 0。
- 因此解码与编码互为逆运算。
- 成本：`K + B(输入字节)`，`D` 为结果字节数。

#### 5.3 `FN_BASE64`（172）

- 编码与解码的方向同 5.1〔R-32〕。
- 字母表：RFC 4648 第 5 节（URL 安全），`A–Z`、`a–z`、`0–9`、`-`、`_`。编码不输出填充字符。
- 解码只接受规范形式，否则失败：
  - 只含上述 64 个字符；`+`、`/`、`=`、空白即失败；
  - 长度除以 4 的余数不是 1；
  - 最后一个字符中未用的低位为 0。
- 成本：同 5.2。

#### 5.4 宿主定义的函数（173–177）

| 码值 | 指令 | 核心的处理 |
| --- | --- | --- |
| 173 | `FN_ADDRESS` | 宿主函数（SPEC-0008 第 5.3 条） |
| 174 | `FN_PUBHASH` | 宿主函数 |
| 175 | `FN_MPUBHASH` | 宿主函数 |
| 176 | `FN_CHECKSIG` | 宿主验证签名（SPEC-0008 第 5.2 条），返回 Bool；除 EVAL 环境外，按宿主给出的序位写入校验域。验证不成功不是失败 |
| 177 | `FN_MCHECKSIG` | 同上，多重签名 |

- 实参的类型与个数、算法、失败条件、成本由宿主规格给出〔P-03〕。构想层给出的 Evidcoin 算法（`FN_PUBHASH` 为 `SHA3-256(BLAKE2b-512(pubKey))` 等、`FN_ADDRESS` 的 Bech32v）属于 SPEC-0901。
- 宿主没有实现其中某条时，它对该宿主是未分配码位，含它的段加载失败（SPEC-0007 第 3 条）。

#### 5.5 `FN_HASH224`、`FN_HASH256`、`FN_HASH384`、`FN_HASH512`（178–181）

- 实参：Bytes，或 Script（取其字节码，不含版本）〔R-26〕。其它类型即失败。
- 输出 N 字节，N 为 28、32、48、64：

| 附参 | 算法 |
| --- | --- |
| 0 | BLAKE3（默认哈希模式），取 XOF 输出的前 N 字节 |
| 1 | BLAKE2b，摘要长度参数为 N（RFC 7693），不是 BLAKE2b-512 的截断 |
| 2 | SHA-2：SHA-224、SHA-256、SHA-384、SHA-512（FIPS 180-4） |
| 3 | SHA-3：SHA3-224、SHA3-256、SHA3-384、SHA3-512（FIPS 202） |

- 成本：`K + 20 + B(输入字节) × k`（SPEC-0006 第 3 条），`D` = N。

## 边界与限制

- 环境字段、签名、地址与 `SYS_AWARD` 的语义属于宿主（SPEC-0008、SPEC-0901）。
- 正则引擎的 Unicode 版本〔P-01〕会影响 `\p{...}`、`(?i)` 等的结果，须随版本冻结。
- 156–163（保留区）、148–151、132、167、168、182–216 在 v1 中未分配（SPEC-0002 第 6 条）。

## 对 Plan 的约束

- 正则统一由一个模块包装 Go `regexp`：编译（RE2，leftmost-first）、单次查找、第 1.2 条的全部匹配、模板展开。`MATCH`、`REPLACE`、MODEL、`MO_RE` 都调用这个模块，不各自调用 `regexp`。
- `REPLACE` 的结果、`MATCH` 的结果个数在构造过程中逐步检查限额，不得先构造出超限的结果再检查。
- `SOURCE` 的测试向量至少覆盖构想层示例的全部 15 个取值（按第 2.5 条的勘误），以及位于 `GOTO` 目标、EVAL 代码、`CASE` 块体中的情形；另有解锁段含 `SYS_NULL`、锁定段中 `SOURCE` 之前没有 `SYS_NULL` 的情形，其中 `0x02` 从锁定段的起点开始，`0x82` 从解锁段中的 NULL 点开始。
- Base58 / Base32 / Base64 的测试向量包括：空输入、前导零、非规范编码（末位非零、错误长度、填充字符、小写）各自失败。
- `RANDOM`、`SLRAND` 的向量给出固定种子下的前若干个输出，供其它实现比对。
