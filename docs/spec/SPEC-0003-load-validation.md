## 概述

每一段字节码在执行之前，都要完整解码一遍并做结构校验，这一步称为**加载期**。加载期的结论只有两种：成功或失败。它只取决于字节码本身、段的种类与版本，与执行路径无关。

本篇定义：哪些段在何时加载，加载的步骤，以及全部规范解码规则与结构规则。


## 规格正文

### 1. 段与加载时点

| 段的种类 | 加载时点 |
| --- | --- |
| 解锁段 | 执行之前 |
| 锁定段 | 执行之前，解锁段之后 |
| `GOTO` 目标 | 执行到该 `GOTO` 时 |
| `EMBED` 目标 | 执行到该 `EMBED` 时 |
| `EVAL` 代码 | 执行 `EVAL` 时，在执行该代码之前 |

- 宿主可以提前预取 `GOTO`、`EMBED` 的目标，但加载期校验必须在上表的时点进行：没有执行到的 `GOTO`、`EMBED` 不加载其目标，其目标即使无效也不影响结果。
- 每段的版本：解锁段取锁定段的版本；`GOTO`、`EMBED` 目标取其所在输出的版本；`EVAL` 代码取 Script 值携带的版本（SPEC-0007 第 2 条）。

### 2. 加载的步骤

#### 2.1 一次验证开始时

1. 确认锁定段的版本。本节点不认识该版本即失败（SPEC-0007 第 5 条）。
2. 加载解锁段。
3. 加载锁定段。
4. 两段都加载成功，才开始执行（SPEC-0005）。

#### 2.2 运行中加载的段

- `GOTO` / `EMBED` 目标的版本是本节点不认识的版本：失败。
- `EVAL` 代码的版本未知，或高于发起 `EVAL` 的段的版本：失败（SPEC-0007 第 5 条）。
- 之后按 2.3 加载该段。

#### 2.3 单段的加载

以下任一情形使该段加载失败，验证失败：

- 违反第 3 条的任一规范解码规则；
- 违反第 4、5、6、7 条的任一规则；
- 含有当前版本未分配的码值，或附参取值不在当前版本的取值范围或取值表内（SPEC-0002 第 5 条）；
- 加载期成本超出预算（第 8 条）。

没有上述情形，该段加载成功。

所有情形的结论相同，因此一段之内先发现哪个错误不影响结果，实现可以在发现第一个错误时停止。遇到未分配的码值时，必须停止解码，因为无法得知该指令的长度。

### 3. 规范解码规则

违反以下任一条，即为无效编码：

1. **变长整数**为最短编码（SPEC-0002 第 2.1 条）。长度类的值不得超过所在范围剩余的字节数。
2. **大整数（opcode 6）**：长度 L ≥ 1；绝对值没有前导零字节；值超出 int64 范围，即正数大于 2⁶³−1、负数的绝对值大于 2⁶³。
3. **Rune（opcode 4）**：不超过 `0x10FFFF`，且不在 `0xD800–0xDFFF`。
4. **浮点数（opcode 7）**及 opcode 124 的三个附参：不是 NaN 或 ±Inf。`-0` 允许。
5. **值集（opcode 9）**：
   - 至少 1 个成员；
   - 成员只能是 opcode 1–8 的值指令，每个成员本身满足本条各项；
   - 成员属于同一类别：全部为 Bool（opcode 1、2）；全部为 String（opcode 8）；或全部为数值（opcode 3–7）；
   - 数值成员中不得同时出现大整数（6）与浮点数（7）。
6. **块长度**：块体的末端必须恰好落在一条指令的末尾，且块体完整位于父范围之内。
7. **MODEL 的标记**：附参的 bit15 为 1，当且仅当其模式体内（不进入嵌套 `MODEL` 的模式体）至少有一条取值指令（`#`、`$[n]`）。
8. **正则**（opcode 11 的数据，opcode 125 的正则数据）按 RE2 语法编译，编译失败即为无效编码。参考实现使用 Go `regexp.Compile`。
9. **附参取值**在 SPEC-0002 格式表所列的范围或取值表之内。
10. **外部脚本引用**（`HostRef`）按宿主声明的字段序列解码成功，并满足宿主声明的字段约束。
11. **段的末尾**：最后一条指令完整结束于段的末字节。

两种写法属于不同指令或不同类型时，不是非规范编码（DEC-0003）：`.` 与 `.[1]`；Byte `'A'`（opcode 3）与 Rune `'\u0041'`（opcode 4）。

### 4. 结构规则

除第 6 条（模式体）另有规定外，以下规则适用于全部段。

| 规则 | 内容 |
| --- | --- |
| IF / ELSE | 同一块层级内，`ELSE` 之前最近的一条 `IF` 或 `ELSE` 必须是 `IF` |
| CASE / DEFAULT | 只能直接位于 `SWITCH` 的块体内（不能隔着其它块） |
| DEFAULT | 同一 `SWITCH` 块体内至多一个，且其后不得再有 `CASE` |
| 模式指令 | opcode 117–127 只能位于模式体内 |
| RETURN | 位于某个 `MAP` / `FILTER` 的块体内（可以隔着其它块） |
| BREAK | 向外查找，在遇到 `MAP` / `FILTER` 的块体或段顶层之前，必须遇到 `EACH`、`CASE` 或 `DEFAULT` 的块体 |
| CONTINUE | 同上，但必须遇到的是 `EACH` 的块体 |
| 循环变量 | `$X`（opcode 22）位于某个 `EACH`、`MAP` 或 `FILTER` 的块体内（可以隔着其它块） |
| 运算符号 | opcode 81–85 只能直接位于表达式体内，且符合第 5 条的文法 |
| 前缀序列 | 形式为「至多一个 `@` / `&` / `_`，其后至多一个 `~`，再接一条非前缀的目标指令」，目标与前缀位于同一块体内；前缀不得悬空在块体末尾 |
| 截取前缀的目标 | `@`、`&`、`_` 的目标必须有返回值（格式表中不是 `—`） |
| `~` 的目标 | 目标的实参为固定的 n（n ≥ 1），或是附参不为 0 的 `CALL` |
| 表达式内的前缀 | 表达式体内只允许 `~`，不允许 `@`、`&`、`_` |
| 表达式的操作数 | 操作数指令的返回值个数必须是 1 或 `*` |
| 嵌套深度 | 段顶层的深度为 0，块体的深度为其块指令的深度加 1，块体深度不得超过 16（DEC-0007） |
| 码值 255 | 任何位置都无效（包括模式体） |
| 系统占位符 | 只能出现在解锁段（或任何段的模式体内） |

补充：

- 「格式表中按方法 / 按条目」的指令（`MO_*`、`EXT_MO`、`FN_X`、`FN_XX`），截取前缀、`~` 与表达式操作数的规则按其方法或条目的实参与返回值个数判断。
- 私有专属且实参与返回值由私有配置决定的指令（`FN_PRIV`、`EXT_PRIV`），在加载期视为「实参为固定 n、返回值为 `*`」。这样公共节点的加载结论不依赖任何私有配置。
- 「位于某块体内」按段内的词法嵌套判断，不跨越段：`EVAL` 代码中的 `RETURN` 不会因为 `EVAL` 本身位于 `MAP` 内而合法。

### 5. 表达式文法

表达式 `()`（opcode 80）的块体按以下文法解析，块体必须恰好是一个 `expr`：

```
expr     = term { ("+" | "-") term }
term     = unary { ("*" | "/" | "%") unary }
unary    = ("+" | "-") unary | operand
operand  = ["~"] 指令
```

- `+` `-` `*` `/` `%` 指 opcode 84、85、81、82、83。一元的 `+`、`-` 出现在表达式开头、运算符之后（DEC-0006 第 10 条），优先级最高；子表达式开头即嵌套 `()` 的块体开头。
- `指令`是除运算符号与前缀以外的任一条指令（含嵌套的 `()`），并满足第 4 条「表达式的操作数」。
- 空表达式、两个操作数之间缺少运算符、运算符之后缺少操作数，都是结构错误。

### 6. 模式体

`MODEL`（opcode 116）与 `?{}`（opcode 119）的块体是模式体。模式体内的普通指令是模式，描述目标脚本的片段，可以是不完整的结构（DEC-0003）。

在模式体内：

- **不适用**第 4 条中关于位置的规则：IF / ELSE、CASE / DEFAULT、RETURN、BREAK、CONTINUE、循环变量、运算符号、前缀序列及其目标、表达式内的前缀与操作数、系统占位符的位置，以及第 7 条的段级禁用指令。
- **照常适用**：第 3 条全部规范解码规则；块长度；嵌套深度；码值 255；未分配的码值与附参取值（包括系统占位符的见证条目）。
- 另需满足 SPEC-0103 对各模式指令的约束（例如 `^?`、`#` 必须跟随一条目标指令）。

表达式体出现在模式体内时，也是模式：不按第 5 条的文法检查。

### 7. 段级规则

| 段 | 规则 |
| --- | --- |
| 解锁段 | 长度小于 8192 字节（`Design.md`「参数限定」），在扫描之前检查 |
| 解锁段 | 只能使用 SPEC-0002 第 7 条列出的码值；`GVAL` 的字段、系统占位符的见证条目必须已分配 |
| `EMBED` 目标 | 不得包含 `EMBED`、`GOTO`（嵌入深度为 0） |
| `EVAL` 代码 | 不得包含 `EVAL`、`GOTO`、`EMBED`、`SYS_CHKPASS`（DEC-0006 第 5 条） |
| 除解锁段外 | 不得包含系统占位符（模式体除外） |

锁定段、`GOTO` / `EMBED` 目标在花费时不检查长度：它们已经上链，长度在创建输出时由宿主检查（`Design.md`「参数限定」的注意）。

### 8. 加载期的成本

按 DEC-0007 第 2、3 条，加载期的成本计入当前输入的成本预算（SPEC-0006）：

1. 扫描一段之前，先计该段的结构扫描成本 ⌈段字节数 / 64⌉。
2. 扫描到正则（opcode 11、125）时，计编译成本 10 + 正则字节数。
3. 计费后累计成本超过预算即失败。

正则的编译成本在加载期计入，即使所在分支不会执行（DEC-0003 影响）。加载成功时，一段的加载期成本是确定的：第 1 项加上该段全部正则的第 2 项。

### 9. 加载期不检查的内容

以下内容依赖运行时的值或执行路径，属于运行时检查（DEC-0003）：实参个数与类型、越界与溢出、私有专属指令「执行到即失败」、`SWITCH` 分支值的个数与 `CASE` 的个数是否一致、`XFROM` 是否位于 `GOTO` / `EMBED` 目标中、`CALL` 的方法名是否在方法集中、限额与成本（第 8 条除外）。

`MODEL` 的目标是运行时数据，不经过加载期。目标无法按规范解码时（包括含有 MODEL 所在段的版本未分配的码值），MODEL 返回「不匹配」，不使脚本失败（DEC-0003 第 1 条，细节见 SPEC-0103）。

`CODE` 的数据在加载期不解码，作为 `EVAL` 代码执行时才加载。


## 边界与限制

- 加载期的结论只取决于：段的字节、段的种类、段的版本、宿主的引用字段声明与见证条目表。同样的输入在所有节点上得出同样的结论。
- 本篇不规定实现必须在加载期构建何种内存结构（DEC-0003 第 6 条）。

## 对 Plan 的约束

- 加载器返回成功或失败；失败时应附带首个被发现的错误的种类与位置，供诊断。诊断信息不属于共识，测试向量只断言结论。
- 第 3、4、6、7 条的每一行都要有失败向量；未分配的码值、未分配的附参取值，在解锁段、锁定段、`GOTO` / `EMBED` 目标、`EVAL` 代码、模式体与不会执行到的分支中各要有向量。
- 解码器与加载器共用 SPEC-0002 的格式表。
