## 概述

Escript 是一种栈脚本语言，用于区块链交易的锁定与解锁。本规格集定义它的**核心 VM**（与宿主无关的执行引擎）和**宿主接口**，并以 Evidcoin 作为第一个宿主规格。

本篇是规格集的入口：说明文档结构、通用约定、外部标准引用，以及全局待决集。


## 规格正文

### 1. 权威

规格文档加测试向量是权威，Go 实现是参考实现（DEC-0001）。参考实现与规格不一致时，修正实现；需要改变语义时，先修订 Decision 或 Spec。

上下级关系：Conception + Decision > Spec > Plan > 实现。Spec 与上级冲突时以上级为准，并且必须向作者反馈。

### 3. 规范用语

| 用语 | 含义 |
| --- | --- |
| 必须 / 不得 | 共识规则。违反即结果不同，不同实现之间会分叉 |
| 应 / 不应 | 强烈建议，不影响共识（例如转发策略） |
| 可以 | 允许的实现选择，不影响结果 |
| 失败 | 本次验证的结果为「失败」（SPEC-0005 第 9 条） |
| 不可用 | 本次验证的结果为「数据不可用」（SPEC-0008） |
| 结构错误 | 加载期发现的错误，结果为失败（SPEC-0003） |

### 4. 记法

- 码值用十进制书写，如 `opcode 58`；字节用十六进制书写，如 `0x3A`。
- 附参的编码类型见 SPEC-0002 第 2 条：`u8`、`i8`、`u16be`、`u32be`、`f32be`、`f64be`、`uvarint`、`varint`、`bytes(N)`、`HostRef`。
- 「实参个数」沿用构想层的记号：`0`、`n`（固定数量）、`-1`（不定数量）、`-2`（由附参给出，仅 `CALL`）。
- 成本公式的记号（`K`、`B(x)`、`a`、`r`、`D`、`m`）见 SPEC-0006 第 2.1 条〔R-21〕。
- 文本中的指令写法（如 `DATA{...}`、`@POPS[3]`）只用于说明，其文法由 SPEC-0201 定义。
- 正文中的 `〔R-NN〕` 表示该条是评审者补充的细则，`〔P-NN〕` 表示该条依赖一个待决问题，见第 6 条。

### 7. 核心与宿主的术语

| 术语 | 含义 |
| --- | --- |
| 段 | 一份单独加载的字节码：解锁脚本、锁定脚本、`GOTO` 目标、`EMBED` 目标、`EVAL` 代码 |
| 函数域 | 由 `MAP`、`FILTER` 构造的私有函数块域，有自己的数据栈和实参区，但共享上层全局变量区 |
| 脚本域 | 拥有自己的数据栈、实参区、全局变量区与通关状态的执行单位（SPEC-0005） |
| 校验域 | 一次输入验证中由 `GOTO` 链共享的验证记录（`SIGNED`） |
| 宿主 | 使用核心 VM 的系统，例如 Evidcoin 节点 |
| 宿主规格 | 一份文档，给出某个宿主的字段表、算法与参数（SPEC-0008 列出它必须包含的内容） |
| 公共验证 / 私有执行 | 共识验证节点上的执行 / 私有节点上的执行（SPEC-0005 第 10 条） |


## 边界与限制

- 本规格集不定义交易结构、区块结构、手续费与转发策略（转发策略只给出建议，标为「应」）。
- 本规格集不定义宿主的前置检查（例如 Evidcoin 中币金与凭信的区别对待），它们在脚本执行之前完成。

- Plan 在第 6.1 条的问题决定之前，不得在代码中写死相应取值；需要占位时，使用显式的配置项或 `TODO(P-NN)` 标注。
- Plan 必须包含测试向量的导出（SPEC-0202）、Unicode 版本断言（P-01）与 Go toolchain 固定（DEC-0001 第 6 条）。
