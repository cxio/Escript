## 概述

Escript 是一种栈脚本语言，用于区块链交易的锁定与解锁。本规格集定义它的**核心 VM**（与宿主无关的执行引擎）和**宿主接口**，并以 Evidcoin 作为第一个宿主规格。

本篇是规格集的入口：说明文档结构、通用约定、外部标准引用，以及全局待决集。


## 规格正文

### 1. 权威

规格文档加测试向量是权威，Go 实现是参考实现（DEC-0001）。参考实现与规格不一致时，修正实现；需要改变语义时，先修订 Decision 或 Spec。

上下级关系：Conception + Decision > Spec > Plan > 实现。Spec 与上级冲突时以上级为准，并且必须向作者反馈。

### 2. 规格集的组成

| 类别 | 编号 | 内容 |
| --- | --- | --- |
| 基础 | 0001–0008 | 总览、字节码格式、加载期校验、值模型、执行模型、限额与成本、版本与升级、宿主接口 |
| 指令语义 | 0101–0106 | 逐条指令的语义、异常与成本（含 MODEL、v1 方法表） |

**核心规格**（0001–0202）不得依赖任何宿主的具体类型或取值；凡是由宿主定义的内容，核心规格只写接口契约，并注明「由宿主规格定义」。

### 3. 规范用语

| 用语 | 含义 |
| --- | --- |
| 必须 / 不得 | 共识规则。违反即结果不同，不同实现之间会分叉 |
| 应 / 不应 | 强烈建议，不影响共识（例如转发策略） |
| 可以 | 允许的实现选择，不影响结果 |
| 失败 | 本次验证的结果为「失败」（SPEC-0005 第 9 条） |
| 不可用 | 本次验证的结果为「数据不可用」（SPEC-0008） |
| 结构错误 | 加载期发现的错误，结果为失败（SPEC-0003） |

### 4. 记法

- 码值用十进制书写，如 `opcode 58`；字节用十六进制书写，如 `0x3A`。
- 附参的编码类型见 SPEC-0002 第 2 条：`u8`、`i8`、`u16be`、`u32be`、`f32be`、`f64be`、`uvarint`、`varint`、`bytes(N)`、`HostRef`。
- 「实参个数」沿用构想层的记号：`0`、`n`（固定数量）、`-1`（不定数量）、`-2`（由附参给出，仅 `CALL`）。
- 文本中的指令写法（如 `DATA{...}`、`@POPS[3]`）只用于说明，其文法由 SPEC-0201 定义。
- 正文中的 `〔R-NN〕` 表示该条是评审者补充的细则，`〔P-NN〕` 表示该条依赖一个待决问题，见第 6 条。

### 5. 外部标准引用

按 DEC-0001 第 2 条：

| 用途 | 标准 |
| --- | --- |

| `FN_HASH*` 算法 1 | BLAKE2b（RFC 7693） |
| `FN_HASH*` 算法 2 | SHA-2（FIPS 180-4） |
| `FN_HASH*` 算法 3 | SHA-3（FIPS 202） |

#### 6.2 评审者补充的细则（待作者确认）

以下细则是评审者在编写 Spec 时补充的，Conception 与 Decision 没有直接写明。正文已按「建议」写入并以 `〔R-NN〕` 标注；作者确认之前，它们的状态是建议值。作者否决或修改时，按回答修订对应条文。

| 编号 | 细则 | 所在规格 |
| --- | --- | --- |
| R-01 | 变长整数分两种：取值类（整数字面量、DATE、MODEL 整数范围的边界）用 Go `encoding/binary` 的 `Varint`（ZigZag + LEB128）；长度、数量、序位用 `Uvarint`（LEB128）。两者都必须是最短编码 | SPEC-0002 |
| R-02 | 多字节的定长整数与浮点数一律大端序（Rune 的 4 字节、Float 的 8 字节、`MODEL` 的 2 字节附参、`FN_XX`、`EXT_MO`、`EXT_PRIV`、`SYS_AWARD` 的高度、浮点范围匹配的边界），与 `BYTES(Int)` 的大端约定一致 | SPEC-0002 |
| R-03 | 可以为负的 1 字节附参（`&[n]`、`PEEK`、`PEEKS` 与 `VIEW` 的位置、`CMPFLO` 的比较类型）按 `i8`（二进制补码）解释 | SPEC-0002 |
| R-04 | `GOTO`、`EMBED`、`SCRIPT` 的引用附参形状由宿主规格用核心的附参类型声明（Evidcoin 为 `uvarint, bytes(48), uvarint`），核心按声明解码 | SPEC-0002、0008 |

| R-06 | 公共验证中，产生 Float 值或成员类型为 Float 的切片（即使为空）即失败 | SPEC-0004 |
| R-07 | 「可选单值」实参（`EXIT`、`RETURN`、`BREAK`、`CONTINUE`）按不定数量（`-1`）取值，实参区多于 1 项即失败 | SPEC-0002、0005 |
| R-08 | 单项大小上限在「产生值的指令」处检查：源码类指令的结果上限 16KB，其它指令的结果上限 8KB；值在栈、实参区、局部域、全局变量之间传递时不重新检查 | SPEC-0006 |
| R-09 | `STRING` 的附参 0 表示默认格式（整数与大整数十进制，浮点数 `g`），其余取值按构想层 | SPEC-0002 |

| R-12 | `MAP`、`FILTER` 迭代 Dict 时采用与 `EACH` 相同的键快照规则（DEC-0006 第 7 条只写了 `EACH`） | SPEC-0005 |
| R-13 | `SWITCH` 的块体也新建局部域。DEC-0006 第 8 条的清单没有列出 `SWITCH`，按「每次进入一个块都新建局部域」的原则补全 | SPEC-0005 |
| R-14 | 核心版本号是从 1 开始递增分配的正整数（「EVAL 代码的版本不得高于调用段」需要版本可比较）；宿主的版本字段映射不到本节点实现的版本的，都是未知版本，即失败 | SPEC-0007 |
| R-15 | `ENV` 的字段索引 0–31 归核心（v1 分配 0–9），32–255 归宿主（DEC-0002 第 1 条要求由 Spec 划分） | SPEC-0008 |
| R-16 | 核心 `ENV` 字段的编号、类型与取值：`Passed`、`InGoto`、`InEmbed`、`InScript`、`InCode` 为 Bool，`Gotos` 为 Int，`Embed1`–`Embed4` 为被嵌入段的字节码（Bytes，未发生为 Nil）；EVAL 代码中 `InGoto`、`InEmbed`、`Gotos` 取发起 `EVAL` 之处的值。构想层「嵌入脚本序列」也可能指引用而非字节码，请作者确认 | SPEC-0008 |

### 7. 核心与宿主的术语

| 术语 | 含义 |
| --- | --- |
| 段 | 一份单独加载的字节码：解锁脚本、锁定脚本、`GOTO` 目标、`EMBED` 目标、`EVAL` 代码 |
| 脚本域 | 拥有自己的数据栈、实参区、全局变量区与通关状态的执行单位（SPEC-0005） |
| 校验域 | 一次输入验证中由 `GOTO` 链共享的验证记录（`SIGNED`） |
| 宿主 | 使用核心 VM 的系统，例如 Evidcoin 节点 |
| 宿主规格 | 一份文档，给出某个宿主的字段表、算法与参数（SPEC-0008 列出它必须包含的内容） |
| 公共验证 / 私有执行 | 共识验证节点上的执行 / 私有节点上的执行（SPEC-0005 第 10 条） |


## 边界与限制

- 本规格集不定义交易结构、区块结构、手续费与转发策略（转发策略只给出建议，标为「应」）。
- 本规格集不定义宿主的前置检查（例如 Evidcoin 中币金与凭信的区别对待），它们在脚本执行之前完成。


## 待决问题

见第 6 条，本篇即全局待决集。


## 对 Plan 的约束

- Plan 必须按本篇第 2 条的划分组织核心包与宿主包，核心包不得引用宿主包。
- Plan 在第 6.1 条的问题决定之前，不得在代码中写死相应取值；需要占位时，使用显式的配置项或 `TODO(P-NN)` 标注。
- Plan 必须包含测试向量的导出（SPEC-0202）、Unicode 版本断言（P-01）与 Go toolchain 固定（DEC-0001 第 6 条）。
