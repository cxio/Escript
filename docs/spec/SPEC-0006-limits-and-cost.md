## 概述

资源由两种机制共同约束：**硬限额**约束单个结构的大小（栈、集合、嵌套、加载次数），**成本预算**约束总的计算量与内存量。本篇给出全部硬限额及其检查时点、成本的计算框架、初始成本表与三层预算。

成本表中的数值是校准的起点〔P-02〕，基准测试之后、v1 冻结之前可以调整；硬限额的数值已经确定。


## 规格正文

### 1. 硬限额

超出即失败（共识规则）。

| 项目 | 上限 | 检查时点 |
| --- | --- | --- |
| 数据栈高度 | < 256 | 每次向数据栈放置值时（SPEC-0005 第 5 条） |
| 实参区条目 | ≤ 1024 | 每次向实参区放置值时 |
| 局部域 | ≤ 128 项 / 活动记录 | 每次向局部域放置值时 |
| 全局变量 | 256 个位置 / 脚本域 | 由 `u8` 附参保证 |
| 普通数据项 | ≤ 8191 字节（< 8KB） | 产生值时〔R-08〕 |
| 源码类取值 | ≤ 16384 字节（16KB） | 产生值时〔R-08〕 |
| 集合成员数 | ≤ 1024 | 产生切片或向 Dict 加入条目时 |
| 块嵌套深度 | ≤ 16 / 段 | 加载期（SPEC-0003） |
| EVAL 嵌套 | 禁止 | 加载期 |
| `EMBED` | ≤ 4 次 / 脚本域，深度为 0 | 运行时计数；深度由加载期保证 |
| `GOTO` | ≤ 2 次 / 脚本域，深度 ≤ 3 | 运行时计数 |
| 外部加载总数 | ≤ 8 次 / 输入 | 每次 `GOTO`、`EMBED`、`SCRIPT` 加载之前 |
| 解锁脚本 | < 8192 字节 | 加载期 |
| 锁定脚本 | < 8192 字节 | 由宿主在创建输出时检查，花费时不检查 |
| 表达式 `()` | ≤ 255 字节 | 编码（`u8` 附参） |
| 正则字面量 | ≤ 255 字节 | 编码（`u8` 附参） |
| BigInt | 绝对值 < 2¹⁰¹⁶ | 产生值时 |
| OUTPUT 缓存 | 无共识限额 | 私有节点自行限制 |

**单项大小**〔R-08〕按产生值的指令区分：

- 源码类指令的结果，上限 16384 字节：`SOURCE`；`IN{Locked}`、`IN{Unlock}`、`IN{Source}`；`OUT{n, Locked}`、`INOUT{n, Locked}`；`XFROM{Locked}`、`XFROM{Source}`；`CODE`、`SCRIPT` 创建的 Script（DEC-0007 第 1 条）；`BYTES(Script)` 的结果〔R-26〕。`IN`、`OUT`、`INOUT`、`XFROM` 的字段名以宿主字段表为准，宿主规格须标注哪些字段属于源码类。
- 其它指令产生的 String、Bytes、RegExp（源文本）、BigInt，上限 8191 字节。
- 值在数据栈、实参区、局部域、全局变量区之间移动，或作为切片成员被引用时，不重新检查。对一个 16KB 的源码类 Bytes 执行 `SLICE`、`ADD` 等运算，结果按普通数据项检查。

**集合成员数**：切片（包括 `[]Byte`）与 Dict 的成员数不超过 1024。Bytes 不是切片（SPEC-0004 第 2 条），是普通数据项，只受单项大小约束（DEC-0007），因此 8KB 的签名可以表示为 Bytes，但不能整体转为 `[]Byte`。切片与 Dict 作为整体不受单项大小约束（DEC-0007 第 1 条）。

### 2. 成本的计算框架

成本是指令性质与实参大小的确定性函数，与硬件无关（`Design.md`「实现参考」）。在此之上（DEC-0007 第 2 条）：

1. **每条被执行的指令至少计 1 个单位**，包括截取前缀，以及公共节点上作为空操作的 `PRINT`、`FN_PRINTF`、`OUTPUT`、`BUFDUMP`。
2. **新数据按字节计**：每产生 64 字节新数据计 1 个单位，即 ⌈新数据字节 / 64⌉。
3. **跳过的代码不计执行成本**；被加载的段按其长度在加载期计费（SPEC-0003 第 8 条）。

单条指令的成本为：

```
成本 = 1 + 按条目项 + 按字节项 + 特殊项
```

各项的含义：

| 项 | 定义 |
| --- | --- |
| 涉及条目数 | 该指令取得的实参个数与放置的返回值个数之和 |
| 新数据字节 | 即第 2.1 条的 `D`：只计新产生的变长内容，定长标量与对已有值的引用（如 `TOP`、`PEEK`、共享底层存储的 `SLICE`）计 0。各指令的规格逐条写明 |
| 成员数 | 该指令遍历或产生的集合成员数 |
| 特殊项 | 哈希、签名、正则、外部加载等的附加成本，见第 3 条 |

**计费时点**：一条指令的成本中，凡在执行其操作之前就能确定的部分（基础成本、与实参大小有关的部分、特殊项），在执行操作之前计入；依赖结果大小的部分，在结果产生之后、放置之前计入。任一时刻累计成本超过预算即失败。

例：`GOTO` 先计 1 + a + 200，再向宿主取目标脚本；取到之后计 ⌈脚本字节 / 64⌉，再按 SPEC-0003 第 8 条计扫描成本。预算在取数之前已经耗尽时，结果是失败，不会向宿主取数。

**成本何时属于共识**〔R-18〕：结果为通过时，实际成本属于共识，宿主据此累计交易与区块的成本。结果为失败或数据不可用时，交易不会被收录，实际成本不属于共识，测试向量不断言。但计费的顺序仍须遵守上述时点，因为它决定了「超出预算而失败」发生在取数之前还是之后，从而区分失败与数据不可用。

#### 2.1 记法〔R-21〕

第 3 条与 SPEC-0101 ～ 0106 各指令的「成本」一行使用以下记号：

| 记号 | 含义 |
| --- | --- |
| `B(x)` | ⌈x / 64⌉，x 为字节数 |
| `a` | 取得的实参个数（截取前缀与附参不计） |
| `r` | 放置的返回值个数 |
| `D` | 新数据字节，见下 |
| `m` | 遍历或产生的集合（切片、Dict）成员数。Bytes 不是集合，不计入 `m`，其字节计入 `D` |
| `K` | `1 + a + r + B(D)`，即上文的「1 + 按条目项 + 按字节项」 |

`D` 只计本指令新产生的**变长内容**：String、Bytes、BigInt 的字节，RegExp 的源文本，Script 的字节码，包括作为新切片或新 Dict 的成员而新产生的这类内容。以下情形计 0：

- 定长的标量（Nil、Bool、Byte、Rune、Int、Float、Time），它们已由 `a`、`r` 计入；
- 只是引用已有的值：`TOP`、`PEEK`、共享底层存储的 `SLICE`，以及放入新切片的已有成员。

计费时点按上文：`a` 与附参决定的部分在执行之前计入；`r` 为 `*` 时的 `r`、`B(D)`、依赖结果的 `m`，在结果产生之后、放置之前计入。

### 3. 初始成本表〔P-02〕

| 类别 | 成本 |
| --- | --- |
| 截取前缀（`@`、`&`、`~`、`_`） | 1 |
| 值、截取取值（`&[n]`、`$X`）、栈操作、比较、逻辑（`BOTH`、`EITHER`）、环境取值（`ENV`、`IN`、`OUT` 等）、结果与流程指令、系统占位符 | `K` |
| 集合操作（`MERGE`、`REVERSE`、`PACK`、`ANYS`、`EVERY` 等，以及值集） | `K + m` |
| Int 运算（命名指令与表达式运算符，含 `NEG`、`NOT`） | 2 |
| BigInt 运算 | 加、减、取负、位运算与移位：2 + w；乘、除：2 + w²。w 为操作数与结果中最大者的 64 位字数（1–16） |
| 字符串、字节的拼接 | `K` |
| 字典合并（`ADD`） | `K + m` |
| 文本解析（`INT(String)`、`TIME(String)`、`SUBSTR` 等） | `K + B(输入字节)` |
| 哈希（`FN_HASH*`） | `K + 20 + B(输入字节) × k`；k：BLAKE3 为 1，SHA-3 为 3，BLAKE2b 与 SHA-2 待校准 |
| `FN_BASE58` | `K + ⌈L² / 128⌉`，L 为输入字节数。编码时实参超过 256 字节即失败；解码时结果超过 256 字节即失败〔R-32〕 |
| 签名验证、`FN_PUBHASH`、`FN_MPUBHASH`、`FN_ADDRESS`、`SYS_AWARD` | 由宿主规格给出（〔P-03〕）；签名验证的量级约 1000 |
| 正则编译 | 10 + 正则字节数（字面量在加载期计；`REGEXP(String)` 在运行时计） |
| 正则匹配（`MATCH`、`REPLACE` 的正则形式、MODEL 的 `RE`、`MO_RE` 的方法） | ⌈输入字节 × 正则字节 / 8⌉，另加所在指令的成本 |
| `MODEL` | `K + m + 10 + B(目标字节)` + 比较次数，另加其中的正则匹配与哈希匹配成本；m 为取值个数（SPEC-0103 第 13 条） |
| `CASE` | `K + 1`（1 为与分支值的一次比较） |
| `EACH` | `K` + 每轮 1（块体的成本另计；被跳过的轮次也计） |
| `MAP` / `FILTER` | `K + 5` + 每轮 2 |
| `EVAL` | `K + m + 10`，m 为返回切片的成员数；另计代码的加载期成本（SPEC-0003 第 8 条） |
| 外部加载（`GOTO`、`EMBED`、`SCRIPT`） | `K + 200`，`D` 为脚本字节数；`GOTO`、`EMBED` 的目标另计加载期成本 |
| `RANDOM` / `SLRAND` | `K + 20` / `K + 20 + m` |
| 加载期结构扫描 | 每段 `B(段字节数)` |

- 外部加载按固定成本计，不论默克尔证明是用户携带的还是节点自己查到的（DEC-0007 第 3 条）。
- 每条指令属于哪一类、各项如何取值，由 SPEC-0101 ～ 0106 在每条指令的「成本」一行写明。本表是这些公式的来源。
- 模块方法的成本见 SPEC-0105 的方法表：基数为 `K`（方法调用按实参与返回值计，不用运算类的固定值 2），再加所属类别的附加项，如 BigInt 除法的 w²、正则匹配的成本。因此同一运算经运算指令与经模块方法的成本可以不同。
- 校准目标：1 个单位约 100 纳秒（参考硬件，单核）。

### 4. 预算

| 预算 | 核心默认值 | 配置层级 | 执行者 |
| --- | --- | --- | --- |
| `MaxInputScriptCost` | 500,000 | 核心级：宿主规格可以改写 | 核心 VM：超出即该输入失败 |
| `MaxTxScriptCost` | 5,000,000 | 核心级：宿主规格可以改写 | 宿主：累计交易中各输入的实际成本 |
| `MaxBlockScriptCost` | 无 | 宿主级：只由宿主规格给出 | 宿主：累计区块中各交易的实际成本 |

- 三层预算都是共识规则（DEC-0007 第 4 条）。数值由宿主规格确定，同一宿主的全部节点相同，不是节点的本地设置。
- 交易与区块的成本是其中各输入实际执行成本之和。
- 单输入预算同时限制了内存：50 万单位对应累计分配约 32MB。

### 5. 冻结

- 校准完成后，成本表与硬限额随脚本版本冻结（DEC-0004 第 2 条），之后的调整只能通过新版本。
- 三项预算不随脚本版本变化，是宿主的共识参数：调低是强分叉（规则收缩），调高是弱分叉（规则扩展）（DEC-0007 第 5 条）。


## 边界与限制

- 手续费与成本的关系不在协议层规定。转发策略中，节点应按「手续费 ÷ max(交易字节数, 成本折算的字节数)」排序，并对频繁转发失败交易的对等节点降低信任（DEC-0007 第 6 条）。这是建议，不是共识。
- 核心 VM 只执行单输入预算。交易与区块预算由宿主在核心之外累计。

## 对 Plan 的约束

- 成本函数必须集中在一张「码值 → 成本函数」的表中，相似成本的指令共享函数（`Design.md`「实现参考」）。成本系数必须是常量表，不得散落在各指令的实现中，以便校准后统一替换。
- Plan 必须包含一套基准测试：覆盖第 3 条每一类，记录参考硬件与单位耗时，产出校准报告。
- 结果为通过的测试向量，期望结果中必须包含成本（DEC-0001 第 5 条、本篇〔R-18〕）。
- 硬限额的每一行都要有「恰好在上限」与「超出上限一项」两个向量。
