## 概述

每个锁定脚本有一个版本号，由创建输出的人决定。一个版本对应一组表（指令码、取值表、方法表、成本表等），发布之后不再变化。节点遇到当前版本的表里没有的码位，或不认识的版本，一律判为失败。新的功能只能通过发布新版本加入；旧版本保持原样，旧版本的输出永远按原规则验证。

本篇规定：版本号的来源与比较，每段的版本，版本冻结的内容，未分配与未知版本的处理，跨版本的规则，以及规格维护者在升级时必须遵守的规则。

分叉的种类按 `Design.md`「附：分叉种类」：**弱分叉**（规则扩展，向后兼容）、**强分叉**（规则收缩，向前兼容）、**异分叉**（规则改变，不兼容）。


## 规格正文

### 1. 版本号

- 版本号由锁定方决定，花费者不能选择（DEC-0004 第 1 条）。
- 版本号放在宿主的输出结构中，不放进字节码。宿主规格规定从输出结构中的哪个字段取得版本，以及该字段的取值与核心版本号的对应（Evidcoin：输出项的版本字节〔P-09〕）。
- 核心版本号是从 1 开始递增分配的正整数〔R-14〕。宿主字段的取值映射不到任何核心版本号，或映射到本节点没有实现的核心版本号，都是**未知版本**。
- 节点必须实现全部已发布的核心版本。

### 2. 每段的版本

| 段 | 版本 |
| --- | --- |
| 锁定段 | 被花费输出的版本 |
| 解锁段 | 与锁定段相同 |
| `GOTO` 目标 | 目标所在输出的版本 |
| `EMBED` 目标 | 目标所在输出的版本 |
| `EVAL` 代码 | 所执行的 Script 值携带的版本 |

Script 值的版本：

- `CODE` 创建的 Script，取 `CODE` 指令所在段的版本。
- `SCRIPT` 创建的 Script，取被引用输出的版本。创建时不检查该版本是否已知（检查在 `EVAL` 时进行，第 5 条）。

**每条指令按其所在段的版本解码和执行。** `EMBED` 的代码虽然在调用者的脚本域内执行，其中每条指令仍按嵌入段的版本处理。`CALL` 使用的方法集，取该 `CALL` 指令所在段的版本。

### 3. 一个版本冻结的内容

| 表 | v1 所在 |
| --- | --- |
| 指令码表：每个指令的附参格式与取值范围；取值由表给出的附参同时给出取值表 | SPEC-0002 |
| 环境字段表：`GVAL`、`ENV`、`IN`、`OUT`、`INOUT`、`XFROM` | 核心字段见 SPEC-0008 第 3 条；宿主字段见宿主规格（Evidcoin：SPEC-0901〔P-08〕） |
| 见证条目表（系统占位符的附参） | 宿主规格〔P-08〕 |
| `FN_X`、`FN_XX`、`EXT_MO` 的索引表，哈希算法标识、MODEL 类型标识等取值表 | SPEC-0002（v1 中 `FN_X`、`FN_XX`、`EXT_MO` 没有已分配的条目）；MODEL 类型标识见 SPEC-0103〔P-07〕 |
| 各模块与系统对象的**静态方法表**：方法索引、索引别名、参数类型、返回类型、成本函数、公 / 私域标注 | SPEC-0105〔P-05〕 |
| 各模块与系统对象的 **`CALL` 方法集**：方法名、参数类型、返回类型、成本函数、公 / 私域标注 | SPEC-0105〔P-05〕 |
| 值类型的集合 | SPEC-0004 |
| 成本表与硬限额 | SPEC-0006〔P-02〕 |

**一个版本发布之后，以上各表都不再变化**：不修改已分配的条目，也不在该版本内分配新的条目。

宿主指令（SPEC-0002 标记 H）：宿主规格没有实现的宿主指令，对该宿主而言是未分配码位。

### 4. 未分配：失败

**未分配**是指：

- 当前版本没有分配的指令码，包括量子安全保留区 156–163 与构想层标为「未用」的码值；
- 附参取值不在当前版本的取值表内：环境字段的索引、见证条目的索引（系统占位符）、`FN_X` / `FN_XX` 的索引、`EXT_MO` 的模块索引与方法索引、模块的静态方法索引（例如 `MO_MATH{Abs}` 的附参）、哈希算法标识、MODEL 的类型标识等（SPEC-0002 中标注「**索引**」的附参）。

| 情形 | 结论 | 时点 |
| --- | --- | --- |
| 任何一段（包括模式体内与不会执行到的分支）含有未分配的码值或附参取值 | 该段加载失败，验证失败 | 加载该段时（SPEC-0003 第 2.3 条） |
| `CALL` 调用的方法不在该 `CALL` 指令所在段的版本的 `CALL` 方法集中 | 失败 | 执行到该 `CALL` 时 |

补充：

1. 码值 255 永久保留，出现在任何段都无效。码值 254（系统占位符）已分配，出现在解锁段以外（模式体除外）即无效（SPEC-0003 第 7 条）。
2. 私有专属指令（SPEC-0002 标记 P）是已分配码位：公共验证执行到即失败（SPEC-0005 第 10 条），不执行到则不影响结果。
3. **`CALL` 与静态方法都严格**，区别只在发现的时点：静态方法索引在加载期可见，`CALL` 的方法名在运行时才确定。

### 5. 未知版本与跨版本的规则

| 情形 | 结论 | 时点 |
| --- | --- | --- |
| 锁定段的版本未知 | 失败，不加载任何段 | 验证开始时（SPEC-0003 第 2.1 条） |
| `GOTO` / `EMBED` 目标的版本未知 | 失败 | 加载该目标时 |
| `EVAL` 代码的版本未知 | 失败 | 执行 `EVAL` 时，加载代码之前 |
| `EVAL` 代码的版本高于发起 `EVAL` 的段的版本 | 失败 | 同上 |

- 「发起 `EVAL` 的段」是 `EVAL` 指令所在的段。例如 `EVAL` 写在 `EMBED` 目标中，比较的对象就是该 `EMBED` 目标的版本。
- `GOTO`、`EMBED` 目标的版本不受调用者版本的限制：目标写在锁定脚本的附参中，由锁定方在创建输出时选定（DEC-0004 理由）。
- **新版本的值类型**〔R-19〕：某条指令按其所在段的版本执行时，遇到该版本没有定义的类型的值，即失败。这样的值可能经由 `EMBED`（共享数据栈）或 `GOTO`（实参）从更高版本的代码进入。v1 是第一个版本，这条规则约束的是将来版本的规格：新增类型的版本必须照此为旧版本补充定义。

### 6. 升级规则

本条约束规格的维护者。

- **升级的唯一途径是发布新版本**（DEC-0004 第 4 条）。新版本有自己完整的一组表，可以：增加指令码、取值、方法（包括 `CALL` 方法集）、模块与值类型；调整成本表与硬限额；改变某个条目在新版本中的语义。
- 旧版本保持原样。对脚本规则而言，发布新版本是**弱分叉**：新节点接受旧节点接受的全部交易，此外还接受新版本的交易。没有升级的节点遇到新版本即失败（第 5 条）。
- 新版本从何时起被接受，由宿主规格规定〔P-04〕。在 Evidcoin 中，新版本连带交易版本与区块版本更新，旧版区块不能收录新版交易，新旧分叉由分叉竞争决出（`Design.md`「未知码位处理」「附：版本关系」）。新版本的生效经过「预发布」：生效高度已到、且新版交易的占比达到阈值，两个条件同时满足才生效；此前沿用旧版，新版标记只用于统计。阈值、高度与统计口径由 SPEC-0901 给出。
- 新版本改变已有码位的语义时，反编译器（SPEC-0201）与 MODEL 都必须按版本区分。码位的语义应尽量在各版本间保持稳定，优先分配新码位。
- **已发布版本的规则不得修改。** 确实需要修改时（例如发现安全缺陷，必须禁用某条指令），属于强分叉或异分叉，不在本条的升级路径之内，由宿主决定并单独发布。
- 宿主参数（三项预算等）不随脚本版本变化：调低是强分叉，调高是弱分叉（SPEC-0006 第 5 条）。

### 7. 转发策略（非共识）

节点**不应**转发或打包这样的交易：它创建的输出使用了本节点不认识的版本，或其锁定脚本按该版本加载失败（SPEC-0003）。这样的输出按当前规则永远无法花费（DEC-0004 第 5 条）。

宿主可以把这一检查定为共识规则（DEC-0004 第 5 条），核心为此提供检查函数（SPEC-0008 第 5.4 条）。Evidcoin 采用共识检查，此时它不再只是转发策略。

### 8. v1

v1 的各张表分布在：SPEC-0002（指令码表、取值表）、SPEC-0004（值类型）、SPEC-0105（方法表〔P-05〕）、SPEC-0006（成本表与硬限额〔P-02〕）、SPEC-0008 第 3 条（核心环境字段）、宿主规格（宿主字段表、见证条目表）。全部待决项决定并通过校准之后，v1 冻结发布。


## 边界与限制

- 区块版本、交易版本与分叉竞争属于宿主，不属于本规格集。核心只认识脚本版本（即 Evidcoin 的输出项版本）。
- 版本号不放进字节码，因此字节码本身不能自述版本。编译器、反编译器与测试向量必须显式携带版本（SPEC-0201、0202）。
- 本篇不规定新版本的发布流程，只规定哪些变更必须通过新版本。
- 其它宿主如果需要「不升级全部验证节点就能引入新的脚本功能」，本规格集不提供这种机制（DEC-0004 不做）。

## 对 Plan 的约束

- 版本表必须是数据驱动的：按版本索引的指令码表、取值表、方法表、值类型集合、成本表。不得用散落在代码中的 `if version >= N` 实现版本差异。
- Script 值的内部表示必须携带版本号。
- 解码器与加载器必须以「段的种类 + 版本」为输入。
- 测试向量必须覆盖（DEC-0004 影响一节）：各种段中出现未分配码位（包括模式体内与不会执行到的分支）；未分配的静态方法索引；`CALL` 调用未知方法；锁定段、`GOTO` 目标、`EMBED` 目标、EVAL 代码的版本未知；EVAL 代码的版本高于调用段；没有执行到的 `GOTO` 的目标版本未知或无效时，验证结果不受影响。
