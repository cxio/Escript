## 概述

文本是字节码的书写与显示形式。构想层的说法是：「链上的脚本已经被编译为指令值序列，文本是解译后的显示」。本篇定义三件事：

- **编译**：把文本转为一段字节码；
- **规范反编译**：把一段字节码转为唯一确定的文本；
- 两者之间的往返性质。

第 11 条用 EBNF 汇总文本的文法。

文本不进入共识，节点只处理字节码。本篇约束的是编译器、反编译器与测试向量（SPEC-0202）三者之间的一致。


## 规格正文

### 1. 输入、输出与往返

**编译**有三项输入：一段文本、核心版本 v、宿主配置。宿主配置指宿主规格中的环境字段表、见证条目表与外部脚本引用的字段序列（SPEC-0008 第 2 条）。输出是一段字节码，或者编译错误。

**反编译**有三项输入：一段字节码、v、宿主配置。输出是规范文本（第 9 条）。

- 文本中不写版本，字节码中也没有版本（SPEC-0007）。同一份文本按不同版本编译，结果可以不同。
- 指令字、别名与取值表都按 v 选取：v 中未分配的码值没有指令字，未分配的取值没有名称。
- 编译只做产生字节所需的检查（第 10 条），不做加载期校验。字节码能否加载由 SPEC-0003 判定；工具应在编译之后按段的种类做加载期校验，并报告结果。
- 一份文本对应一段字节码，解锁脚本与锁定脚本分别编译。

**往返**〔R-49〕：

1. 一段字节码 S 在 (v, 宿主, 段的种类) 下能通过加载期校验时，`编译(反编译(S)) = S`。
2. 文本 T 编译成功时，`反编译(编译(T))` 称为 T 的规范形式；把规范形式再编译，仍得到 `编译(T)`。
3. 反编译的结果只取决于 (S, v, 宿主配置)。

第 1 项以规范编码为前提（DEC-0003 第 2 条）。为使它对所有可加载的段都成立，加载期规则保证正则与 `SHELL` 的数据总能用字面量写出（SPEC-0003 第 3 条第 8、12 项）；代码类的数据（`CODE`、块体、表达式体、模式体）可能不能写成指令文本，本篇为它们规定了原始数据写法（第 8 条）。

### 2. 源文本与词法〔R-43〕

**字符集。** 源文本是 UTF-8 编码的文本（构想层：「所有的脚本源码文本视为 UTF-8 编码」），不合法的 UTF-8 是编译错误。指令字、别名、类型名等标识符只由 ASCII 字母、数字与 `_` 组成，区分大小写。非 ASCII 字符只能出现在注释、字符与字符串字面量、正则字面量，以及 `SHELL` 的内容中。正则与 `SHELL` 的内容没有转义，其中的字符（包括控制字符）按其 UTF-8 字节原样成为数据（第 3.6、3.9 条）。

**空白。** 空格、制表符（U+0009）、换行（U+000A）与回车（U+000D）是空白。其它字符都不是空白，包括非 ASCII 的空白字符。

**注释**（构想层 `0.基本约束.md`）：

- `<|` 开始单行注释，直到行尾（换行或文本的末尾）。
- `<<` 开始多行注释，直到其后的第一个 `>>`。多行注释不嵌套；没有结束的 `>>` 是编译错误。
- 注释只能出现在一层指令序列中、两条指令之间（或序列的首尾）。一层指令序列指段的顶层、代码块体、模式体、表达式体，以及写成指令文本的 `CODE` 内容。
- 注释不能出现在一条指令的内部，即：指令字与其附参、数据之间；方括号之内；数据、别名、值集、范围与 `RE{}` 的花括号之内（块体除外）；任何字面量之内。在这些位置，`<|`、`<<` 不是注释。例如字符串 `"<|"` 中的两个字符是数据，`SHELL{<<` 中的 `<<` 是定界符（第 3.9 条）。
- 注释在编译时等同于空白。

**记号的切分。** 按最长匹配切分记号。只有当两个记号会被连成一个时，才必须用空白分开，例如两个相邻的指令字。规范文本中的分隔见第 9.4 条。

**附着。** 一条指令由指令字（或符号）及附着在它后面的附参与数据组成：

| 附着的部分 | 规则 |
| --- | --- |
| 附参 `[...]` | 紧跟在指令字之后，中间不得有空白 |
| 名称别名 `{...}`（第 4.3 条） | 紧跟在指令字之后，中间不得有空白 |
| 关联数据 `{...}` | 用于需要关联数据的指令（`DATA`、`CODE`、`SHELL`、`DATE`、块指令、`MODEL`）。它与指令字或附参之间可以有空白，例如构想层的 `IF {`、`EACH { $Value }`，但不能有注释 |
| 尾随的 `?`（第 7.3 条） | 紧跟在目标指令之后，中间不得有空白 |

对于不接受附参或花括号的指令，后面紧跟 `[` 或 `{` 是编译错误，例如 `NOP{5}`。用空白分开写成 `NOP {5}` 时，`{5}` 是下一条指令。

### 3. 字面量〔R-44〕

#### 3.1 常量与字符

- `NIL`、`TRUE`、`FALSE` 分别是 opcode 0、1、2。
- 字符字面量写作 `'c'`，单引号内是一个字符或一个转义。转义与 Go 的 rune 字面量相同：`\a`、`\b`、`\f`、`\n`、`\r`、`\t`、`\v`、`\\`、`\'`，以及 `\xHH`、`\ooo`（八进制）、`\uHHHH`、`\UHHHHHHHH`。
  - 用 `\u` 或 `\U` 书写的是 Rune（opcode 4），例如 `'\u0041'`。
  - 其余写法按码点选择类型（构想层：按 Unicode 码点大小自动选择 opcode 3 或 4）：码点不大于 `0xFF` 的是 Byte（opcode 3），否则是 Rune。因此 `\xHH`、`\ooo` 与单字符转义都是 Byte，直接写出的 `'é'`（U+00E9）也是 Byte，值为 `0xE9`。
  - Rune 必须是 Unicode 标量值（SPEC-0003 第 3 条第 3 项），否则是编译错误。

#### 3.2 数值

```
十进制   0 | [1-9] ( ["_"] [0-9] )*
十六进制 ("0x" | "0X") ["_"] 十六进制数字 ( ["_"] 十六进制数字 )*，二进制 0b / 0B 与八进制 0o / 0O 同理
浮点     十进制数字串 "." [十进制数字串] [ ("e" | "E") ["+" | "-"] 十进制数字串 ]
无穷     "Inf" | "+Inf" | "-Inf"
```

- 下划线只能位于两个数字之间，或者位于进制前缀与数字之间（同 Go）。多位的十进制数不得以 0 开头：`007` 是编译错误，以免与 Go 的旧式八进制混淆。
- 浮点的数字写法必须含小数点（构想层：「需包含小数点以与整数区分」），例如 `{123.}`、`{2.16e10}`。没有小数点的 `2e10` 是编译错误，浮点范围（第 7.6 条）除外。不支持十六进制浮点。`NaN`、`+NaN`、`-NaN` 都是编译错误。无穷用上一行的 `Inf`，不靠数字舍入得到。
- **整数**写在花括号中：`{12345}`、`{-100}`。花括号内可以有空白，数值前可以带一个 `+` 或 `-`，符号与数字之间不能有空白。在表达式体内，非负的整数与浮点数字可以不加花括号（第 6.2 条）。
  - 花括号中的整数必须落在 int64 范围内，编码为 Int（opcode 5）。超出 int64 是编译错误，大整数用 `B{}`。
- **大整数**写作 `B{...}`，编码为 BigInt（opcode 6）。这是显式的类型指定：值可以落在 int64 范围内，如 `B{1024}`、`B{0}`、`B{-1}`，与 `{1024}` 等 Int 是不同类型（DEC-0003 第 2 条第 2 项）。超出 int64 的值也写在这里，如 `B{0x8000ffff_8000ffff_8001}`。绝对值必须小于 2¹⁰¹⁶（编码后至多 127 字节），否则是编译错误。
  - 花括号内是整数写法，可以带一个 `+` 或 `-`。小值通常写十进制，较大的值通常写十六进制（构想层）。下划线分隔同整数。
  - 编译器写出最短绝对值：去掉前导零字节。`B{0}`、`B{0x0}`、`B{+0}` 都是一个 `0x00` 字节、符号位为 0。`B{-0}`、`B{-0x0}` 是负零，编译错误。字节码中的负零、前导零与 L = 0 由加载期拒绝（SPEC-0003 第 3 条第 2 项）。
  - `B` 与 `{` 之间不能有空白。
- **浮点**写在花括号中，编码为 Float（opcode 7）：`{3.14}`、`{123.}`、`{2.16e10}`、`{-0.0}`、`{+0.0}`、`{Inf}`、`{+Inf}`、`{-Inf}`。
  - 十进制值按 IEEE 754 舍入到最近的 binary64（两者等距时取偶数）。舍入结果不是有限值即为编译错误：过大的数不能借舍入变成无穷，要写无穷只能用 `Inf`。下溢成 0 的保留符号，`{-1e-400}` 是 −0，不是编译错误。
  - `Inf` 与 `+Inf` 是 +Inf，`-Inf` 是 −Inf。符号与 `Inf` 之间不能有空白。三者各对应唯一的位模式（SPEC-0003 第 3 条第 4 项）。
  - `{-0.0}` 是 −0，`{0.0}` 与 `{+0.0}` 是 +0。两者位模式不同。
  - 不支持 NaN 字面量。浮点范围的上下界也可以写 `Inf`（第 7.6 条）；范围里舍入成 −0 的有限写法仍编译为 +0，与字面量不同。

#### 3.3 字符串

字符串有两种写法，书写规则与取值都和 Go 语言规范中的字符串字面量相同：

- 解释型 `"..."`：支持 Go 的全部转义。`\xHH` 与八进制转义可以写出任意字节，不要求是合法的 UTF-8（String 不检查 UTF-8，SPEC-0004）。不能含换行。
- 原始型 `` `...` ``：内容原样取用（按 Go 的规定，其中的回车被丢弃），可以跨行。

字符串编码为 opcode 8，长度附参由编译器计算。

#### 3.4 值集

`{m1, m2, ...}` 编码为 opcode 9。

- 成员只能是 `TRUE`、`FALSE`、字符字面量、数值、`B{...}` 与字符串。成员中的整数与浮点数字不加花括号，可以带符号；大整数成员仍写 `B{...}`，无穷写 `Inf`、`+Inf`、`-Inf`。`{B{1024}, 255}` 的成员是 BigInt 与 Int。`{B{1}}` 没有逗号，不是值集，也不能按第 3.2 条解析为数值，是编译错误；单成员写作 `{B{1},}`。
- 至少两个成员；只有一个成员时，必须带尾随逗号，如 `{100, }`（构想层）。多个成员时也允许尾随逗号。
- 只有一个成员且没有逗号的 `{...}` 是数值字面量（第 3.2 条）；如果花括号内不是数值（如 `{'A'}`、`{"x"}`），是编译错误。`{}` 也是编译错误（构想层：「缺乏类型表达」）。
- 成员的类别约束（同一类别，BigInt 与 Float 不混合）属于加载期检查（SPEC-0003 第 3 条第 5 项）。

#### 3.5 `DATA`

`DATA{hex}`、`DATA[L]{hex}` 编码为 opcode 10。

- 花括号内是十六进制数字，大小写不限，可以夹有空白和 `_` 作为分隔，数字的个数必须是偶数。可以带 `0x` 前缀（与第 8 条一致）。`DATA{}` 是空的 Bytes。
- 写出 `[L]` 时，数据不足 L 字节的部分在末尾补零（构想层：「多出的空位用零值填充」）；数据超过 L 字节是编译错误。

#### 3.6 正则

`/.../` 编码为 opcode 11。

- 两个 `/` 之间的内容原样作为正则的数据，交给 RE2，没有任何转义替换（构想层：「不支持任何转义替换」）。
- 扫描从左到右，`\` 与它后面的一个字符一起消费，原样保留，所以 `\/` 不结束字面量，数据中仍是 `\/`（RE2 把它当作 `/`）。第一个不属于这种成对的 `/` 结束字面量。
- 因此正则中的 `/` 都要写作 `\/`。与 JavaScript 不同，字符类中的 `/` 也要转义：`/[/]/` 在 `[` 之后的 `/` 处就结束了，得到正则 `[`，其后的 `]` 是编译错误；应写作 `/[\/]/`（构想层）。
- 内容不能含换行或回车（构想层：「内容本身不支持换行，匹配换行需要用转义 `\n` 表达」），这里的 `\n` 是交给 RE2 的两个字符。
- `//` 是空正则（构想层）。
- 数据不超过 255 字节，否则是编译错误。数据不含换行与回车、其中的 `/` 都与前面的 `\` 成对、能按 RE2 编译，属于加载期检查（SPEC-0003 第 3 条第 8 项）。所以凡能通过加载的正则，都能用这种写法原样写出（第 9.2 条）。
- 在表达式体内，`/` 总是除号，不能开始正则（第 6.2 条）。

#### 3.7 `DATE`

`DATE` 是 opcode 12，数据是毫秒时刻。它有两种写法（构想层）：

- `DATE{RFC3339}`，形如 `YYYY-MM-DDTHH:MM:SS[.f](Z|±HH:MM)`。`T`、`Z` 必须大写；小数秒为 1 到 3 位；秒为 00–59，不接受闰秒；年为 0000–9999；日期必须合法。带偏移的时间按偏移换算为 UTC 时刻，偏移本身不编码（SPEC-0004 第 2 条）。
- `DATE[ms]`：直接写毫秒数，取值为 int64，可以为负。

这里的文本写法与 `TIME(String)` 的运行时解析（SPEC-0102）是两回事，后者接受的范围另有规定。

#### 3.8 `CODE`

`CODE{...}` 编码为 opcode 16。花括号内是一段指令文本，按普通代码编译（不属于模式上下文，见第 7.1 条），得到的字节就是 `CODE` 的数据。段级规则（例如 EVAL 代码不得含有 `EVAL`）在编译时不检查，`EVAL` 执行时加载这段代码才检查（SPEC-0003）。

数据不能用指令文本表达时，写作 `CODE{0x...}`（第 8 条）。

#### 3.9 `SHELL`〔R-48〕

`SHELL` 编码为 opcode 155（语义见 SPEC-0104 第 3.13 条）。它的数据是命令文本的 UTF-8 字节，不是指令文本，没有任何转义，其中的引号、花括号都只是数据（构想层）。数据必须是合法的 UTF-8（SPEC-0003 第 3 条第 12 项），因此总能写成定界写法。`{` 之后的写法由其后的内容区分。

**定界写法**（构想层）。`{` 之后紧跟 n 个 `<`（n ≥ 1），再紧跟一个换行（LF 或 CRLF）。数据从这个换行之后开始，到结束定界符之前为止。结束定界符是 n 个 `>`，其后紧跟 `}`：

```
SHELL{<<
#!/bin/bash
echo "hello"
>>}
```

- n 由书写者按内容选定。`{`、`<`、换行三者之间不得有空白或注释。`<` 之后不是换行，是编译错误。
- 数据止于文本中第一个「n 个 `>` 紧跟 `}`」的位置。这 n 个 `>` 与 `}` 不属于数据；在它们之前的字符，包括紧挨着的 `>`，都属于数据，例如 n = 2 时 `a>>>}` 的数据是 `a>`。没有这样的位置，是编译错误。
- 数据原样取用，包括缩进与末尾的换行。开头的那个换行属于定界符，不属于数据，所以示例的数据是 `#!/bin/bash`、换行、`echo "hello"`、换行，Shebang 位于数据的第一行。结束定界符之前没有换行时，数据也不以换行结尾。
- 数据中可以含有 `{`、`}`、`<`、`>`，也可以含有「不足 n 个 `>` 紧跟 `}`」的序列。数据含有 `>>}` 时，n 至少取 3。
- 空数据写作 `SHELL{<`、换行、`>}`。
- 这借鉴了注释 `<< … >>` 的写法，但结束规则不同：注释止于第一个 `>>`，这里 `>` 的个数随 `<` 而定，并且其后必须紧跟 `}`。`SHELL{<<` 中的 `<<` 是定界符，不是注释（第 2 条）。

**数据通配。** `SHELL{?}`（第 7.3 条），只能用于 `^` 单元。

**哈希。** 在掩码式 `^[0x81]` 等 0x80 置位的单元中，数据写作 `{0x…}`，是 32 字节的哈希（第 7.3 条）；匹配外部的 `SHELL` 脚本通常用哈希（构想层）。`SHELL` 没有原始数据写法，`{0x…}` 只在这里出现。

`{` 之后既不是 `<`，也不是（允许有空白在前的）`?` 或上述哈希，是编译错误，例如 `SHELL{echo hi}`、`^SHELL{0x…}`。

### 4. 指令、附参与别名

#### 4.1 指令字

指令字取自版本 v 的格式表（SPEC-0002 第 6 条），例如 `PASS`、`FN_HASH256`、`MO_MATH`。符号形式的指令见第 5、6、7 条。

#### 4.2 附参 `[...]`〔R-45〕

方括号内按格式表的顺序列出附参，以逗号分隔，可以有空白：

| 附参类型 | 写法 |
| --- | --- |
| `u8`、`u16be`、`u32be`、`uvarint` | 非负整数（第 3.2 条的整数写法）。可以用 `\|` 把几个整数按位或组合，如 `#[1\|2\|4]` |
| `i8`、`varint` | 整数，可以带 `-` 号 |
| `bytes(N)` | `0x` 加恰好 2N 个十六进制数字 |
| `HostRef` | 按宿主声明的字段序列逐个书写（SPEC-0002 第 2.2 条），如 `GOTO[2026, 0xab93…, 0]` |

- 取值超出类型的范围（例如 `u8` 大于 255）是编译错误。取值是否已分配（**索引**类附参）属于加载期检查。
- **长度类附参**由编译器计算，通常不写。这类附参包括：`DATA`、字符串、值集、`CODE`、`SHELL`、块指令、正则与表达式的长度，大整数的符号与长度，`MODEL` 的标记与长度。写出时，`DATA` 按第 3.5 条补零，其余的必须等于计算值，否则是编译错误。`MODEL` 的附参写出时是完整的 16 位值，含 bit15 的标记。
- **省略**：只有一个整数附参的指令（长度类附参除外），省略附参或写空的 `[]` 时，附参为 0（构想层的 `SHIFT[]`、`@POPS`、`FN_HASH256`、`SYS_TIME`）。以下指令例外，必须写出附参，因为省略后是另一条指令或没有意义：`&[n]`（21）、`.[n]`（118）、`^[m]`（120）、`#[m]`（121）、`$[n]`（126）。有多个附参的指令不能省略，例如 `PEEKS[0, 5]`。
- **`MATCH` 的省略**〔R-52〕：`MATCH` 有两个附参（方式、匹配数量），是上一条的例外：附参 2 可以省略，取 0；两个都省略（或写空的 `[]`）时都取 0（构想层的示例 `MATCH`、`MATCH{g}`、`MATCH[103]`、`MATCH{S}`）。写出附参 2 时必须同时写出附参 1，如 `MATCH[103, 20]`、`MATCH{g, 20}`。

#### 4.3 名称别名 `{...}`〔R-45〕

附参有名称表的指令，可以在花括号中写名称来代替数字（构想层：「花括号中的名称只是索引值的友好别名」）：

- 花括号内按附参顺序列出，以逗号分隔。每一项可以是名称，也可以是数字，例如 `OUT{0, Amount}`。
- 名称区分大小写，不在名称表中的名称是编译错误。
- `EXT_MO{Module.Method}` 用句点分隔模块名与方法名，给出两个附参；`EXT_MO{Module}` 的方法为 0，即构造模块对象（构想层）。

名称表：

| 指令 | 附参 | 名称表 |
| --- | --- | --- |
| `GVAL`、`IN`、`XFROM` | 字段 | 宿主的环境字段表 |
| `ENV` | 字段 | 核心字段（SPEC-0008 第 3 条，如 `Passed`）与宿主字段 |
| `OUT`、`INOUT` | 附参 2（字段） | 宿主的环境字段表。附参 1 是输出序位，只能写数字 |
| `ANYS` | 转换标识 | 类型名：`Bool` 1、`Byte` 3、`Rune` 4、`Int` 5、`BigInt` 6、`Float` 7、`String` 8、`Bytes` 10（构想层：「用花括号包围成员类型名表达标识」）。0 没有名称 |
| `MATCH` | 附参 1（方式） | `g`、`G`、`f`、`S`，即它们的 ASCII 码值（构想层）。0 没有名称。附参 2 是匹配数量，只能写数字，如 `MATCH{g, 20}` |
| `SYS_TIME` | 条目 | `Stamp`、`Year`、`Month`、`YearDay`、`Day`、`WeekDay`、`Hour`、`Minute`、`Second`、`Millisecond`、`Microsecond`（SPEC-0002 第 6.14 条）。0 没有名称 |
| `FN_HASH224` ～ `FN_HASH512` | 算法 | `blake3` 0、`blake2` 1、`sha2` 2、`sha3` 3（构想层：「算法名称用小写形式」） |
| `MO_*` | 方法 | 该模块的方法表（SPEC-0105）。0（构造方法）没有名称 |
| `EXT_MO` | 模块、方法 | 扩展模块表及其方法表（v1 为空） |
| `FN_X`、`FN_XX` | 函数 | 函数条目表（v1 为空） |

没有名称表的附参只能写数字，例如 `KEYVAL`、`CMPFLO`、`ISEFV`、`SOURCE` 的附参。

### 5. 前缀、局部取值、循环变量与占位符

| 写法 | 指令 |
| --- | --- |
| `@`、`&`、`~`、`_` | 截取前缀（opcode 19、20、23、24），各自是一条独立的指令，通常紧贴其目标书写，如 `@POPS[3]`、`_EVAL`、`@~CALL[2]` |
| `&[n]` | 局部域取值（opcode 21）。`&` 与 `[` 之间不得有空白；写成 `& [0]` 时，是存值前缀后面跟一个不合法的记号 |
| `$Value`、`$Key`、`$Object`、`$Size` | 循环变量（opcode 22，附参依次为 0–3） |
| `<Name>` | 系统占位符（opcode 254）。Name 取自宿主的见证条目表，首字母大写，如 `<Sig>` |

- 文档中的 `<pubKey>`、`DATA{<hashResult>}` 等是「命名数据」的示意（`Design.md`「书写约定」），不是可编译的文本。`<` 后面跟小写字母是编译错误。
- 没有以 `_` 开头的指令字，所以 `_` 后面紧接指令字时，`_` 是前缀，如 `_POP`。

### 6. 块与表达式

#### 6.1 块

块指令（`IF`、`ELSE`、`SWITCH`、`CASE`、`DEFAULT`、`EACH`、`BLOCK`、`MAP`、`FILTER`）写作 `NAME{...}`，花括号内是一层指令序列，长度附参由编译器计算。`MODEL{...}` 与 `?{...}` 的花括号内是模式体（第 7 条）。

#### 6.2 表达式〔R-46〕

表达式写作 `( ... )`，编码为 opcode 80，括号内是表达式体：

- 运算符 `*`、`/`、`%`、`+`、`-` 依次对应 opcode 81–85。
- 操作数可以是任意指令，包括嵌套的 `( ... )`；操作数前面可以有 `~`。
- **数值可以不加花括号**（构想层 `9.运算指令.md`：「数值类指令书写时无需包围花括号」），如 `( POP + 100 )`、`( 100 + POP * 1.5 )`。不加花括号的只是非负的整数与带小数点的浮点，没有符号：`( -100 )` 是一元的 `-` 作用于 100（构想层称之为「单操作数」），编码为 opcode 85 与 Int 100。值为 −100 的 Int 写作 `{-100}`。`Inf`、`-Inf`、−0 与大整数仍写完整形式：`{Inf}`、`{-Inf}`、`{-0.0}`、`B{1024}`。表达式的字面量操作数不能是 BigInt，写在表达式里的 `B{...}` 会在加载期失败（SPEC-0003 第 4 条）；模式体中仍可这样书写。
- **`/` 的判定**：在表达式体内，`/` 总是除号；在表达式体外，`/` 总是开始一个正则字面量。表达式体指 `( ... )` 内的这一层，不包括其中操作数自带的块体、`CODE` 内容或 `RE{}` 的花括号。表达式只做数值运算（构想层），字面量操作数只能是数值，正则不能作为操作数（SPEC-0003 第 4 条「表达式的操作数」），所以这条规则不会丢失可加载的写法。
- `*`、`%`、`+`、`-` 在表达式体外也按运算符编译，因为模式体中可能用到它们（SPEC-0003 第 6 条）。表达式体外的除号与表达式体内的正则无法写出，见第 9.3 条。
- 表达式的文法（SPEC-0003 第 5 条）在加载期检查，编译时不检查。

### 7. 模式文本〔R-47〕

#### 7.1 模式上下文

以下位置是**模式上下文**：`MODEL{...}` 与 `?{...}` 的花括号内，以及其中深匹配的块体与表达式体内。以下位置不是模式上下文：`^` 之后的目标指令的块体（它们作为数据做单匹配，SPEC-0103 第 5.1 条），以及 `CODE{...}` 的内容。

模式指令在任何位置都按下表编译。它们只能出现在模式体内，这条限制属于加载期规则（SPEC-0003 第 4 条）。依赖模式上下文的只有一种写法，即第 7.3 条中省略 `^` 的写法。

| 写法 | 码值 | 说明 |
| --- | --- | --- |
| `.` | 117 | |
| `.[n]` | 118 | n 不能省略 |
| `?{...}` | 119 | `?` 与 `{` 之间不得有空白 |
| `^...` | 120 | 见第 7.3 条 |
| `#[m]` | 121 | 可以写作 `#[1\|2\|4]` |
| `!Type`、`?Type` | 122 | Type 是 SPEC-0103 第 6 条的类型名，见第 7.5 条 |
| `>{lo, hi}`、`>{lo, hi, eps}` | 123、124 | 见第 7.6 条 |
| `RE{...}`、`?RE{...}` | 125 | 见第 7.7 条 |
| `$[n]` | 126 | |
| `...` | 127 | |

`MODEL` 附参中的「有取值」标记由编译器按其模式体计算（SPEC-0003 第 3 条第 7 项）。

#### 7.2 普通指令

模式体内的其它指令按普通文本编译，表示严格匹配或深匹配（SPEC-0103 第 4 条）。

#### 7.3 通配指示 `^`

`^` 有两种写法，不能混用（构想层）。

**嵌入式** `^目标`：目标指令照常书写，但其中可以写 `?`：

- 方括号或别名花括号中的任一附参写作 `?`，表示该附参任意（掩码的 0x01–0x08），如 `^GOTO[2026, ?, 0]`、`^&[?]`；
- 关联数据写作 `{?}`，表示数据任意（0x20），表达式也一样，如 `^()[30]{?}`；
- 紧跟在目标之后的 `?` 表示整个单元可选（0x40）。

补充规则：

- 数据写作 `{?}` 而没有写出给出数据长度的附参时，该附参也任意：`^IF{?}` 即 `^IF[?]{?}`。
- 目标有附参或数据，但两者都不写、只写尾随的 `?` 时，全部附参与数据都任意，且单元可选：`^DATA?` 即 `^DATA[?]{?}?`，`^SHIFT?` 即 `^SHIFT[?]?`。这时不适用第 4.2 条「省略即为 0」的规则。`^&?` 的目标是存值前缀 `&`（opcode 20），它没有附参，所以只表示可选；局部取值要写作 `^&[?]?`（构想层：「附参位不可省略」）。
- `""`、`//` 与 `()` 既是空字符串、空正则、空表达式的写法，也是目标名。它们在 `^` 之后紧接 `[` 或 `{` 时是目标名，如 `^""[50]{?}`、`^//[10]{?}?`、`^()[?]{?}`。上一项的简写不适用于它们：`^""?`、`^//?`、`^()?` 是空字符串、空正则、空表达式，且单元可选。任意的表达式写作 `^()[?]{?}`，更好的写法是类型匹配 `!Expr`；可选时写作 `^()[?]{?}?` 或 `?Expr`（构想层）。字符串与正则同理，用 `!String`、`!RegExp`（SPEC-0103 第 6 条）。
- 不写任何 `?` 的 `^目标`，掩码为 0：单匹配，块体作为数据比较。
- 嵌入式不能表示哈希匹配（0x80）。

**掩码式** `^[m] 目标`：m 是掩码，可以用 `|` 组合；`]` 之后可以有空白。目标的写法如下：

- 掩码中置位的附参不写，其余附参按顺序写出（可以用名称），如 `^[0x02] GOTO[2026, 0]`；
- 0x20 置位时不写数据，如 `^[0x20] DATA[20]`、`^[0x21] DATA`。这时目标之后的 `{`（即使只隔着空白）属于下一条指令；
- 0x80 置位时，数据写作 `{0x` 加 64 个十六进制数字 `}`，即 32 字节的 BLAKE3-256 哈希，如 `^[0x80] DATA[80]{0x4f26…}`、`^[0x81] CODE{0x4f26…}`、`^[0x81] SHELL{0x4f26…}`；
- 目标中不得出现 `?`，也不得有尾随的 `?`（构想层：`^[0x20] DATA[20]?` 不支持，`^[0x81] CODE[?]{…}` 非法）。

**省略 `^`**：在模式上下文中，一条指令的附参或数据中写有 `?` 时，即使前面没有 `^`，也按嵌入式的 `^` 单元编译。构想层的 MODEL 示例 `DATA[32]{?}` 与 `IF{?}` 用的就是这种写法。只有尾随的 `?`、没有其它 `?` 时，必须写出 `^`。

**字面量指令作为目标。** 字面量指令的数据被通配或按哈希匹配时，它的值写不出来，需要用目标名确定码值。有空字面量的类型以空字面量作为目标名：构想层用 `""` 与 `()` 作为字符串与表达式的目标名（`^""[50]{?}`、`^()[30]{?}`），正则同理用 `//`。其余类型没有空字面量，用类型名（与 SPEC-0103 第 6 条的类型名相同）：

| 目标名 | 码值 | 例 |
| --- | --- | --- |
| `Byte`、`Rune`、`Int`、`Float` | 3、4、5、7 | `^Int{?}`、`^[0x20] Int` |
| `BigInt` | 6 | `^BigInt[?]{?}`；`^BigInt[0x83]{?}` 的附参是符号与长度字节 |
| `""` | 8 | `^""[50]{?}` |
| `Values` | 9 | `^Values[12]{?}` |
| `//` | 11 | `^//[10]{?}`、`^//[10]{?}?` |
| `()` | 80 | `^()[30]{?}` |

在掩码式中，`""`、`//`、`()` 用于确定码值。0x20 置位时数据不写，它们只表示码值，例如 `^[0x21] //`；0x20 与 0x80 都不置位时，它们同时给出空数据，例如 `^[0x40] //` 与 `^//?` 相同，是空正则且可选。

数据给出时，按字面量的常规写法书写：`^{123}?`、`^'A'?`、`^'\u0041'`。`^{?}` 是编译错误，因为它不能确定码值，应写作 `^Int{?}` 等。

#### 7.4 取值 `#[m]` 与 `$[n]`

`#[m]` 写在它的单元之后，以空白分隔，例如 `^DATA[20]{?} #[32]`、`^GOTO[?,?,?] #[1|2|4]`。`$[n]` 同样写在其 RE 单元之后。

#### 7.5 类型 `!Type` / `?Type`

类型名取自 SPEC-0103 第 6 条的表：`Nil`、`Bool`、`Byte`、`Rune`、`Int`、`BigInt`、`Float`、`String`、`Values`、`Bytes`、`RegExp`、`Time`、`Dict`、`Script`、`Loops`、`Number`、`Intes`、`Char`、`Expr`、`Model`。

#### 7.6 范围 `>{}`

- 两个元素是整数范围（opcode 123），如 `>{0, 1024}`，元素为 int64 范围内的整数。
- 三个元素是浮点范围（opcode 124），如 `>{0, 1.0, 0}`、`>{0.1, 10, 1e-10}`、`>{0, Inf, 0}`、`>{-Inf, 0, 0}`。lo 与 hi 可以写成整数、带小数点的数、只带指数的数（构想层的 `1e-10`），或无穷 `Inf`、`+Inf`、`-Inf`。`Inf` 与 `+Inf` 是 +Inf，`-Inf` 是 −Inf，中间不能有空白。eps 不能是无穷，只能是整数、带小数点的数或带指数的数。两个元素的整数范围里出现 `Inf`，是编译错误。
- lo、hi 的有限写法舍入到最近的 binary64，eps 舍入到最近的 binary32。舍入结果必须是有限值；过大的数不能借舍入变成无穷，要写无穷只能用上一款的 `Inf`。结果为 −0 时写成 +0。这与浮点字面量不同：字面量保留 −0（第 3.2 条），范围的上下界与误差仍不编码 −0（SPEC-0003 第 3 条第 4 项），因为范围比较把 −0 与 +0 视为相等。`>{-Inf, Inf, 0}` 合法：−Inf < +Inf。下界写成 +Inf，或上界写成 −Inf，编码之后不满足 lo < hi，加载失败（SPEC-0103 第 12 条）。

#### 7.7 正则匹配 `RE{}`

```
RE{ [目标] 正则 方式 }      ?RE{ ... }
```

- 目标：指令字（如 `DATA`、`CODE`、`IF`），或者码值（十进制或 `0x` 十六进制，如 `8`）。省略时为 `0xFF`，表示任意指令（构想层：「可以用命名指令的名称，也可以用数字直接指定指令码」）。
- 正则：`/.../`（第 3.6 条）。
- 方式：`g`、`G`、`f`、`S` 之一，必须写出。
- 各部分之间可以有空白。例：`RE{8/(?i)([a-z]+):(\d+)/S}`、`RE{DATA/\d+/g}`、`?RE{/(?i)[a-z]+/f}`。

### 8. 原始数据写法〔R-48〕

往返性质要求每一段可加载的字节码都有文本形式（第 1 条）。字面量的数据总能写出：正则与 `SHELL` 的数据由加载期规则保证（SPEC-0003 第 3 条第 8、12 项），字符串、`DATA` 等有转义或十六进制。代码类的数据则不然：`CODE` 的数据在加载时不校验，模式体允许不完整的结构，`^` 单匹配目标的块体是任意字节，其中可能有不能解码或写不出的内容（第 9.3 条）。原始数据写法只为这类数据而设。

下列指令的数据可以写作 `{0x` 加十六进制数字 `}`，表示数据的字节就是这些，不再按指令文本解释。十六进制数字之间可以有空白和 `_`。

| 写法 | 何时需要 |
| --- | --- |
| `CODE{0x...}` | `CODE` 的数据不能写成指令文本（第 9.3 条） |
| `IF{0x...}` 等块指令、`(){0x...}`、`?{0x...}`、`MODEL[n]{0x...}` | 块体、表达式体或模式体中有写不出的内容（第 9.3 条），或 `^` 单匹配的块体不能写成指令文本 |
| `DATA{0x...}` | 与 `DATA{...}` 相同 |

- 数据长度附参按字节数计算。`MODEL` 的原始写法必须写出附参（第 4.2 条），因为编译器不解码原始数据，无法计算「有取值」标记。
- 在掩码式 `^[m]` 中 0x80 置位时，`{0x...}` 是哈希（第 7.3 条），不是原始数据。
- 原始数据写法只改变书写，不改变字节，也不豁免加载期校验。例如 `IF{0x...}` 的块体照常按代码解码与校验。

### 9. 规范反编译〔R-49〕

#### 9.1 原则

- 规范文本是 UTF-8 文本（构想层：「反编译解码也输出 UTF-8 文本」）。字面量中合法的非 ASCII 字符原样写出，例如 `"你好"`、`'嗨'`、`/(?i)名称/`。
- 字符串与字符字面量中，**需转义的码点**一律转义，以免把不可见字符或方向控制字符显示给审阅者。需转义的码点是下面这张固定的表，不随 Unicode 的版本变化，所以反编译不依赖 Unicode 字符表：
  - `U+0000`–`U+001F`、`U+007F`–`U+009F`（C0、DEL、C1 控制字符）；
  - `U+00AD`、`U+061C`、`U+180E`；
  - `U+200B`–`U+200F`、`U+2028`–`U+202E`、`U+2060`–`U+2064`、`U+2066`–`U+206F`（零宽字符、行与段分隔符、方向控制字符）；
  - `U+FEFF`、`U+FFF9`–`U+FFFB`。
- 正则与 `SHELL` 没有转义，数据原样写出。其中的不可见字符由工具在显示时提示，不属于规范文本。
- 每条指令只有一种规范写法（第 9.2 条），排版也是确定的（第 9.4 条）。工具可以另外提供其它显示形式，但它们不是规范反编译。

#### 9.2 写法

| 内容 | 规范写法 |
| --- | --- |
| Byte | `0x20`–`0x7E` 中除 `'` 与 `\` 以外的字节写作 `'c'`；`'` 与 `\` 写作 `'\''`、`'\\'`；其余写作 `'\xhh'` |
| Rune | 码点不小于 `0x100`、且不是需转义的码点（第 9.1 条）的，原样写作 `'c'`，如 `'嗨'`；其余不大于 `0xFFFF` 的写作 `'\uhhhh'`，否则写作 `'\Uhhhhhhhh'`。码点小于 `0x100` 的 Rune 必须用 `\u`，原样写出会编译成 Byte（第 3.1 条） |
| Int | `{十进制}`，负数带 `-` |
| BigInt | 绝对值 ≤ 2⁶³ 时 `B{十进制}`，否则 `B{0x十六进制}`。负数的符号在花括号内，如 `B{-1024}`、`B{-0x8000ffff8000ffff8001}`。十六进制小写，无分隔 |
| Float | `{x}`，x 按第 9.2.1 条 |
| 字符串 | 解释型字符串。`0x20`–`0x7E` 中除 `"` 与 `\` 以外的字节原样写出；`"`、`\`、LF、CR、TAB 写作 `\"`、`\\`、`\n`、`\r`、`\t`；其余 ASCII 字节（其它控制字符与 `0x7F`）写作 `\xhh`。非 ASCII 字节中，构成合法 UTF-8 编码的原样写出，但需转义的码点（第 9.1 条）写作 `\uhhhh`；不构成合法 UTF-8 编码的逐字节写作 `\xhh` |
| 值集 | `{m1, m2}`，逗号后一个空格；只有一个成员时写作 `{m,}`。成员按本表各行的写法。整数与有限浮点不加花括号；BigInt 仍写 `B{...}`；+Inf 写 `Inf`，−Inf 写 `-Inf` |
| `DATA` | `DATA{hex}`；空数据写作 `DATA{}` |
| 正则 | `/数据/`，数据原样写出（第 3.6 条），如 `/a\/b/`、`/[\/]/` |
| `DATE` | 时刻在 0000–9999 年之内时写作 `DATE{YYYY-MM-DDTHH:MM:SSZ}`，毫秒不为 0 时在秒之后加 `.mmm`；否则写作 `DATE[ms]` |
| `CODE` | 数据能按第 9.3 条写成指令文本时写作 `CODE{...}`，否则写作 `CODE{0x...}` |
| `SHELL` | 定界写法（第 3.9 条）：`SHELL{`、n 个 `<`、换行（LF）、数据、n 个 `>`、`}`。数据原样输出。n 取使数据中不含「n 个 `>` 紧跟 `}`」的最小正整数：设 k 为数据中紧跟 `}` 的 `>` 序列的最大长度（没有则为 0），n = k + 1 |
| 附参 | 取值有名称的写名称别名（第 4.3 条），同一指令的其余附参写数字；否则，取值为 0 且可以省略的（第 4.2 条），省略；其余写在方括号中。`MATCH` 的附参 2 为 0 时省略，例如 `MATCH`、`MATCH{f}`、`MATCH{g}`、`MATCH{G, 3}` |
| 数字 | 十进制。例外：`^[m]`、`#[m]` 的掩码与 `SOURCE` 的标识写作 `0x` 加两位十六进制；`bytes(N)` 写作 `0x` 加 2N 位十六进制 |
| 长度类附参 | 不写。例外：`^` 目标中必须写出的长度，以及 `MODEL` 的原始写法 |
| 前缀 | 紧贴目标，如 `@POPS[3]`、`@~CALL[2]` |
| `^` 单元 | 用嵌入式，写出目标的全部附参（包括取值为 0 的）与数据，不用 `^DATA?` 这类简写；0x40 用尾随的 `?` 表示。嵌入式不能表示该掩码时，用掩码式。这些情形是：含 0x80 或 0x10，置位了目标没有的附参，目标没有数据却置位 0x20，长度附参任意而数据不任意（第 7.3 条） |
| `^` 目标中的字面量 | 数据给出时用常规写法；否则用第 7.3 条的目标名，其中字符串用 `""`、正则用 `//`、表达式用 `()` |
| 范围 | `>{lo, hi}` 用十进制；`>{lo, hi, eps}` 的有限元素用 Float 的写法（第 9.2.1 条），eps 取能还原该 binary32 的最短十进制。+Inf 写作 `Inf`，−Inf 写作 `-Inf` |
| `RE` | 目标为 `0xFF` 时省略；码值有指令字时写指令字，否则写十进制码值（如 `8`）；正则同上。各部分之间不加空白，如 `RE{DATA/\d+/g}` |
| 十六进制 | 一律小写，不加 `_` |

**9.2.1 Float 的写法。** −0 写作 `-0.0`。+Inf 写作 `Inf`，−Inf 写作 `-Inf`；不用 `FormatFloat` 对无穷给出的 `+Inf`。其余有限值：先取能还原该 binary64 的最短十进制数字串，它与 Go `strconv.FormatFloat(x, 'e', -1, 64)` 给出的数字相同，记为 d₁.d₂…dₙ × 10ᴱ。−6 ≤ E ≤ 20 时写成定点形式，至少保留一位小数，如 `123.0`、`0.001`、`3.14159`。其余情形写成 `d₁.d₂…dₙe±E`，尾数至少一位小数，指数不补零，如 `1.0e+21`、`1.5e-7`。+0 写作 `0.0`。binary32 的 eps 按同样的方法书写，只是最短数字串按 binary32 计算；eps 没有 −0 与无穷（SPEC-0003 第 3 条第 4 项），范围元素中的 −0 已在编译时写成 +0（第 7.6 条）。因此 `{+Inf}` 的规范文本是 `{Inf}`，`{-0.0}` 的规范文本是 `{-0.0}`。`>{0, Inf, 0}` 的规范文本是 `>{0.0, Inf, 0.0}`，`>{-Inf, 0, 0}` 的规范文本是 `>{-Inf, 0.0, 0.0}`。

**表达式体内的数值。** 非负的 Int 与符号位为 0 的有限 Float 不加花括号，如 `( POP + 100 )`、`( POP + 1.5 )`。负值与 −0 加花括号，如 `( POP + {-100} )`、`( POP + {-0.0} )`。±Inf 写作 `{Inf}`、`{-Inf}`。BigInt 总是 `B{...}`，如 `( POP + B{1024} )`。可加载的表达式不能以 BigInt 为字面量操作数（SPEC-0003 第 4 条）；模式体中的这种写法仍按本款反编译。

#### 9.3 写不出的内容与回退

按第 6.2 条的 `/` 判定，只有两种内容不能写成指令文本：位于表达式体外的除号（opcode 82），它会被读成正则的开始；以及直接位于表达式体内的正则（opcode 11），它的 `/` 会被读成除号。

一层指令序列中出现写不出的内容时，包含它的最内层指令（其数据长度由附参给出）改用原始数据写法（第 8 条）。在可加载的段中，这只可能发生在模式体内或 `CODE` 的数据中：段的顶层与普通块体受加载期结构规则的约束，运算符号只能位于表达式体内，表达式的字面量操作数只能是数值（SPEC-0003 第 4 条），不会出现上述情形。

`CODE` 的数据，以及 `^` 单匹配目标的块体，满足以下两项才能写成指令文本：按 SPEC-0003 第 3 条的规范解码规则在版本 v 下解码成功；其中没有写不出的内容。否则用原始数据写法。

#### 9.4 排版

1. 缩进单位为 4 个空格。每行以 LF 结束，行尾没有空格（`SHELL` 的数据原样输出，不受此限）。非空的文本以 LF 结尾；空段的文本是空串。
2. 一层指令序列按顺序放入行中，同一行内的指令以一个空格分隔。以下几种组合视为一体，中间不换行：前缀与其目标；`#[m]`、`$[n]` 与其前一个单元。
3. **行尾指令**（构想层「指令码的解译显示」）之后换行：`PASS`、`CHECK`、`EMBED`、`EXIT`、`RETURN`、`END`、`BREAK`、`CONTINUE`、`SYS_CHKPASS`。
4. **块**：块指令、`MODEL`、`?{}`，以及写成指令文本的 `CODE` 与 `^` 单匹配目标。块体非空时，写作 `NAME{`，换行，块体缩进一级，换行，在原缩进处写 `}`，然后换行。块体为空时写作 `NAME{}`，不强制换行。
5. **行长**：行长按码点计数，缩进计入。如果把下一条指令加到当前行会使这一行超过 80 个字符，并且当前行不为空，先换行。超过 80 个字符的单条指令独占一行。构想层的「独行指令」（长的 `DATA`、大整数、正则）由这条规则实现。
6. 表达式、值集、范围、`RE{}` 与原始数据写法总在一行内写出。表达式的括号内侧各留一个空格，如 `( POP + 100 )`；空表达式写作 `()`。
7. `SHELL{` 与 n 个 `<` 之后换行，然后原样输出数据，紧接着写 n 个 `>` 与 `}`，然后换行。数据不以换行结尾时，结束定界符紧跟在数据的最后一个字符之后，不另起一行。

### 10. 编译错误

以下情形是编译错误，不产生字节码：

- 词法错误：不合法的 UTF-8；非法字符；未结束的字符串、字符字面量、正则（包括内容中出现换行或回车）、多行注释或花括号；数字写法不合法。
- `SHELL` 的 `{` 之后既不是定界写法，也不是数据通配或掩码式中的哈希，包括 `<` 之后不是换行，以及 `{` 与 `<` 之间有空白；定界写法没有结束定界符（第 3.9 条）。
- 未知的指令字、名称、类型名或目标名。
- 附参个数不符；取值超出类型范围；`|` 用于有符号的附参；`bytes(N)` 的长度不符。
- 字面量的值不合法：Rune 不是 Unicode 标量值；花括号整数超出 int64；BigInt 的绝对值达到 2¹⁰¹⁶，或写成负零；浮点数字舍入后不是有限值；写成 NaN；浮点范围的数值元素舍入后不是有限值，或 eps 写成无穷，或整数范围里出现 `Inf`；`DATE` 的文本不合法或超出范围；`DATA` 的数字个数为奇数，或者超过 `[L]`；正则的数据（处理转义之后）超过 255 字节。
- 长度超出附参的容量：表达式体超过 255 字节，模式体超过 32767 字节。
- 写出的长度附参与计算值不符（`DATA` 除外）。
- `?` 出现在 `^` 单元之外（模式上下文中省略 `^` 的写法除外）；嵌入式与掩码式混用。
- `MODEL` 的原始写法没有写出附参，或者写出的附参与数据长度不符。
- 需要关联数据的指令没有写数据（第 11.8 条第 4 项的例外除外）。

编译错误的诊断信息（位置、原因）不受本规格约束。

### 11. 附：文法（EBNF）

#### 11.1 记法与适用范围

- 记法同 SPEC-0003 第 5 条：`=` 表示定义，`|` 表示选择，`[ x ]` 表示可选，`{ x }` 表示零次或多次，`( )` 表示分组，并列即连接。终结符写在双引号中，`'"'` 表示双引号字符本身。另外：`n * x` 表示 x 恰好重复 n 次；`x - y` 表示属于 x 而不属于 y；`"a" … "z"` 表示码点区间；`? … ?` 是用文字说明的字符集合；`(* … *)` 是注释。
- 本条汇总第 2 ～ 8 条的文本形式：哪些字符序列构成文本，以及它们怎样分成指令。取决于格式表、名称表与上下文的约束不在文法中表达，见第 11.8 条。
- 文法与正文描述同一种语言。两者有出入时以正文为准，并修订本条。

#### 11.2 字符、空白与注释

```
char          = ? 任一 Unicode 标量值 ?
lf            = ? U+000A ?
cr            = ? U+000D ?
ws-char       = " " | ? U+0009 ? | lf | cr
sp            = { ws-char }                         (* 指令内部可以有空白之处 *)
gap           = { ws-char | comment }               (* 指令之间 *)
comment       = "<|" { char - lf }
              | "<<" ? 不含 ">>" 的 char 序列 ? ">>"

upper         = "A" … "Z"
letter        = upper | "a" … "z"
digit         = "0" … "9"
nz-digit      = "1" … "9"
hex-digit     = digit | "a" … "f" | "A" … "F"
oct-digit     = "0" … "7"
bin-digit     = "0" | "1"
word          = letter { letter | digit | "_" }
```

#### 11.3 指令序列

```
segment       = code-seq
code-seq      = gap { instr gap }
pattern-seq   = gap { ( instr | implicit-unit ) gap }
expr-body     = gap { ( instr | number | "/" ) gap }   (* number 不带符号；"/" 是除号，instr 不含 regex-lit，见第 11.8 条第 7 项 *)
```

#### 11.4 指令

```
instr         = prefix | local-get | loop-var | placeholder
              | literal | data-instr | block-instr | expression | operator
              | pattern-instr | plain-instr

prefix        = "@" | "&" | "~" | "_"
local-get     = "&[" sp ( "?" | [ "-" ] integer ) sp "]"
loop-var      = "$Value" | "$Key" | "$Object" | "$Size"
placeholder   = "<" upper { letter | digit | "_" } ">"
operator      = "*" | "%" | "+" | "-"

plain-instr   = word [ aux | alias ]
aux           = "[" sp [ aux-item { sp "," sp aux-item } sp ] "]"
aux-item      = "?" | [ "-" ] integer { sp "|" sp integer }
alias         = "{" sp alias-item { sp "," sp alias-item } sp "}"
alias-item    = "?" | integer | word [ "." word ]
```

#### 11.5 字面量

```
literal       = char-lit | number-lit | bigint-lit | value-set | string-lit | regex-lit

char-lit      = "'" ( char - ( "'" | "\" | lf ) | rune-esc ) "'"
rune-esc      = "\" ( "a" | "b" | "f" | "n" | "r" | "t" | "v" | "\" | "'" ) | byte-esc | uni-esc
string-lit    = '"' { char - ( '"' | "\" | lf ) | str-esc } '"'
              | "`" { char - "`" } "`"
str-esc       = "\" ( "a" | "b" | "f" | "n" | "r" | "t" | "v" | "\" | '"' ) | byte-esc | uni-esc
byte-esc      = "\x" 2 * hex-digit | "\" 3 * oct-digit
uni-esc       = "\u" 4 * hex-digit | "\U" 8 * hex-digit

number-lit    = "{" sp ( [ sign ] number | inf ) sp "}"
bigint-lit    = "B" "{" sp [ sign ] big-int sp "}"
sign          = "+" | "-"
inf           = [ "+" ] "Inf" | "-" "Inf"
number        = integer | float
integer       = dec-int
              | "0" ( "x" | "X" ) [ "_" ] hex-digit { [ "_" ] hex-digit }
              | "0" ( "o" | "O" ) [ "_" ] oct-digit { [ "_" ] oct-digit }
              | "0" ( "b" | "B" ) [ "_" ] bin-digit { [ "_" ] bin-digit }
big-int       = dec-int
              | "0" ( "x" | "X" ) [ "_" ] hex-digit { [ "_" ] hex-digit }
              | "0" ( "o" | "O" ) [ "_" ] oct-digit { [ "_" ] oct-digit }
              | "0" ( "b" | "B" ) [ "_" ] bin-digit { [ "_" ] bin-digit }
dec-int       = "0" | nz-digit { [ "_" ] digit }
float         = dec-int "." [ digits ] [ exponent ]
digits        = digit { [ "_" ] digit }
exponent      = ( "e" | "E" ) [ sign ] digits

value-set     = "{" sp member sp "," sp [ member sp { "," sp member sp } [ "," sp ] ] "}"
member        = "TRUE" | "FALSE" | char-lit | [ sign ] number | inf | bigint-lit | string-lit

regex-lit     = "/" { char - ( "/" | "\" | lf | cr ) | "\" ( char - ( lf | cr ) ) } "/"
                                                    (* 内容原样作为数据，"\" 与其后的字符成对保留，见第 3.6 条 *)
raw           = "0x" { hex-digit | "_" | ws-char }
```

#### 11.6 带数据的指令、块与表达式

```
data-instr    = "DATA" [ aux ] [ sp "{" sp ( hex-data | "?" ) sp "}" ]
              | "DATE" ( [ sp "{" sp ( rfc3339 | "?" ) sp "}" ] | "[" sp [ "-" ] integer sp "]" )
              | "CODE" [ aux ] [ sp "{" ( code-seq | sp ( raw | "?" ) sp ) "}" ]
              | "SHELL" [ aux ] [ sp "{" ( shell-text | sp ( raw | "?" ) sp ) "}" ]
hex-data      = [ "0x" ] { hex-digit | "_" | ws-char }
rfc3339       = 4 * digit "-" 2 * digit "-" 2 * digit "T" 2 * digit ":" 2 * digit ":" 2 * digit
                [ "." digit [ digit [ digit ] ] ] ( "Z" | sign 2 * digit ":" 2 * digit )
shell-text    = shell-open shell-body shell-close
shell-open    = "<" { "<" } ( lf | cr lf )
shell-body    = { char }
shell-close   = ">" { ">" }                         (* 个数等于 shell-open 的 "<"，其后紧跟 "}"；见第 11.8 条第 10 项 *)

block-instr   = block-word [ aux ] [ sp "{" ( code-seq | sp ( raw | "?" ) sp ) "}" ]
              | "MODEL" [ aux ] [ sp "{" ( pattern-seq | sp ( raw | "?" ) sp ) "}" ]
block-word    = "IF" | "ELSE" | "SWITCH" | "CASE" | "DEFAULT" | "EACH" | "BLOCK" | "MAP" | "FILTER"

expression    = "(" expr-body ")"
              | "()" [ aux ] "{" sp raw sp "}"
```

#### 11.7 模式指令

```
pattern-instr = "..." | "." | ".[" sp integer sp "]"
              | "?{" ( pattern-seq | sp raw sp ) "}"
              | "#[" sp mask sp "]"
              | "$[" sp integer sp "]"
              | ( "!" | "?" ) word
              | range | re-unit | wildcard-unit
mask          = integer { sp "|" sp integer }
range         = ">{" sp range-elem sp "," sp range-elem [ sp "," sp range-elem ] sp "}"
range-elem    = [ sign ] ( integer | float | dec-int exponent | "Inf" )
re-unit       = [ "?" ] "RE{" sp [ ( word | integer ) sp ] regex-lit sp re-mode sp "}"
re-mode       = "g" | "G" | "f" | "S"

wildcard-unit = "^" target [ "?" ]
              | "^[" sp mask sp "]" sp target
target        = target-name [ aux ] [ "{" sp ( "?" | raw ) sp "}" ]
              | instr
target-name   = "Byte" | "Rune" | "Int" | "Float" | "BigInt" | "Values"
              | '""' | "//" | "()"
implicit-unit = instr [ "?" ]
```

#### 11.8 文法之外的规则

1. **单词的分类。** `word` 按所在位置查表，查不到即为编译错误：
   - `plain-instr` 中：版本 v 的格式表中的指令字（第 4.1 条），但不包括 `DATA`、`DATE`、`CODE`、`SHELL`、`MODEL`、`RE` 与块指令字，它们只按第 11.6、11.7 条的产生式书写；
   - `alias` 中：名称表（第 4.3 条）；
   - `!`、`?` 之后：类型名（第 7.5 条）；
   - `re-unit` 的目标：指令字。
2. **记号的切分**（第 2 条）。按最长匹配，因此：
   - `...` 先于 `.`；`.[`、`&[`、`#[`、`$[`、`^[`、`>{`、`?{`、`?RE{`、`()` 各是一个记号；`?` 紧接字母时，与其后的单词一起构成 `?Type` 或 `?RE{`。所以尾随的 `?` 之后如果是 `{` 或字母，中间要有空白；
   - `B` 紧接 `{`（中间无空白）是 `bigint-lit`，不是指令字；
   - `gap` 为空的两条相邻指令，不得能连成一个更长的记号，例如两个相邻的指令字；
   - 只有 `gap` 中的 `<|`、`<<` 是注释的开始。在字面量、方括号与花括号之内，它们是普通字符。
3. **附参。** `aux` 的项数、各项的类型与取值范围、长度类附参与省略规则，见第 4.2 条与格式表：`|` 只用于无符号附参；`bytes(N)` 写作恰好 2N 位的十六进制数字；`HostRef` 按宿主声明的字段序列书写。`plain-instr` 只有在格式表给出附参时才能带 `aux`，只有附参有名称表时才能带 `alias`。
4. **数据的归属。** `data-instr` 与 `block-instr` 在文法中把数据写成可选，实际规则是：这些指令之后（可以隔空白）的 `{` 总是它的数据，没有数据就是编译错误。例外只在 `^` 单元的目标中：嵌入式的简写（如 `^DATA?`）与掩码式中 0x20 置位时不写数据，这时目标之后的 `{` 属于下一条指令（第 7.3 条）。`target-name` 与 `()` 的数据必须紧接，中间不能有空白。
5. **通配写法。** `aux-item`、`alias-item` 与数据中的 `?`、`target-name`，以及目标之后的 `?`，只能出现在 `^` 单元的目标中，或模式上下文的省略式单元中（第 7.3 条）。具体来说：
   - 掩码式的目标中不得有 `?`；
   - `implicit-unit` 的 `instr` 中至少要有一处通配写法；只有尾随的 `?` 时，必须写出 `^`；
   - 目标名之后的 `raw`：掩码式中 0x80 置位时是哈希；其它情形只能跟在 `()` 之后，是表达式的原始写法（第 8 条）。其余字面量的数据给出时，按常规写法书写，如 `^"abc"`、`^/\d+/`。
6. **模式上下文**（第 7.1 条）。在 `MODEL` 与 `?{}` 的 `pattern-seq` 中，块指令的块体也按 `pattern-seq` 解析，`expr-body` 的成员也可以是 `implicit-unit`，并逐层传递。`^` 的目标与 `CODE` 的内容回到代码上下文。
7. **`/` 的判定**（第 6.2 条）。直接位于 `expr-body` 中的 `/` 总是除号（文法中单列的 `"/"`），所以 `expr-body` 的 `instr` 不会是 `regex-lit`；在 `expr-body` 之外（包括操作数自带的块体、`CODE` 内容与 `RE{}` 的花括号内），`/` 总是开始 `regex-lit`。
8. **`""`、`//` 与 `()`**（第 7.3 条）。在嵌入式的 `target` 中，`""`、`//`、`()` 紧接 `[` 或 `{` 时是 `target-name`，否则（包括紧接尾随的 `?`）是空字符串、空正则、空表达式。在掩码式中，它们给出码值，数据是否写出由掩码决定（第 7.3 条）。在 `target` 之外，`()` 紧接 `[` 或 `{` 时是表达式的原始写法（第 8 条）。
9. **取值的约束**（第 3、10 条）。包括：转义与码点决定的字符类型，Rune 必须是标量值；花括号整数必须在 int64 内，超出须写 `B{}`；BigInt 的范围与负零；Float 可以写 `Inf` 与 −0，不能写 NaN，数字舍入后必须有限；浮点范围的 `Inf` 只用于上下界，eps 与整数范围不能写它，范围元素舍入为 −0 时写成 +0（第 7.6 条）；`hex-data` 与 `raw` 中十六进制位的个数为偶数；`rfc3339` 的日期与时间合法；正则不超过 255 字节；长度不超出附参的容量。
10. **`SHELL` 的数据**（第 3.9 条）。`{` 之后紧跟 `<` 时是 `shell-text`；否则按 `raw` 或 `?` 处理（`{` 之后可以有空白）：`raw` 只能是掩码式中 0x80 置位时的哈希，`?` 是数据通配，只能用于 `^` 单元（第 5 项）。`SHELL` 没有原始数据写法。
    - `shell-open` 中 `<` 的个数记为 n，`shell-close` 恰好是 n 个 `>`，其后紧跟的 `}` 是本指令的 `}`。
    - `shell-text` 止于第一个「n 个 `>` 紧跟 `}`」的位置：这 n 个 `>` 是 `shell-close`，它们之前的字符（包括紧挨着的 `>`）都属于 `shell-body`。所以 `shell-body` 中没有「n 个 `>` 紧跟 `}`」的序列，但可以含有 `{`、`}`、`<`、`>` 与更短的 `>` 序列。
    - 数据是 `shell-body` 的原样字节，没有转义；`shell-open` 的换行不属于数据。


## 边界与限制

- 文本不进入共识，也不是测试向量中的权威部分：向量以字节码为准，文本只供对照（SPEC-0202）。
- 本篇不定义值在运行时的文本形式（`STRING`、`PRINT`、`FN_PRINTF` 的输出），见 SPEC-0102 与 SPEC-0106。
- 别名表随版本与宿主而变。没有宿主配置时，宿主字段与见证条目没有名称，`HostRef` 与占位符也无法编译；核心测试使用测试宿主（SPEC-0202 第 6 条）。
- DEC-0002 所说「反编译器不需要知道宿主是谁」指码位的识别：码位不按宿主划分。`HostRef` 的形状〔R-04〕与名称别名仍取自宿主配置，它们只是数据表，不改变反编译的规则。
- 规范文本保证往返，但不保证与作者手写的文本相同：注释、空白、名称与数字的选择、省略 `^` 的写法等都会被规范化。
- 正则与 `SHELL` 的数据原样输出，其中可能有不可见字符或方向控制字符。规范文本不对它们做转义；提示审阅者是显示工具的责任（第 9.1 条）。

## 对 Plan 的约束

- 编译器与反编译器共用 SPEC-0002 的格式表与各取值表（含名称），不另行维护指令清单。
- 「编译(反编译(S)) = S」作为性质测试：向量集中所有可加载的段，以及随机生成后能通过加载的段，都必须满足。
- 编译器应在编译之后按段的种类做加载期校验，把加载失败作为警告或错误报告给用户。
- 文本向量（SPEC-0202 第 3.3 条）至少覆盖：
  - 构想层中可以编译的全部示例；
  - 每一种回退：`CODE{0x}`、块指令、`(){0x}`、`?{0x}` 与 `MODEL` 的原始写法，包括模式体中表达式体外的除号与表达式体内的正则；
  - `SHELL` 的定界写法（第 3.9 条）：n 取 1、2、3；数据含 `>}`、`>>}`；数据以 `>` 结尾；数据以换行开头、以换行结尾、不以换行结尾、为空；`>` 多于 n 个时多出的属于数据（`a>>>}`）；规范反编译取最小的 n；数据含非 ASCII 字符（构想层的示例）与控制字符时原样输出；编译错误：`<` 之后不是换行、`{` 与 `<` 之间有空白、没有结束定界符、`{` 之后是普通文字、`SHELL{0x…}` 不在掩码式中；
  - 正则的扫描（第 3.6 条）：`\/`、`\\`、`\d` 都原样成为数据；`/\\/` 的数据是 `\\`；`/\\\//` 的数据是 `\\\/`；`/[/]/` 是编译错误；含非 ASCII 字符；内容含换行是编译错误；加载失败：数据含不成对的 `/`、以单独的 `\` 结尾；
  - `/` 的判定：表达式体内总是除号，表达式体外总是正则，以及表达式操作数自带的块体内是正则；
  - 字符字面量的 Byte / Rune 选择，以及 Rune 的规范写法（码点 `0xFF`、`0x100`，需转义的码点）；
  - 字符串的规范写法：合法的非 ASCII 原样输出；需转义的码点（如 `U+202E`、`U+FEFF`、`U+0085`）写作 `\u`；不合法的 UTF-8 字节写作 `\x`；
  - 含非 ASCII 字符的行按码点计算行长；
  - Int 与 BigInt 的边界：`{9223372036854775807}` 为 Int，`{9223372036854775808}` 是编译错误；`B{1024}` 与 `{1024}` 的字节码不同；`B{9223372036854775807}`、`B{9223372036854775808}`、`B{-9223372036854775808}` 的规范写法是十进制，`B{9223372036854775809}` 规范为十六进制；`B{-0}` 是编译错误；
  - Float 的两种写法及其边界（E 为 −6、−7、20、21）；`{-0.0}`、`{-1e-400}` 编译为 −0，规范文本是 `{-0.0}`；`{0.0}`、`{+0.0}` 为 +0；`{Inf}`、`{+Inf}`、`{-Inf}` 编译为 ±Inf，`+Inf` 的规范写法是 `{Inf}`；`{NaN}` 与舍入成无穷的数是编译错误；浮点范围的 `>{0, Inf, 0}`、`>{-Inf, 0, 0}`、`>{-Inf, Inf, 0}`；eps 为 `Inf`、整数范围里的 `Inf`、舍入成无穷的范围元素是编译错误；范围元素舍入为 −0 时编译为 +0；
  - `DATE` 的年份边界；
  - `^` 的嵌入式、掩码式与省略 `^` 的写法；
  - 每一类编译错误；
  - 第 11.8 条的每一项，尤其是掩码式 0x20 之后的 `{`；`^""?`、`^//?`、`^()?` 是空字面量且可选，与 `^""[?]{?}?`、`^//[10]{?}?`、`^()[?]{?}?` 的区别；`^//[10]?` 缺少数据是编译错误；`^[0x21] //`；尾随 `?` 之后紧接 `{` 的切分。
- 编译器的词法与语法分析按第 11 条实现；文法之外的规则（第 11.8 条）集中在一处，按格式表与名称表检查。
