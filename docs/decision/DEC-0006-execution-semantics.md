# DEC-0006 执行语义：通关状态、执行上下文、表达式求值

- 状态：Accepted
- 日期：2026-10-28
- 覆盖评审条目：P0-1、P0-2、P1-3、P1-4（Q2–Q5、Q13、Q16）


## 背景

构想层已经确定了几条基本原则：

- 默认可自由通行：初始通关状态为「未决」，执行完毕仍未决则通过（P0-1）；
- PASS 与 CHECK 共用同一个通关状态（P0-2）；
- 子脚本的 `PASS(true)`、`CHECK(false)` 只属于子脚本自身，只有 `PASS(false)` 会透传（Q2）；
- EVAL 是封闭环境，内部的 `PASS(false)`、`END` / `INPUT` 不影响调用者，内部错误向外传递（Q3）。

这些规则分散在多条指令的说明里。Spec 需要一个统一的状态机，以及一张「执行上下文 × 结束方式」的表，才能写到可实现的精度。

这条原则还有一个推论：既然默认通过，安全性就完全取决于「锁定脚本被完整、按原意执行」。凡是能让花费者提前结束锁定脚本、或改变其语义的机制，都会直接变成放行漏洞。下面的规则都以此为准绳。


## 决策

### 1. 脚本域与通关状态机

**脚本域**是拥有自己的数据栈、实参区、全局变量区和通关状态的执行单位：

- 顶层：解锁脚本 + 锁定脚本，共一个脚本域（两段之间的边界规则见 DEC-0003）；
- 每个 `GOTO` 目标脚本：一个新的脚本域；
- 每次 `EVAL`：一个独立的执行环境，结构与脚本域相同。

`EMBED` 的代码、`MAP` / `FILTER` 的体都不是独立的脚本域，它们读写所在脚本域的通关状态。

每个脚本域的通关状态有三个值：**未决**（初始）、**通过**、**未通过**。

| 事件 | 效果 |
| --- | --- |
| `PASS(true)`、`CHECK(true)`、`SYS_CHKPASS` 成功 | 当前脚本域置为「通过」，继续执行 |
| `CHECK(false)` | 当前脚本域置为「未通过」，继续执行 |
| `PASS(false)`、`SYS_CHKPASS` 失败、运行错误 | **否决**：立即结束，见第 2 条 |
| 顶层正常结束（执行完毕、`EXIT`、公共节点上的 `END` / `INPUT`） | 顶层状态为未决或通过，验证通过；为未通过，验证失败 |

- 解锁段发生的错误一律失败，不适用「未决即通过」（构想层：锁定脚本必须已经开始执行）。
- `ENV{Passed}` 读取当前脚本域的状态：未决与通过返回 true，未通过返回 false，即「如果此刻结束，是否通过」。

### 2. 执行上下文

| 在哪里执行 | `PASS(false)` / `SYS_CHKPASS` 失败 | `EXIT` | `END` / `INPUT`（公共节点） | 运行错误 |
| --- | --- | --- | --- | --- |
| 顶层 | 验证失败 | 结束，按顶层状态判定 | 同 `EXIT` | 验证失败 |
| `EMBED` 的代码 | 同其所在脚本域 | 结束其所在脚本域 | 同 `EXIT` | 验证失败 |
| `GOTO` 目标脚本 | 透传，验证失败 | 结束目标脚本，回到调用者 | 同 `EXIT`（Q13） | 验证失败 |
| `MAP` / `FILTER` 体 | 同其所在脚本域 | 结束其所在脚本域 | 同 `EXIT` | 验证失败 |
| `EVAL` 的代码 | `PASS(false)` 结束 EVAL，调用者继续（`SYS_CHKPASS` 不能出现在 EVAL 中） | 结束 EVAL，回到调用者 | 同 `EXIT` | 向外传递，验证失败 |

要点：

- **子脚本只能否决，不能放行。** `GOTO` 目标结束时，它自己的状态（通过或未通过）都丢弃，不影响调用者。需要向上传递否决，只能用 `PASS(false)`（构想层 CHECK 的说明已写明）。
- **子脚本不能替调用者结束公共验证。** `GOTO` 目标与 `EVAL` 中的 `END` / `INPUT` 只结束它自己，调用者的后续检查照常执行。
- `EXIT` 的实参只在顶层交给宿主；在 `GOTO` 目标和 `EVAL` 中丢弃。
- 私有节点忽略 `END`；`INPUT` 在私有节点上读取外部数据，数据不足时按「中断退出」处理，与上表 `END` / `INPUT` 一列相同。

### 3. GOTO

- 调用者实参区的全部条目成为目标脚本的初始数据栈。
- 目标脚本有自己的数据栈、实参区、全局变量区、局部域和通关状态。结束后全部丢弃，不向调用者返回数据。
- 校验域（`SIGNED` 读取的验证记录）在 `GOTO` 之间共享（构想层 `SIGNED` 的说明）。
- 次数与深度限制见构想层与 DEC-0007。

### 4. EMBED

- 嵌入的代码在当前位置执行，共享当前脚本域的数据栈、实参区、全局变量区和通关状态。
- 嵌入的代码从一个新的局部域开始，不能读写嵌入点所在块的局部域。理由同解锁段与锁定段的边界（P0-8）：外来代码向局部域存值会打乱宿主脚本的局部域下标。
- 嵌入的代码单独解析（DEC-0003），其中的 `ELSE` 不会与嵌入点之前的 `IF` 配对。

### 5. EVAL

- 独立的执行环境：自己的数据栈（初始为空）、实参区、局部域、全局变量区和通关状态。调用者看不到 EVAL 的通关状态。
- 结束时（正常执行完、`EXIT`、`PASS(false)`、`END` / `INPUT`），EVAL 的数据栈剩余项打包为一个切片，返回调用者。
- 内部的运行错误向外传递，验证失败。
- **校验域对 EVAL 只读**（Q16）：EVAL 内可以读取 `SIGNED`；`FN_CHECKSIG`、`FN_MCHECKSIG` 只返回验证结果，不写入校验域；`SYS_CHKPASS` 在 EVAL 内即失败。
- **EVAL 的代码不能包含 `EVAL`（构想层）、`GOTO`、`EMBED`、`SYS_CHKPASS`**，在加载期判定（DEC-0003）。

### 6. MAP / FILTER

- 私有块域：自己的数据栈和实参区，在各次迭代之间共享（上一次迭代留在实参区的值会被下一次迭代使用，这是构想层的明确设计）；结束后丢弃。
- 实参中首个成员为目标集，其余成员是私有数据栈的初始内容（构想层）。
- 全局变量区、通关状态属于所在脚本域。
- 每次迭代从一个新的局部域开始。
- `RETURN` 结束当前迭代，其实参为本次迭代的结果；迭代执行完而没有 `RETURN`，结果为 Nil。
- `MAP` 丢弃 Nil 结果。`FILTER` 的结果必须是 Bool 或 Nil（Nil 视为不选取），其它类型即失败。
- 目标集是字典时按插入顺序迭代（构想层）。
- `BREAK`、`CONTINUE` 不能跨越 MAP / FILTER 的边界（加载期判定）；`EXIT` 结束所在脚本域。

### 7. EACH 与 SWITCH

- `EACH` 没有私有数据栈；每次迭代从一个新的局部域开始；循环变量 `$Value`、`$Key`、`$Object`、`$Size` 按构想层定义。
- 遍历字典时按构想层的规则：进入循环时确定键的快照，迭代中删除的键跳过，新增的键不进入遍历（Q5）。
- `BREAK` 退出最近的 `EACH` 或 `SWITCH`；`CONTINUE` 作用于最近的 `EACH`，`CASE` 中的 `CONTINUE` 继续外层 `EACH`（同 Go）。
- `SWITCH` 按 `EQUAL` 的语义（DEC-0005）比较标的值与各分支值；分支值的个数与 `CASE` 的个数不一致即失败。

### 8. 局部域与 IF 状态

- **每次进入一个块，都新建一个空的局部域**（容量 128）：包括 `IF`、`ELSE`、`CASE`、`DEFAULT`、`BLOCK`，`EACH` 与 `MAP` / `FILTER` 的每次迭代，以及 `EMBED` 的代码。表达式 `()` 不是块，没有局部域。
- IF 状态按块层级保存，同一层级的 `IF` / `ELSE` 共享一个状态变量（构想层）。`ELSE` 的合法性在加载期判定（DEC-0003）。

### 9. 实参区

取值规则以构想层为准：实参区有值时，必须恰好 n 项、一次取完，否则失败；无值时才从数据栈取。实参数量允许运行时才确定（P0-3）。

### 10. 表达式 `()` 的求值

- **链上存中缀形式。** 实现可以在加载期转成内存中的后缀形式再执行，这不改变链上格式（DEC-0003）。
- **文法**：`*` `/` `%` 优先于 `+` `-`，同级左结合。一元 `+` / `-` 出现在表达式开头、运算符之后或子表达式开头，优先级最高。
- **操作数**：值指令、子表达式，或任何恰好返回 1 个值的指令（局域取值 `&[n]`、循环变量 `$X`、带 `~` 前缀的指令等）。返回 0 个或多个值即失败。
- **求值顺序**：操作数严格按书写顺序从左到右求值，与运算符优先级无关。例如 `( POP - POP )` 先执行左边的 `POP`。
- 表达式内的命名指令照常从实参区或数据栈取实参，返回值作为操作数，不入栈。
- 表达式内不允许 `@`、`&`（存值）、`_`；允许 `~`。
- 操作数的类型规则见 DEC-0005：Byte、Rune 提升为 Int；BigInt 操作数即失败；Float 只在私有域有效。
- 顶层表达式的结果与普通指令的返回值一样：自动入栈，或被 `@`、`&`、`_` 截取。

### 11. 公共与私有两种执行模式

| 指令 | 公共节点 | 私有节点 |
| --- | --- | --- |
| `PRINT`、`FN_PRINTF`、`OUTPUT`、`BUFDUMP` | 空操作，但照常消费实参，并计基础成本 | 按指令执行 |
| `INPUT` | 相当于 `END` | 从外部读取数据 |
| `END` | 结束（见第 2 条） | 忽略 |
| 私有专属指令（浮点字面量、`SYS_TIME`、`SHELL`、`*_PRIV`） | 执行到即失败 | 按指令执行（`SHELL` 需白名单，见 DEC-0002） |

空操作仍要消费实参，否则同一个脚本在两种节点上的实参区状态不同，后续指令的行为也就不同。

### 12. 其它

- **NULL 点**按字节位置记录，与执行路径无关（构想层 `SOURCE`）。
- **系统占位符**按 DEC-0003 第 5 条执行。
- **校验域的写入者**：顶层、`EMBED` 的代码、`GOTO` 目标、`MAP` / `FILTER` 体中的 `SYS_CHKPASS`（仅成功时）、`FN_CHECKSIG`、`FN_MCHECKSIG`。EVAL 只读。


## 理由

- **只能否决、不能放行**：`GOTO` 的典型用途是「管理者 + 审计者 + 第三方」，每一方都应能否决，但任何一方都不应能替调用者放行，或跳过调用者后面的检查。
- **子脚本里的 END 只结束自己**（Q13）：如果目标脚本中的 `END` 能结束整个公共验证，一个为私有监听而写了 `END` 的通用脚本，会让每个调用者在 `GOTO` 之后的检查全部失效。这与 EVAL 的封装逻辑一致。
- **校验域对 EVAL 只读**（Q16）：`SIGNED[n]` 是锁定脚本判断「谁签了名」的依据。EVAL 的代码可能来自花费者，如果它能写入验证记录，花费者就可以用自己的密钥制造一条「已签名」记录。
- **EVAL 代码不含 GOTO / EMBED / SYS_CHKPASS**：构想层把 EVAL 定位为「运算拆解，而非通关检查拆解」。禁止这三条指令，EVAL 的否决与校验域语义就不需要再处理「EVAL 里的子脚本」这一层，外部加载的计数也更简单。
- **EMBED 从新的局部域开始**：与解锁 / 锁定段边界的理由相同，外来代码不应改变宿主脚本的局部域下标。
- **求值顺序固定**：操作数可能有副作用（`POP`），不规定顺序，不同实现就会得出不同结果。


## 影响

- Spec 需要把第 1 条的状态机和第 2 条的表原样写入，并为每个单元格提供测试向量。
- 构想层中 `GOTO`、`END`、`EVAL`、`SYS_CHKPASS`、`SIGNED` 的说明已按 Q13、Q16 同步修订。
- 实现中每个脚本域持有自己的通关状态；EVAL 环境需要一个「校验域只读」标志。

## 开放问题

以下几条是评审者在起草时补充的规则，构想层没有直接写明，请作者确认：

1. `EVAL` 的代码不能包含 `GOTO`、`EMBED`（第 5 条）。
2. `EMBED` 的代码从新的局部域开始（第 4 条）。
3. `EXIT` 的实参在 `GOTO` 目标和 `EVAL` 中丢弃（第 2 条）。
4. `ENV{Passed}` 在未决时返回 true（第 1 条）。
5. `MAP` / `FILTER` 的迭代没有 `RETURN` 时结果为 Nil；`FILTER` 的结果只接受 Bool 或 Nil（第 6 条）。
6. 公共节点上的空操作（`PRINT` 等）照常消费实参（第 11 条）。
7. `CASE` 中的 `CONTINUE` 作用于外层 `EACH`（第 7 条）。构想层只写了「只能存在于 EACH 子块内」，这里按词法嵌套理解。
