# DEC-0003 字节码解码与加载期校验

- 状态：待评审者确定
- 日期：2026-10-28
- 覆盖评审条目：P0-6、P0-8、P1-8（Q1、Q12、Q14），以及 P0-1 回复中的分段解析规则


## 背景

链上存储的是编译后的字节码：指令码、附参和关联数据。构想层已经确定这份字节码就是执行格式，不另设二进制格式（P1-8）。还有三件事没有定：

1. **规范编码。** 同一个值可能有多种字节编码（例如 varint 的冗余长编码、可以用 int64 表示的 BigInt）。MODEL 按字节做全等匹配，非唯一编码会让模式匹配被绕过，反编译再编译也不能得到相同的字节码。
2. **结构错误在什么时候判定。** 只在执行到时检查，那么不会执行到的分支里有结构错误，脚本照样通过，脚本是否合法就取决于执行路径。
3. **系统占位符的执行方式**，以及解锁段与锁定段的边界规则。后者构想层已有，这里只引用。


## 决策

### 1. 加载期

每一段字节码在执行之前，先由节点完整解码一遍，并做结构校验。这一步称为**加载期**。所有验证节点都执行这一步，交易构建者无法绕过，因此它与运行时检查同样具有约束力。

加载期发现的错误，一律使该段字节码无效，验证失败。与执行路径无关：不会执行到的分支里有结构错误，脚本同样无效（Q12）。

需要加载的段，以及加载的时点：

| 段 | 加载时点 |
| --- | --- |
| 解锁脚本、锁定脚本 | 执行之前，两段分别加载 |
| `GOTO`、`EMBED` 的目标脚本 | 执行到该指令时。宿主可以提前预取，但这不改变结果。没有执行到的 `GOTO` / `EMBED` 不加载其目标 |
| `EVAL` 执行的代码 | 执行 `EVAL` 时，在执行该代码之前 |

加载期扫描会进入代码块（`IF`、`ELSE`、`SWITCH`、`CASE`、`DEFAULT`、`EACH`、`BLOCK`、`MAP`、`FILTER`、`()`、`MODEL` 的模式体），不进入数据类的关联数据（`DATA`、字符串、正则、`CODE`、`SHELL` 的内容）。`CODE` 的内容在被 `EVAL` 执行时才作为代码加载。

### 2. 规范解码规则

以下任一条不满足，即为无效编码：

1. **varint 必须是最短编码。** 多字节编码的末字节不能是 `0x00`，且值不超出 64 位。适用于所有变长附参，以及整数（opcode 5）和时间（opcode 12）的数据。Go 的 `binary.Varint` 不检查这一点（`[0x80, 0x00]` 也会解出 0），解码后需要额外判断。
2. **BigInt（opcode 6）**：值必须超出 int64 范围；绝对值不能有前导零字节；不能是「负零」（符号位为 1、绝对值为 0）。int64 范围内的值只能用 opcode 5 编码。
3. **Rune（opcode 4）**：必须是合法的 Unicode 标量值，即不超过 `0x10FFFF`，且不在代理区 `0xD800–0xDFFF`。
4. **Float（opcode 7）**：字节不能编码 NaN 或 ±Inf。`-0` 允许。
5. **值集（opcode 9）**：成员只能是构想层列出的值类型的值指令（Bool、Byte、Rune、Int、BigInt、Float、String），且类型一致或可以按构想层规则提升。空值集无效。系统占位符不能出现在值集内。
6. **块长度**：每个块的长度必须恰好落在指令边界上，子块必须完整包含在父块内。
7. **MODEL 的附参标记**：附参最高位标记「模式内是否有取值」，必须与模式体的实际内容一致。否则 MODEL 的返回值个数会与标记不符。
8. **正则字面量（opcode 11）** 在加载期编译。语法错误即为无效编码。
9. **分段**：解锁脚本与锁定脚本分别解析。任何指令（包括 `DATA` 的长度、块长度）都不能跨越两段的边界。
10. **非索引类附参的取值**必须在该指令定义的取值范围内（例如 `KEYVAL` 的附参只能是 0、1、2）。哪些附参属于可扩展的「索引类」、按未分配码位处理，见 DEC-0004。

两种写法并存、但属于不同指令或不同类型的情况，不属于非规范编码：`.` 与 `.[1]` 是两个模式指令；`'A'` 编为 Byte（opcode 3）与 `'\u0041'` 编为 Rune（opcode 4）是两个不同的值。

### 3. 结构规则

以下规则与运行时的值无关，在加载期判定：

- **IF / ELSE 配对**：同一块层级内，`ELSE` 之前最近的一条 IF 类指令必须是 `IF`。即 `IF{} ELSE{} IF{} ELSE{}` 合法，`IF{} IF{} ELSE{} ELSE{}` 的第二个 `ELSE` 非法。
- **SWITCH**：`CASE`、`DEFAULT` 只能直接位于 `SWITCH` 块内；`DEFAULT` 至多一个，且位于所有 `CASE` 之后。（`CASE` 的个数与分支值列表的长度是否一致，属于运行时检查。）
- **模式指令**（opcode 117–127）只能位于 `MODEL` 的模式体内。
- **RETURN** 必须位于某个 `MAP` / `FILTER` 体内。
- **BREAK**：从 `BREAK` 向外查找，必须在遇到 `MAP` / `FILTER` 体或段顶层之前遇到 `EACH`、`CASE` 或 `DEFAULT`。
- **CONTINUE**：同上，但必须遇到的是 `EACH`。中间隔着 `CASE` 没有关系（与 Go 相同）。
- **运算符号**（opcode 81–85）只能直接位于表达式 `()` 内，且表达式内部符合中缀文法（见 DEC-0006）。
- **截取前缀**：前缀之后必须紧跟一条目标指令，且位于同一块内。前缀序列的形式为：至多一个截取前缀（`@`、`&`、`_`），其后至多一个 `~`，再接目标指令。表达式内不允许 `@`、`&`（存值）、`_`，允许 `~`。
- **块嵌套深度**：每段字节码分别计算，上限见 DEC-0007。
- **解锁段的指令范围**：只能使用 `[0-45]` 中已分配的指令、`SYS_NULL`（169）和系统占位符（254）。`GVAL` 的索引也必须已分配。违反即失败，不适用 DEC-0004 的宽松通过。
- **系统占位符（254）** 只能出现在解锁段，且其附参必须是宿主见证条目表中已定义的值。
- **码值 255** 在任何段中都无效。
- **EMBED 目标**不能包含 `EMBED`、`GOTO`（构想层的嵌入深度为 0）。
- **EVAL 代码**不能包含 `EVAL`、`GOTO`、`EMBED`、`SYS_CHKPASS`（见 DEC-0006）。

**MODEL 模式体的例外。** 模式体内的普通指令是模式，描述的是目标脚本的片段，可以是不完整的结构。因此上面关于「某指令只能 / 不能出现在哪里」的规则（IF / ELSE 配对、SWITCH、RETURN / BREAK / CONTINUE 的位置、截取前缀、运算符号、解锁段范围、占位符只能在解锁段、EMBED / EVAL 的禁用指令）不适用于模式体。例如锁定脚本可以用 `IN{Unlock} MODEL{ <Sig> <PubKey> }` 检查解锁脚本的形态，其中的占位符就是模式。规范解码规则、块长度与嵌套深度、码值 255、未分配码位的处理，在模式体内照常适用，因为不知道格式的指令无法继续解码。

**运行时**检查依赖值或执行路径的规则，包括：实参个数是否匹配、类型是否正确、越界与溢出、私有专属指令「执行到即失败」、`SWITCH` 的分支值个数、限额与成本。

### 4. 解锁段与锁定段的边界

构想层 `Design.md`「锁定&解锁 / 边界处理」已经写明，这里直接引用，不另立规则：两段只共享数据栈；解锁段结束时实参区必须为空，否则失败；锁定脚本从新的顶层局部域开始；`SOURCE` 的取码视图仍把「解锁 + 锁定」当作一段源码。

### 5. 系统占位符的执行（Q14）

- 执行到 `254(n)` 时，从宿主提供的见证条目表中取出第 n 项，按值指令的规则处理：默认入栈，可以被 `@`、`&`、`_` 截取。
- 见证条目缺失，即失败。
- 字节码本身不改写。`SOURCE`、`IN{Unlock}`、`IN{Source}`、NULL 点位置、`MODEL`、解锁脚本长度，都按含占位指令的原始字节计算。

### 6. 实现层的缓存（非规范）

加载期扫描时，实现可以顺便把指令解码成内存中的数组，记录每条指令的位置、附参、块的结束位置，并把表达式转成后缀形式。这样 `EACH` 的循环体执行多次时不必重复解码。这份内存结构不属于规格，也不上链。


## 理由

- **加载期判定结构错误**，使「脚本是否合法」只取决于字节码本身。所有节点读到同样的字节，就得出同样的合法性结论。这一遍扫描本来就要做：跳过一个 `IF` 块，必须先读出块长度。
- **规范编码**消除同一个值的多种写法，MODEL 的全等匹配因此可靠，反编译再编译能得到相同的字节码。
- **交易延展性不是规范编码要解决的问题。** Evidcoin 的 TxID 不含见证信息和解锁脚本（Q7），第三方改写解锁脚本不会改变 TxID。解锁区因此可以保留 `[0-45]` 的灵活性，而不必收窄为只能压入值。
- **占位符不改写字节码**：签名消息、`SOURCE`、NULL 点、MODEL 看到的是同一份字节，构想层「不含见证信息」的说法也就自然成立。改写字节会移动所有偏移，`SOURCE` 与 NULL 点的语义就要分「改写前」「改写后」两套。
- **解锁段拒绝未分配码位**，而不是宽松通过：解锁段由花费者编写，宽松通过等于让花费者自己决定放行。


## 影响

- Spec 需要一张完整的**指令格式表**：每个指令码有几个附参，每个附参的编码（固定字节数、varint、48 字节等）和取值范围，是否属于索引类，有没有关联数据，关联数据的长度由哪个附参给出，关联数据是代码块还是数据。
- Spec 需要逐条列出上面的规范解码规则与结构规则，并为每条规则提供失败用例（DEC-0001 的测试向量）。
- 加载期按脚本字节数计成本，见 DEC-0007。
- 正则在加载期编译，其成本在加载期计入，即使所在分支没有执行。

## 开放问题

1. **MODEL 的目标无法解码时怎么办。** 目标是运行时数据（Script 或 Bytes），可能来自花费者。建议：目标无法按规范解码时，MODEL 返回「不匹配」，而不是让脚本失败。这样锁定脚本可以安全地对花费者提供的字节做模式检查。
2. 截取前缀能否作用于没有返回值的指令（如 `@PASS`），由 Spec 的指令格式表逐条标注，在加载期判定。
3. `DATE` 的取值范围（RFC 3339 只能表示 0000–9999 年），由 Spec 定义。

> 2. 不可以。没有返回值不等于返回 nil。
