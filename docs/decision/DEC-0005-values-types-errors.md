# DEC-0005 数值、类型与异常

- 状态：Accepted
- 日期：2026-10-28
- 修订：2026-11-01（并入作者回答：Time 的运算由 `MO_TIME` 提供）；2026-11-06（开放问题 1 关闭：BigInt 的取模与幂由 `MO_BINT` 提供）；2026-11-08（作者决定：Bytes 与 `[]Byte` 是两个类型，取消别名；第 1、5、6、7、8 条相应修订）；2026-11-11（Nil 不再转到基本类型、String、Bytes、Time）；2026-11-13（第 5 条：Nil 与不可比较的类型做相等比较为「不相等」而不是失败，与构想层 `10.比较指令.md` 对齐）；2026-11-15（第 8、10 条：PACK 忽略切片中的 Nil 成员；第 7、8 条：`BYTES(Float)` 为 IEEE 754 原始位的大端 8 字节，以及 `FLOAT(Bytes)` 的逆运算）；2026-11-22（作者修订构想层浮点规则：第 2 条重写，公共域中 Float 可以编码、传递与精确转换，运算、数值比较、`ISEFV` 与文本转换即失败；第 1、5、7 条与理由、影响相应修订）
- 覆盖评审条目：P0-4、P1-1、P1-2、P2-5（Q5、Q9）


## 背景

构想层定义了值类型和各指令支持的类型，但跨类型运算、溢出、除零、移位范围、比较规则、异常时是失败还是返回空值，都没有统一规则。这些规则直接决定脚本结果，属于共识。

另外，浮点运算在不同架构上可能得出不同结果（例如 FMA 融合、扩展精度、数学库的末位差异），不能进入共识路径。构想层（2026-11-22 修订）规定：浮点数只在私有域参与计算（含比较），在公共域可以编码、传递与确定性转换，使解锁段中的浮点数据能够传到私有段，或经 `OUTPUT` / `BUFDUMP` 导出。


## 决策

### 1. 值类型

Nil、Bool、Byte、Rune、Int（int64）、BigInt（绝对值不超过 1016 位）、Float（float64；公共域只作数据，第 2 条）、String、Bytes、RegExp、Time、Script、切片（具体类型的切片与 `[]any`）、Dict、模块 / 对象。

- **Bytes 与 `[]Byte` 是两个类型**（作者决定，取消第一轮回答中的别名含义）。Bytes 是一个整体的字节序列，与 String 同属普通数据项（DEC-0007），可以比较、拼接。`[]Byte` 是成员类型为 Byte 的切片，与 `[]Int` 等一样适用切片的全部规则：受成员数上限约束，不可比较。
- **Bytes 只在写明的指令中代替切片**：`SLICE`、`REVERSE`、`MERGE`、`EXTEND`、`PACK`、`INDEX`、`SIZE`（构想层 `4.集合指令.md`）与 `SLRAND`（`14.工具指令.md`）。`INDEX` 的单个位置得到 Byte；位置集总是得到值集，目标为 Bytes 时得到 `[]Byte`。其余要求切片的指令，包括 `SPREAD`、`EACH`、`MAP`、`FILTER`，不接受 Bytes，需先用 `ANYS{Byte}` 转为 `[]Byte`（第 7 条）。
- 成员全为 Byte 的值集得到 `[]Byte`（构想层 `1.值指令.md`）；Bytes 的字面量是 `DATA`。
- **String 不检查 UTF-8 合法性**，按字节比较。
- Script 携带版本号（DEC-0004）。

### 2. Float 在公共域只作数据（Q9；2026-11-22 作者修订）

**公共验证中，Float 可以编码、传递与精确转换，不得参与运算与数值比较。** 结果由 binary64 的位模式或正确舍入唯一确定的操作可以进行，需要解读浮点数值的操作即失败。

| 公共验证 | 操作 |
| --- | --- |
| 可以：编码与传递 | 浮点字面量，含浮点成员的值集（含 Int 到 Float 的提升）；在数据栈、实参区、局部域、全局变量区之间传递；作为切片成员与字典的值，由栈、集合与流程指令搬运（`SHIFT`、`MERGE`、`SLICE`、`INDEX`、`SET`、`EACH` 等）；从解锁段经 `GVAL` 取得；MODEL 取值得到 Float；`OUTPUT`、`BUFDUMP` 导出 |
| 可以：精确转换 | `FLOAT(Bool / Byte / Rune / Int / Bytes)`，`BOOL(Float)`、`INT(Float)`、`BYTES(Float)`，以及逐项按这些转换进行的 `ANYS`、`PACK` |
| 不看数值的比较 | 一边是 Nil，或两边类别不同时的 `EQUAL` / `NEQUAL`，照常得出结果（第 5 条） |
| 失败：运算 | Float 作为表达式、运算指令（`ADD`、`NEG`、`DIVMOD` 等）、`MO_MATH` 的操作数；`RANDOM`、`RANGE` 的浮点分支 |
| 失败：数值比较 | 两边都是数值类、且至少一边是 Float 的比较指令；`WITHIN` 中出现 Float；`CMPFLO` |
| 失败：私有专属 | `ISEFV` 整条指令私有专属，公共验证执行到即失败（与 `SYS_TIME` 同类） |
| 失败：文本转换 | `FLOAT(String)`、`STRING(Float)`，以及逐项包含它们的 `ANYS` |

- `FLOAT(Int)` 按 IEEE 754 就近舍入（两者等距时取偶数），结果唯一。`INT(Float)` 向零截断，`BOOL(Float)` 只判断是否为 ±0，都不涉及舍入。
- 文本转换在数学上也是确定的（正确舍入的解析、最短往返的格式化），但进入共识需要逐位规定算法，各语言的实现都要复现。与 `Time` 的 `Format` 一样（DEC-0001 第 3 条），留在私有域。
- MODEL 的浮点范围匹配（opcode 124）是例外：它比较的是目标字节码中的浮点字面量与模式中的边界，只有一次减法与比较，结果由 IEEE 754 唯一确定，构想层把它作为模式匹配的一部分，公共验证中照常使用。
- 私有域里 Float 照常运算与比较。

**浮点字面量的位统一**（构想层「比特位统一：-0 => +0」）：字面量不编码 −0，文本 `-0.0` 编译为 +0；字节码中的 −0 位模式是无效编码（DEC-0003 第 2 条）。这只约束字面量。运行时的 −0 仍然存在（`FLOAT(Bytes)` 的还原、私有域运算的结果），`BYTES(Float)` 与 `FLOAT(Bytes)` 保持逐位互逆（第 7 条）。

### 3. 数值提升

- 整数类按 Byte → Rune → Int → BigInt 提升。Byte、Rune 参与算术时先提升为 Int，结果至少是 Int。
- 有 BigInt 参与时结果为 BigInt，不自动降回 Int。BigInt 结果的绝对值超过 1016 位即失败，这样运行时的任何 BigInt 都能写回字面量。
- 私有域：Int 与 Float 运算提升为 Float；BigInt 与 Float 没有共同类型，运算即失败（与构想层值集的提升规则一致）。
- Bool、String、Bytes、Nil 不是数值，参与算术即失败（`ADD` 的拼接除外）。
- **表达式 `()` 不接受 BigInt 操作数**。构想层的符号指令只支持 Int（以及私有域的 Float），BigInt 运算使用命名指令（`ADD`、`SUB`、`MUL`、`DIV`、`NEG` 和位运算）。表达式的结果是 Int，私有域里也可能是 Float。

各指令支持的类型以构想层为准：`MOD`、`POW`、`DIVMOD` 不支持 BigInt；`ADD`、`SUB`、`MUL`、`DIV`、`NEG` 与位运算支持 BigInt。

### 4. 溢出与异常（一律失败）

「整数溢出即失败」（Q9）指算术运算：

- Int 的加、减、乘、取负、幂溢出即失败。Go 本身静默回绕，`MinInt64 / -1` 和 `-MinInt64` 的结果仍是 `MinInt64`，实现必须显式检查。
- 除数或模数为零即失败。
- 除法向零截断，余数的符号与被除数相同（同 Go）。
- `POW` 的指数为负即失败；`0^0 = 1`。

位运算不做溢出检查，按二进制补码处理（Go 的 `big.Int` 也这样定义）：

- Int 的移位数必须在 `[0, 63]` 之内，否则失败。左移移出的位丢弃；右移为算术右移。
- BigInt 的移位数必须非负；左移结果的绝对值超过 1016 位即失败。

### 5. 比较

- `EQUAL` / `NEQUAL`：数值类先提升再按值比较（Byte 65 等于 Int 65，Int 与值相同的 BigInt 相等）；String 与 String、Bytes 与 Bytes、Script 与 Script 按字节比较；Time 按时刻比较；Bool 与 Bool 比较；Nil 只等于 Nil。两边类别不同时结果为「不相等」，不失败。切片（包括 `[]Byte`）、字典、RegExp、模块 / 对象不可比较，比较即失败；因此 Bytes 与 `[]Byte` 比较是失败，而不是「不相等」。例外：一边是 Nil 时，相等比较不失败，Nil 与任何非 Nil 的值（包括不可比较的类型）都为「不相等」。
- `LT` / `LTE` / `GT` / `GTE`：只用于数值、String、Bytes、Time，且两边类别相同，否则失败。String 与 Bytes 按字节从左到右比较。
- `WITHIN`：只用于数值，按构想层的类型清单。
- 私有域的 Float 按 IEEE 754 比较，NaN 不等于任何值，+0 等于 −0。公共域中，比较的两边都是数值类、且至少一边是 Float 时即失败；一边是 Nil，或两边类别不同时，相等比较不看数值，照常得出「不相等」（第 2 条）。
- Time 与 Int 属于不同类别：`EQUAL` 返回「不相等」，`LT` 等即失败。需要与时间戳比较时，先用 `INT(Time)` 或 `TIME(Int)` 转换。

Time 不参与运算指令（`ADD`、`SUB` 等对 Time 即失败）。时长加减等运算由 `MO_TIME` 模块的方法提供（作者回答）。

### 6. 拼接与合并

- `ADD` 只允许 String + String、Bytes + Bytes，混用即失败。结果受单项大小上限约束（DEC-0007）。
- `MERGE` 的实参全为 Bytes 时，结果是首尾相接的 Bytes；Bytes 与切片（包括 `[]Byte`）混用即失败。`EXTEND` 的目标为 Bytes 时，追加的成员必须是 Byte，结果为 Bytes。
- 字典合并（`ADD`）返回一个新字典：先保留左侧的键及其顺序，右侧新增的键按其顺序追加，重复的键取右侧的值。

### 7. 转换的补充规则

构想层 `8.转换指令.md` 的转换表为准，补充：

- `RUNE`：结果落在代理区 `0xD800–0xDFFF` 即失败。
- `BYTE`：值不在 `[0, 255]` 即失败（包括负数）。
- `INT(String)` 解析失败即失败。
- `BOOL` 不接受切片、字典、Bytes。判空用 `SIZE BOOL`。
- `BYTES(Int)` 为 8 字节大端补码，`INT(Bytes)` 要求恰好 8 字节、按大端补码还原，两者对称。
- `BYTE` 接受恰好 1 字节的 Bytes，与 `BYTES(Byte)` 对称。按位置从 Bytes 中读取单个字节用 `INDEX`，直接得到 Byte。
- Bytes 与 `[]Byte` 的互转：`BYTES([]Byte)` 把成员依次复制为 Bytes；`ANYS{Byte}`（`ANYS[3]`）把 Bytes 转为 `[]Byte`。`ANYS` 的其它标识（包括 `ANYS[0]`）不接受 Bytes，需要 `[]any` 时先转为 `[]Byte`。转换的结果是切片，受成员数上限约束，超过 1024 字节的 Bytes 不能整体转为 `[]Byte`。
- `BYTES(BigInt)` 与 `BIGINT(Bytes)` 只处理绝对值，会丢失符号。这是已知的局限，在指令说明中提示。
- `BYTES(Float)` 取该值的 IEEE 754 binary64 原始位（`math.Float64bits`），按大端序写成固定 8 字节，与浮点字面量的 `f64be` 相同。+0、−0、NaN 的载荷和 ±Inf 都按原位写出。这是位模式搬运，不是浮点运算，结果是 Bytes。`FLOAT(Bytes)` 是它的逆运算，实参必须恰好是 8 字节，按大端序读成 uint64，再用 `math.Float64frombits` 还原，−0、±Inf 与 NaN 载荷都原样还原。两者都是公共域可用的精确转换（第 2 条）。
- `ANYS{T}` 对每个成员按 T 的转换规则转换，任一成员不能转换即失败。

### 8. PACK

**PACK 定义为「每个成员做 `BYTES` 转换，再首尾相接」**，不另设一套「基础二进制形态」，只维护一张转换表。实参为切片时，按直接成员的实际类型转换：取该成员的实际类型，再查 `BYTES` 表。

值为 Nil 的直接成员忽略，无转换操作。切片为空，或成员全部被忽略时，结果为空 Bytes。成员不能转为 Bytes 时失败。Nil 忽略只属于 `PACK`，发生在转换之前。

实参也可以是 Bytes 本身，此时结果与 `BYTES(Bytes)` 相同（构想层）。

PACK 的结果不带长度信息，`["ab", "c"]` 与 `["a", "bc"]` 的结果相同。用于哈希承诺时，如果成员长度可变，应先固定长度或自行加入长度字段。这一点在指令说明中提示。

### 9. SLICE 与字符串

`SLICE` 只用于切片和 Bytes，对 String 使用即失败，以免切断 UTF-8 字符。字符串截取用 `SUBSTR`。

### 10. 异常处理的归类（P1-2）

每条指令的异常都属于以下三类之一。Spec 中每条指令有一行「异常」，写明所属类别：

| 类别 | 处理 | 指令 |
| --- | --- | --- |
| 按位置访问 | 越界即失败（同 Go 的切片越界） | `SLICE`、`INDEX`、`POPS`、`TOPS`、`PEEK`、`PEEKS`、`SHIFT`、`CLONE`、`VIEW`、`&[n]` |
| 按键查找 | 缺失返回 Nil（同 Go 从 map 取不存在的键） | `ITEM` |
| 明确声明的宽松行为 | 按指令说明 | `SUBSTR` 返回已截取的部分；MODEL 内 `$[n]` 越界返回 Nil；`MAP` 丢弃 Nil 结果；`PACK` 忽略切片中的 Nil 成员 |

Nil 流入后续指令时：参与算术即失败；转到基本类型、String、Bytes、Time 即失败（`RUNES(Nil)` 与 `ANYS(Nil)` 仍得到空切片，构想层 `8.转换指令.md`；`PACK` 忽略切片中的 Nil 成员，第 8 条）；Nil 只支持 `EQUAL/NEQUAL` 比较。

### 11. 值语义

- **除字典外，所有值不可变。** 产生新内容的运算总是返回新值。
- `SLICE` 与原切片共享底层数组。因为切片不可变，共享是安全的，且效率更高。
- `EXTEND` 先复制底层数组再扩展，不会写穿共享的父切片。
- 字典可以被 `SET`、`DEL`、`CLEAR` 就地修改；`COPY` 是浅复制。
- **字典的值（递归地，包括值中切片的成员）不能包含字典**（Q5）。在 `DICT`、`SET`、字典合并时检查，违反即失败。切片可以包含字典。

最后一条同时解决两个问题：`COPY` 的浅复制之后，两个字典不会共享可变的内层字典；字典也无法直接或间接地包含自身，`PACK`、比较、打印等递归操作不会陷入循环。切片不可变，只能由已经存在的值构造，本身形不成循环，所以只需约束字典。


## 理由

- **默认失败**：类型不匹配、溢出、越界时返回一个「合理的」值，看似友好，实际是让脚本在作者没有预料的状态下继续执行。默认通关的原则下（P0-1），这类静默继续最终更可能变成放行。
- **规则贴近 Go**：作者和多数实现者熟悉 Go，越界失败、缺键返回零值、截断除法、补码位运算都与 Go 一致，记忆成本最低。差异只在 Go 静默回绕的地方（算术溢出），这里改为失败。
- **Float 在解读数值处拦截**：跨平台差异只来自运算，编码、搬运与按位转换逐位确定，因此公共域放行 Float 本身，只拦截解读数值的操作。Float 的来源很多，但运算与数值比较都要经过数值提升，在提升处检查，新增指令也不会漏。比较本身也是确定的，一并禁止是构想层的使用约束，不是共识的需要；脚本可以先 `BYTES` 或 `INT` 再比较，这不影响共识。
- **字面量不编码 −0**：值集的成员、MODEL 的按字节匹配都依赖「同一个值只有一种编码」。+0 与 −0 相等却有两种位模式，按 DEC-0003 的规范编码原则只保留 +0。NaN 与 ±Inf 本来就不能写成字面量。
- **Bytes 与 `[]Byte` 分立**：Bytes 在限额、成本、比较、拼接、转换上的行为都与切片不同。作为切片的别名，每条切片规则都要附带「Bytes 除外」，新增规则时漏写例外就会造成实现分歧。分立之后两者各守一套规则，Bytes 只在写明的指令中代替切片，其余默认失败。有 Byte 就有 `[]Byte`，与 `[]Int` 等一致（作者）。
- **表达式不接受 BigInt**：遵从构想层符号指令的类型定义，表达式保持为简单的 Int 运算。BigInt 的运算本来就需要按字数计成本（DEC-0007），留在命名指令里更清楚。
- **PACK 在转换之前忽略 Nil**：构想层已写明切片中的 Nil 成员直接忽略。忽略留在 `PACK` 内、发生在查表之前，因此仍然只有一张 `BYTES` 表，Nil 没有字节编码。
- **浮点与 Bytes 只搬位**：构想层用 `math.Float64bits` 与 `math.Float64frombits` 的大端 8 字节，两个方向逐位互逆。给定同一个位模式，各平台的结果相同；跨平台差异只可能来自产生该 Float 的运算，不来自这两次转换。


## 影响

- Spec 需要一张「运算 × 类型 → 结果或失败」的矩阵，覆盖运算、比较、转换三类指令。
- 每条指令的 Spec 条目增加「异常」一行。
- 实现中公共域对 Float 的拦截必须集中在数值提升（运算与比较的操作数分派）一处，另加 `ISEFV` 与文本转换的执行模式判断。
- 撤回 R-06（公共验证中产生 `[]Float` 即失败）：`[]Float` 在公共域是普通的切片。
- 测试向量覆盖：公共验证中 Float 的字面量、值集、`GVAL`、栈与集合搬运、MODEL 取值、精确转换都成功；每一类运算、数值比较、`ISEFV`、`CMPFLO`、文本转换都失败；Float 与 Nil、与 String 的相等比较不失败。
- 测试向量需要覆盖每一类溢出、除零、移位越界、代理区、跨类别比较。
- `PACK` 跳过切片中值为 Nil 的直接成员；空切片与成员全部被忽略时结果为空 Bytes。测试向量覆盖 Nil 在首、中、尾，全部为 Nil，以及 Nil 与不能转换的成员同时存在。
- `BYTES(Float)` 与 `FLOAT(Bytes)` 逐位互逆。测试向量覆盖往返（+0、−0、一个有限值、±Inf、载荷不被清掉的 NaN），以及长度不是 8 字节时 `FLOAT(Bytes)` 失败。含浮点数成员的 `PACK`、`ANYS{Bytes}` 使用同一编码。两者在公共域与私有域中结果相同。
- 构想层 `9.运算指令.md` 中 `MOD`、`POW` 写的是「输入什么类型返回什么类型」，按第 3 条，Byte、Rune 输入的结果是 Int。
- 值的内部表示必须区分 Bytes 与 `[]Byte`。限额与成本中，Bytes 按普通数据项处理，`[]Byte` 按切片处理，两者都不是对方的例外。
